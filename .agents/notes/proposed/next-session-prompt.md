## 阶段二：一次性全测（隔离实例）

`DSH_HOME` 是官方数据根覆盖（`packages/util/home-paths/src/index.ts:17,135`，
优先级 显式配置 → `$DSH_HOME` → `~/.dsh`）。做法：

    $env:DSH_HOME='D:\tmp\dsh-e2e'    # 隔离根，不碰用户的 ~/.dsh
    # 在该根里装连接器（见 docs/cookbook/channel-bootstrap.md）→ 启动 → 出码 → 手机配对

**不要**在默认根上另起第二个实例（那才是并发写同一份会话日志）。

然后一次性覆盖（清单里所有「未验」都在这轮变「已验」）：

1. 流式文本：发一句，正文边生成边显示，且**未闭合围栏不抖动**（第 7 条）。
2. 斜杠命令卡：跑 `/goal` 或 `/compact`，卡片出现且排版正常（第 4 条）。
3. 异常结局与重试、压缩标记、过程摘要的真实用时。
4. 附件：`＋` → 照片/拍照 → 芯片 → 发送 → 气泡旁附件计数。
5. 历史翻页：滚到顶多出几轮。
6. 宽表：发一条 5-6 列的表，看是否横向溢出（第 6 条）。
7. 工具卡展开后的正文字体/行高与展开态是否仍保持（第 3 条）。

测试要点：截图前先 `adb shell uiautomator dump` 拿**当前**坐标（坐标不能跨状态复用，
踩过三次）；深色与浅色各看一遍关键屏。

## 阶段三：文件上传（可选，看预算）

按开工单整批做：契约文档 → 连接器（端口 + handler + caps 键 + 测试）→

二进制线上放大 ≈1.78 倍 ⇒ 原始字节 ≤3 MiB。**别半截提交**。

## 硬规则（违反任何一条都等于乱猜）

- 不许猜：DSH 行为要 `packages/...:行号`；包 API 查本地 pub 缓存源码
  （`AppData/Local/Pub/Cache/hosted/pub.dev/...`）；Flutter 行为查本机 SDK
  （`node app/tools/flutter-api.mjs <符号>`）。查不到写「未找到」并问。
- **示例数据不是产品的一部分**：它显示不出某屏 ≠ 该屏有问题；不必为它加样本。
  真实行为一律用隔离实例验。
- 改源码只用编辑工具，不用 shell 字符串替换（静默损坏过两次）。
- 每条新判据做一次变异验证（故意破坏实现，确认恰好那一条红）。
- 提交前 `git status --porcelain` 只剩你有意改的文件；代码与决策笔记同批提交。
- 视觉/文案以 `docs/design-and-tech-plan.md` 为基线；冲突时先改文档；
  该文档 ≤3,000 词，新增内容下沉到 `docs/subsystems/`。
- 图标集机生成，不许手写 unicode 字形。
- 收尾更新 `memory.md`（现状 + 待办 + 门禁数字），不做流水追加。
