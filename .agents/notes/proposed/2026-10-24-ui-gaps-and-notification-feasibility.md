# Agent Note: 五条界面观察逐条求证 + 通知可行性（会话完成 / 审批 / 问答）

Status: proposed（本条只求证与记录，**0 行代码改动**；每条的"做不做/怎么做"等点头）

## 背景

用户在 2026-10-24 真机验证之后，从手机上看出了五件事，并提出"会话完成 / 审批 / 问答能不能发手机通知"。
本篇逐条对到代码，给出现状事实、根因、成本与需要拍板的点。**结论里没有一条是"顺手就能改"以外的承诺**。

## 1. 设置页：有的显示"未读到"，有的却"显示了"

**现象**：断开桌面时，`新会话默认权限` / `新任务默认模式` / `电脑侧 DSH 版本` 显示"未读到"，
但 `上传 Session Log` 那个开关**显示成"关"**。本地项（主题 / 界面字号 / 工作步骤展示 / 性能与用量 /
繁忙时发送）显示值是对的 —— 它们本来就落盘在手机侧。

**根因**（`app/lib/ui/settings_page.dart`）：

- 走"未读到"的三项都用 `?? '未读到'` 收口：`:291`（`app.dshVersion`）、`:377`（`permission.defaultPreset`）、
  `:428`（`agent-preset-registry.selectedDefault`）。
- 那个开关是 `value: app.settingsValue('session-log-deepseek', 'enabled') == true`（`:248-249`）——
  没读到时 `null == true` 是 **false**，于是**画出一个具体状态"关"**，而这个值一次都没读到过。

**判定**：这是第八条教训（"生产路径上的假数据"）的同一形状 —— **"不知道"被画成了"关"**。
旁边三项已经是对的，这一处漏了。

**成本**：1 处 UI（未读到时显示"未读到"/不画开关态，`onChanged` 已经是 `null` 禁用）+ 1 条 widget 用例。

## 2. 斜杠命令：有执行面，但没有补全面板，且只有两条能用

- **执行面存在**：`app/lib/model/command.dart` 的 `sendRouteOf` → `command.execute`（契约 §5.7）。
- **白名单只有两条**：`connector/src/handlers.ts` 的 `const MOBILE_COMMANDS = new Set(['goal', 'plan'])`。
  其它斜杠命令按 DSH Web 的输入流水线退化成**普通消息**（这是契约 §5.7 定死的准入三条，不是缺实现）。
- **输入框没有补全**：`app/lib/ui/dsh_composer.dart` 里搜不到 `/` 触发的候选菜单；
  DSH 桌面那一套是 `packages/client/ui-input-trigger` 的 `InputTriggerService`
  （触发字符 + 候选菜单 + 落点，`contract.ts` 有 `TriggerChar` / `InputTriggerSource`）。手机侧没有对应物。

**成本**：只补 `/` 的候选菜单（候选=白名单两条 + 会话内其它命令不可用）—— 纯 UI，**轻**；
要放开更多命令，是白名单的准入判断（设计决定，不是 UI）。

## 3. `@` 文件 / 会话：**目前零实现，占位符在承诺一个不存在的功能**

- `app/lib/` 里 `@` 只出现在两句占位符文案：`dsh_composer.dart:130,137`
  （`'发消息或创建任务, / 调用指令, @ 文件或对话'`）。**没有任何解析、没有候选、没有落点。**
- DSH 桌面是有的：`ui-reference`（`@` 文件引用）+ `ui-input-trigger` 的 trigger 机制。
- 拆成两半看，成本差很多：
  - **`@ 会话`：轻**。`session.list` 的数据已经在手机上（抽屉就是它），只是没有选择面板与落点。
  - **`@ 文件`：重**。契约里没有"列目录 / 搜文件"的窄口（方法面 38 条里没有），要新增方法；
    而且 DSH 的文件引用带编码（`ui-reference` 的 `ReferenceCodec` / `user-text-rules`），
    手机侧要"发出去的东西桌面认"，不是画个列表就完事。

**判定**：占位符先写着 `@`，是**假入口**（`AGENTS.md` 明令"不摆点下去只弹还没做的假入口"的同一类）。
处置二选一：**要么实现 `@会话`**（轻），**要么把占位符改回不承诺 `@`**（1 行）。

## 4. 抽屉会话列表：没有"运行中转圈 / 完成绿点"

- **现状**：`app/lib/ui/session_drawer.dart:644` 只有一枚**连接状态点**（在线绿 / 离线灰，在抽屉头部），
  会话行本身**没有任何运行态**。
- **数据已经在手**：运行态来自 `status` 帧（W4）与 `session.list` 的 `running`，`AppModel` 里就是 `_runningSids`；
  "完成"可以由 `running: true → false` 的边沿得到。**所以这是纯 UI 的活。**
- DSH 桌面的形态（用户描述）：运行中转圈、完成后绿点、点进去消失 —— 最后一条是**本地"已读"记忆**，
  与 DSH 的 `activitySlot`（`dsh_app_bar.dart:184` 引的就是它）同源；手机侧要新增一个本地已读表。

**成本**：行首一枚状态点 + 本地已读表（落盘）+ 2–3 条用例。**不大，收益直观**。

## 5. 用量页：不可折叠、无日期筛选；而 DSH 桌面**没有用量页**

- **现状**（`app/lib/ui/usage_page.dart`）：`_TotalCard`（总量）→ 每工作区一个 `_ProjectHeader` →
  该工作区下逐条 `_SessionRow`，**全部平铺**（`:116` 把所有 section 直接铺进 `ListView`）。
  没有折叠、没有日期筛选、没有矩阵/热图、没有"明细"下钻（点行是跳到会话）。
- **日期筛选不是纯 UI**：`connector/src/handlers.ts:731` 是 `handlers['usage.summary'] = async () => {…}` ——
  **零参数**。要筛选就得先加参数（连接器 + 契约 §5.7 一行），再谈 UI。
- **参照系要说清**：DSH 桌面**没有**用量页（`packages/client` 里没有 `ui-usage`；
  只有账户页的 `usage: '查询用量'` 一个链接，`ui-settings-account`）。所以这一页是**本仓自己设计的面**，
  对齐对象不是 DSH —— 形态要设计决定，不能拿"照抄 DSH"糊过去。

**成本分三档**：① 工作区可折叠（纯 UI，小）；② 日期筛选（契约 + 连接器参数 + UI，中）；
③ 矩阵/热图 + 明细下钻（新设计，要先把"按什么聚合"定下来，大）。

## 6. 通知（会话完成 / 审批 / 问答）：**现在做不了，原因是架构级的**

**硬事实**（`app/lib/core/sync_client_impl.dart:1152-1163`）：切到后台时

```dart
if (next == AppState.background) {
  if (previous != next && _machine.acceptsBusinessFrames) await _sendHello(); // 先声明"我退了"
  await _disconnect();                                                        // 再断开
}
```

注释原文：「切后台主动断开并停表（§2.2）：**三端都不做后台长连接**（§13）」。
也就是说 **App 在后台没有连接 ⇒ 收不到任何事件 ⇒ 没有东西可以变成通知**。

三条路，代价各不相同：

| 路 | 做法 | 代价 |
|---|---|---|
| A 前台服务常驻 | Android foreground service 保连接，收事件再发本地通知 | **推翻契约 §13/§2.2**（"三端都不做后台长连接"）；MIUI 要白名单、耗电与"常驻通知"用户可见；还要处理通知权限 |
| B 系统推送 | FCM / 厂商推送通道 | 要公网推送服务端 + Google 服务（国内 ROM 还得逐家接）；契约 §15 已明写"**推送本期不做**"，方法表里没有 `push.configure` |
| C 只做 App 内通知 | 页面级横幅 + 未读角标 + 可选震动/声音 | **不碰任何契约**；但只覆盖"App 在前台、人却在别的会话/别的页面"这一档 |

**建议**：先做 **C**（与第 4 条的"完成绿点"是同一批"看得见"的改进）；A 要当**一次设计决定**立项
（会改 §13），B 保持不做。

## 排序建议（按"0 真机回合优先 + 收益/成本"）

1. 抽屉行运行中/完成态（数据已有，纯 UI）—— 收益最直观
2. 设置页"未读到"统一（1 处 UI + 1 条用例）
3. `@` 占位符二选一：实现 `@会话`（轻）或**改文案**（1 行，先止住假入口）
4. App 内通知（横幅 + 角标 + 震动/声音开关）
5. 用量页折叠（纯 UI）→ 日期筛选（要契约 + 连接器参数）→ 矩阵/明细（要设计）
6. `/` 候选菜单（白名单两条）
7. `@ 文件`（要新方法，最重，单独立项）

## 需要拍板的三件事

1. **通知**：接受"只做 App 内"（C），还是把"后台常驻连接"当设计决定立项（A，会改契约 §13）？
2. **`@`**：先实现 `@会话` 这半，还是先把占位符的 `@` 去掉？
3. **用量页**：折叠 + 日期筛选够不够，还是要一次做到"矩阵 + 明细"（后者要先把聚合口径定下来）？
