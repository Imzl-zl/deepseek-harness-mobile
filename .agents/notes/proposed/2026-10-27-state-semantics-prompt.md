## 背景（用户原话，必须当真）

> "你很显然只是复刻了外貌，深层次的你根本没看，不知道还有多少同样的问题。"
> "不要到处打补丁了……这应该涉及到状态管理了吧？给我看看怎么样优雅解决。"

已确认的同类问题（清单里的 1–7 条）只是样本：抽屉折叠态关一次就丢；模型/思考程度/工作区不记；
空白会话能直接发送（桌面不许，发了就失败）；连接时"运行中 + 子智能体后台任务"的复合状态手机呈现不全。
**这类问题的共同点是：状态没有唯一主人、约束没有唯一落点。**

## 你的任务（按顺序，先设计不写实现）

### 第 1 步：全量审计（只读，不改代码）

把 `app/lib` 里**所有**"跨页面 / 跨重启 / 跨连接该活下来"的状态找出来，逐个回答：

- 它是什么（折叠态 / 页签 / 草稿 / 选择 / 滚动位置 / 焦点 / 计数…）；
- 桌面对应物是哪个，主人是谁（联网源码 `D:\sudy\github\deepseek-harness`，给 `packages/...:行号`）；
- 手机现在住在哪里（widget 局部 / `AppModel` / 本地库 / 没有）；
- 现在丢不丢、什么时候丢（关抽屉 / 切会话 / 冷启动 / 重连）。

同时把**动作前置约束**也列出来（发送、分支、打开文件、切模型…）：
桌面在什么条件下禁用，依据是哪一行；手机是否同样禁用。

产出：一张表（状态/动作 → 主人 → 存储 → 读取时机 → 桌面证据）。**不允许"通常如此"**。

### 第 2 步：提出一个机制（一次说清，不许写成 N 个补丁）

要求：

1. **状态归属模型**：三类主人——`host`（宿主投影/接口，手机只读）、
   `browser-local-persisted`（桌面自己持久化的浏览器状态，手机应有同构替代）、
   `device-local`（手机本地偏好）。每类给出"读取时机"与"失效/迁移"规则。
2. **一个设备本地状态机制**：统一键前缀、统一序列化（版本号 + 迁移）、统一恢复点
   （`AppModel.start()` 一处），widget 不许再持有这类状态。
3. **一个动作可用性入口**：例如 `composerGateOf(...)` 返回"能用 / 缺什么"，
   UI 只消费结论；缺什么要能说人话（与桌面同一句）。
4. **连接瞬间的快照**：进服务态后一次画全（运行中、子智能体后台任务、待处理、计数），
   数据只来自宿主已有字段，**不新增宿主语义、不自造状态**。
5. 与既有约束一致：手机不拼 cwd、不伪造 fork、不代理宿主 HTTP、不新增宿主没有的边界。

产出：设计文档（放 `docs/subsystems/`）+ 决策笔记（`proposed/`），写清
"替代了哪些补丁式做法、代价是什么"。

### 第 3 步：分批落地（评审通过后再动手）

每批一条红线：**红先写用例 → 实现 → 变异校验（故意破坏，看恰好那几条红）→ 门禁全绿 → 一个提交**。
门禁：`cd app && dart analyze --fatal-infos lib test integration_test`、`dart format --output=none --set-exit-if-changed`、
`flutter test`、`node app/tools/verify-platform-boundary.mjs`、`node app/tools/verify-rpc-single-caller.mjs`；
动连接器再加 `cd connector && pnpm exec tsc --noEmit && pnpm build && pnpm test`。

建议批次（可按审计结果调整）：

1. **发送门槛**（缺工作区/模型置灰 + 说清缺什么）——最硬，直接对应一次真机失败；
2. **设备本地状态机制** + 抽屉折叠态、页签、草稿接入（先机制后使用）；
3. **选择类记忆**：模型 / 推理等级 / 工作区——**默认值优先从宿主拿**（`agent-default-model`、
   `permission.catalog` 默认档、最近选择的会话），手机只存"用户显式选过"的那一份；
4. **连接时的复合状态**：子智能体后台任务在会话页可见，与桌面同形；
5. 回验收：把 `.agents/notes/proposed/2026-10-26-desktop-alignment-plan.md` 里
   改动卡 / 逐行差异 / 正文提及三项的真机验收补掉。

## 硬规则

- 先审计后设计，**不允许先改代码再解释**；每个结论给 `packages/...:行号` 或本仓 `文件:行号`。
- 不把"桌面没有的语义"加进协议或 UI（不猜端口、不伪造状态、不自己发明默认值）。
- 不删/不弱化已有用例来变绿；改断言必须做一次变异校验并写清红了几条。
- 视觉与文案以 `docs/design-and-tech-plan.md` 为基线；**约束（能不能点、记不记）以 DSH 源码为基线**。
- 真机只在测试 profile 上动；需要扫码配对、重启桌面 DSH、开辅助功能时**停下来问用户**。
- 每批只解决一类问题；发现新的同类问题**记进清单**，不要顺手打到当前批里。
