# Agent Note: 投影包按消费者拆开 —— 轮级常新、步级按需

Status: proposed

## Problem

一条 20 轮的会话，一次 `session.projections` 的线上大小是 **80.6 KB**（2026-11-04 实测，
取 `session_projcache` 里那份 wire view 逐键量）：

| 键 | 大小 | 占比 | 谁在读 |
|---|---|---|---|
| `trajectory` | 72.2 KB | 89.6% | 轨迹页（时间轴）+ 聊天页（每轮用时） |
| `turnOutline` | 3.7 KB | 4.6% | 只有轨迹页 |
| 其余 27 个键 | 4.7 KB | 5.8% | 统计条 / chip / 权限 / 队列 |

而消费者其实只有三种新鲜度需求：聊天页每轮结束要**轮级用时**（turns-only 是 3.3 KB）、
轨迹页偶尔要**步级时间轴**（68.9 KB）、其余面要 4.7 KB。

一个包服务三种需求，被迫同步，两个方向的症状都出现过：

- **都旧**：2026-11-04 真机，轨迹页空态二十分钟，重启 App 才恢复
  （`implemented/2026-11-04-trajectory-view-refetch.md`）；
- **都贵**：每次 `turn/end` 搬 80 KB，20 轮 ≈ 1.6 MB，与当初 `session.list` 的 1.9 MB 同档。

## Decision

（待评审，未实现。）按消费者拆，分两刀。

**W1 拆键 + 按需取键**

1. `trajectory` 只留轮级：`turn` / `startSeq` / `startTime` / `endTime` / `durationMs` /
   `outcome` / `tokens` / `stepCount` / `stepsTruncated`；
2. 步级挪到新键 `trajectorySteps`（按 turn 的 `steps` 数组）；
3. `session.projections` 加**可选** `keys`：不传 = 整包（老客户端逐字不变），
   传了就只回这些键。

收益：每次 `turn/end` 80.6 → **8 KB（−90%）**；轨迹页才取步级。

**W2 步级带游标**

`trajectorySteps` 支持 `sinceTurn`，进入轨迹页只搬变化的轮（通常就是正在跑的那一轮
6.7 KB）：进页面 76 → **~14 KB**。

准入门槛：

1. **请求方知道自己要了哪些键**：要了却没有 = 没注册（照直说）；没要的键保留旧值。
   不许再出现"这份包是完整还是部分"的歧义 —— 那正是 2026-11-04 那个坑。
2. **一个键一个含义**：轮级与步级各一个键，不许在同一个键里用参数改形状（解析层会分叉）。
3. 手机上仍然**一个时间减法都不做**（`docs/subsystems/trajectory-page.md` §1 的硬规则不变）。
4. 老客户端不传 `keys` 时逐字不变；摘要键已把参数算进去（`snapshotKeyOf`），
   所以两个键、两个游标各自命中自己的摘要，不用新机制。

## Alternatives considered

1. 移植 DSH 的 `observeProjections` 推送流
   - 最强的理由：DSH 自己就是这么做的，手机端不再需要任何触发点，"旧包"这一类问题从根上消失。
   - 为何被否：它解决的是**延迟**，不解决 72 KB 的**体量** —— 推送只会让这 72 KB 来得更频繁；
     而要在加密通道上新增一条带 seq / 恢复语义的流，是这批里最贵的。
2. 每面一个方法（`session.trajectory` / `session.stats` …）
   - 最强的理由：调用方拿到的就是它要的那一块，不用理解"包"这个概念。
   - 为何被否：已有定案 —— 每面一个方法等于把 DSH 的投影面翻译一遍，而翻译层就是漂移层
     （`connector/src/dsh/projections.ts` 文件头）。
3. 手机上按事件现算时间轴
   - 最强的理由：零额外字节，事件本来就在流里。
   - 为何被否：违反"时间由电脑侧算"的硬规则；而且手机的事件窗口是分页的，
     翻页后的轮会退化成"不到 1 秒"（2026-10-22 之前就是这个症状）。
4. 压缩 / 短键名（`{t,d,o}`）
   - 最强的理由：不动协议形状，省 30–40%。
   - 为何被否：省得不够多，换来第二套不可读的线上形状与一次全量重写 ——
     可读的解析层是这个仓的既定资产。
5. 调小上限（`MAX_STEPS_TOTAL` 1200 → 300）
   - 最强的理由：一个常量，零协议改动，立刻见效。
   - 为何被否：超限是**整轮丢**（`connector/src/dsh/trajectory.ts` 的 `dropOldestTurn`），
     老轮的用时与结局会一起消失 —— 那是功能退化，不是优化。

## Consequences

- 收益：最热的那条路（每次 `turn/end`）从 80.6 KB 降到 8 KB；轨迹页的重数据只在打开时取；
  新鲜度从"靠触发点枚举补洞"变成"按需取"。
- 代价：契约 §5.7 多一个可选参数与一个键；connector 多一次切片与一个投影注册；
  app 侧多一条"按请求的键合并"的规则与它的回归用例；金样（`wire-shapes.json` /
  `session-row-payload.test.ts` 的键清单）要重生成。
- 风险：**合并语义**。W2 的游标一旦与 `truncated` / `droppedTurns` 对不上，会出现
  "某些轮有行没有轴"。必须配"按 turn 合并 + 被上限丢掉的轮一起丢"的用例。
