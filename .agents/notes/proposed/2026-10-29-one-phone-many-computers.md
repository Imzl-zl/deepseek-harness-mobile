# Agent Note: 一台手机配多台电脑（独占 1:1）

Status: proposed

## Problem

手机现在只能记住**一台**电脑，而配对与连接本来是两件事，之前被同一个单槽实现绑死了：

1. **凭据单槽**：`app/lib/platform/pairing_store.dart:162-176` 是一张平铺的键表（13 个 `dsh.*` 常量），
   `load()`（`:204-243`）只回一份 `PairedCredentials?`，`save()`（`:298-331`）把整组键重写，
   `clear()`（`:362`）是 `deleteAll()`。所以配第二台电脑 = **覆盖**第一台。
2. **设备身份按配对生成**：`app/lib/ui/pairing_page.dart:244` 每次 `toHex(randomBytes(32))` 当 master seed。
   第二台电脑看到的是**另一台设备** —— 这是安全属性（换电脑 = 换身份），但它决定了"多机"不能靠
   共用一份凭据糊过去。
3. **电脑侧的 UI 状态是单桶**：`host.*`（`app/lib/data/ui_state.dart:41-62`）装"上次看的会话 / 页签 / 草稿"，
   切换电脑时整段清（`app_model.dart:1306-1310`）。
4. **端点表剪枝与"可切回"冲突**：`Endpoint.hostId`（`app/lib/core/endpoint.dart:122`）已经按电脑分桶，
   但合并时会剪掉别的电脑的自动条目（`app/lib/data/endpoint_book.dart:151-158`）—— 对"换电脑"对，对"切回"错。
5. **中转侧 id 无校验**：连接器 `connectorId` 默认 `'local'`（`connector/src/index.ts:144`），
   而中转的控制面 key 是**令牌 id**（`relay/src/server.ts:209-216` → `digest-auth.ts:27-36`），
   两者不一致时没有任何一处会报，症状是二维码里的 `pcId` 与中转眼里的 id 不是同一个值。

### 模型（已定）

- **配对**：多对多 —— 一台手机可配多台电脑；一台电脑可被多台手机配对（名册本来就多行）。
- **连接：1 对 1 独占**。手机任一时刻只连一台；电脑任一时刻只服务一台。被占用时，新来的
  **拒绝并说明原因，不踢人**。所以"多机"在系统里 = 多份凭据 + 一个当前 + 电脑侧一个占用位。
- 由此**不需要**：跨电脑聚合、后台多路保活、每台一套连接状态机、跨电脑通知 fan-in。
  审批与提问天然只来自当前那台（副作用：连着 A 时 B 的待处理收不到，切过去才看到）。
- **独占是一条新增边界，宿主没有**（DSH 的网关服务多个浏览器 client；我们现在的连接器也天然服务多台：
  `transport/listener.ts:8` 每 accept 一条就装一次、presence 记多台 online/foreground、
  `relay/src/core.ts:106-109` 每设备一条数据通道）。所以它必须：**先改契约 docs、留本笔记、在准入处拦**。

## Decision

### 1. 三个 id 各就各位（一个都不能混）

| id | 是什么 | 谁用 | 能改吗 |
|---|---|---|---|
| `hostId` = `pcSignPubHex` | 电脑**身份**（自证式；与 Syncthing 拿证书 SHA-256 当 Device ID 同一族） | 手机分槽 / 分桶 / 端点归属 | **不能**（改了就是另一台） |
| `connectorId` | 通道 id，进握手 transcript（`connector/src/protocol/handshake-frames.ts:17`）与配对上下文（`pairing.ts:135`） | 中转路由；**必须等于令牌 id** | 能，但要重新配对 |
| `devId` | 手机在**那台电脑**名册里的行 id（`devDhPub` 哈希，`app/lib/platform/pairing_store.dart:143-158`） | 电脑认手机 | 不能 |

`hostId` 不用 `pcId` 的理由已经写在 `app/lib/core/endpoint.dart:113`（两台电脑会撞）。

### 2. 电脑名：自报的展示值，走 `repo.info`

`os.hostname()` 在连接器里直接可用（同一模块已 `import { networkInterfaces } from 'node:os'`，
`connector/src/transport/listener.ts:31`）。规则：

- 名字是**展示值**：可改、可伪造、会重名 —— 只用来给人看，从不参与任何判据；
- 过线的位置是 `repo.info`（旁边就是 `dshVersion`，`connector/src/handlers.ts:1642-1644`），
  **不放进握手 transcript** —— 否则"改个名字"就等于重新配对；
- 手机侧可改名（存本地，`host.<hostId>.name`），与电脑自报名同时存在时以本地名为准；
- 两台电脑同名时用 `hostId` 的**短码**区分（前 6 + 后 4，Syncthing 显示 Device ID 的同一种做法）。

### 3. 凭据层：按 `hostId` 分槽

键从 `dsh.<field>` 变成 `dsh.pairing.<hostId>.<field>`，外加 `dsh.pairing.active`（当前那台）。
**master seed 不重生成**（换槽是换凭据；身份仍按"每次重新配对生成一份"）。
迁移：首次读取时若只有旧平铺键，读成一台槽、写新键、删旧键（一次、幂等；判据"旧键在且新槽空"）。
`clear()` 从 `deleteAll()` 改成"删这一台的槽"，另加 `clearAll()` 给"撤销所有配对"。

### 4. UI 状态：按电脑分桶

`host.<hostId>.<field>`；切换只切桶、不删除。两个连带条件必须同时满足：

- `pruneSessions`（`app_model.dart:2690-2696`，每次会话清单刷新后调）**只许剪当前桶** ——
  否则切到 B 时会按 B 的清单剪掉 A 的页签与草稿；
- 本地 sqflite 条目按 `sid` 存（`sid` 是 16 字节随机，`connector/src/alias.ts:26,60-61`），
  两台电脑撞 `sid` 的概率可忽略，**不分区**。

### 5. 端点表：分桶、切走不删

每个 `hostId` 一个桶；切走只降序（`dialOrder` 已按 `hostId` 分桶，`endpoint.dart:326-340`），**不删**。
"别的电脑的自动条目永不留"这条（`endpoint_book.dart:151-158`）改成"只在本桶内按
'没被自报 + 拨过失败 + 从没成功' 剪"。

### 6. 切换与占用（状态机）

手机侧状态：`未连接 → 拨号 → 握手 → 同步 → 就绪`，失败落到 `连不上（原因）`。

- **切换立即生效**：先主动 close 旧的（电脑立刻释放）→ 换凭据槽 → 连新的一台。
  `active` **立刻**变成 B，界面立刻只显示 B 的数据（此刻是空的/加载中）——
  **绝不允许"B 的名字下面挂着 A 的数据"**，那是"在 A 的会话里以为在跟 B 说话"的错投来源。
  失败就停在 B 的"未连接（原因）"，**不回滚到 A**（回滚会让人以为切成功了），
  但给"切回上一台"一键。
  （更正：本笔记早前正文与 2026-10-30 的对话里说过"逻辑指针后置、成功前 active 不变"——
  对聊天这类**数据面绑在电脑上**的界面是错的：后置意味着 B 的 chrome 下面仍渲染 A 的会话，
  比"切过去是空的"危险得多。以本条为准。）
- **电脑侧占用**：准入时若已有设备在 serving，拒以**可区分的原因**（新错误码 `device/busy`），
  手机显示"这台电脑正被另一台设备连接（配对名 / 时间）"；**不踢人**；
- **占用位只对"有效设备"成立**：已停用（`revokedAt`）与已删除的行不占位，否则一台被停用的旧手机
  在名册里留着就能永久挡住新手机（占坑 DoS）。判据复用 `presence.ts` 的 `pairedAtOf` 那一处
  （"连接层认证过不等于授权过"）；
- **幽灵占用**（旧手机掉线未 FIN）：等心跳半开自动释放（`connector/src/transport/keepalive.ts`）；
  面板另给**显式"接管"**（走 `admin/device-admin.ts` 既有的写路径），不做自动抢占、不加定时器；
- **面板要显示占用者**：设备行本来有 `online`/`foreground`（`presence.ts`），再加"此刻在服务"这一档，
  否则操作者只能看到"有台设备在线"，分不出是谁占着。

### 7. 时间预算与提示（数字与依据）

| 层 | 上限 | 依据 |
|---|---|---|
| 单条直连拨号 | 3s | 现有 `app/lib/platform/transport_factory.dart:52`（死地址不该拖满 10s，`:22-25` 有理由）；局域网 RTT 毫秒级，3s 容 3 个 RTO |
| 单条中转拨号 | 10s | 现有同文件 `:43`；公网 + WS 升级 + 中转排队 |
| **拨号总预算** | **15s** | 并行竞速后总预算 ≈ 单条上限 + 错开；15s 是硬上限（不许"N 条 × 单条上限"全交给用户等） |
| 握手 | 10s | 现有 `app/lib/core/handshake_driver.dart:45` |
| 首同步（第一页） | 15s | 500 条分页，慢网 2–3 个往返 |
| 请求 / 心跳 | 60s / 60s | 现有；两者同量级（RFC 5382 一类建议） |
| 提示时序 | 2s 出阶段 → 8s "网络很慢" → **15s 出结论 + 手动重试** | 2s 内绝大多数连接已通（RFC 6298 附录：97.5% 连接 RTT < 1s）；15s 是人在看时的耐心上限 |
| 结论之后 | 静默慢重试：60s + ±20% 抖动 | 用户已拿到结论，重试不该再打扰；抖动防惊群 |

结构照主流：分层 deadline + 有界重试 + 指数退避带抖动 + 到点给结论
（[AWS：retry storm / backoff+jitter](https://builder.aws.com/content/3JXo23BdhUUzrapO0UHVNXYHqYB)、
[RFC 6298](https://www.rfc-editor.org/rfc/rfc6298)）。退避本仓已合规：
`app/lib/core/connection.dart:131,157` 是 ±20% 抖动、10 次上限、用尽后给手动重试。

**拨号改成竞速：并行拨 socket、串行握手**（照 Happy Eyeballs 的做法）。
现在 `app/lib/core/endpoint_transport.dart:116` 是**串行** `for (const endpoint of endpoints)`，
2026-10-17 真机被三个死 IPv6 地址拖成 30 秒（`platform/transport_factory.dart:22-25` 记着那次）。
竞速的边界必须画清楚：**只竞速"连接建立"**，赢家才走握手 —— 否则同一台电脑会同时收到两条
同一设备的握手，撞上 relay 的"同设备单通道"与本章的独占判据。输家立刻关，不留半开。

### 8. 前置：水位判据必须先改

`connector/src/session-buffer.ts:100-108` 的裁剪点 = **全部配对未吊销设备**水位的最小值，
从没确认过的设备按 0 算 → 一行都不裁。独占模型下"配了 3 台只连 1 台"是**常态** →
缓冲永不裁剪 → 涨到 16 MiB / 10000 条 → **每次切回都退化成快照**。

所以独占与"裁剪点改用当前 + 最近活跃设备集"必须**同批**落地，否则多机一开就是在制造
"每次切回都全量重灌"。

### 9. 前置二：端点条目的 id 是 URL，多机下会串

`Endpoint.id => url`（`app/lib/core/endpoint.dart:130`），而端点表的合并、剪枝、"曾经成功"集合、
"记住的那条"全都按这个 id 走（`endpoint_book.dart` 的 `_succeededEndpointIds` / `rememberedEndpointUrl`）。
两台电脑先后用同一个局域网地址（`192.168.x.y:8790`）时，它们共用同一条记录与同一份历史：
后者的"成功过"会给前者的死地址续命（剪枝规则是"成功过的永不删"），"记住的那条"也会指向不属于
当前电脑的地址。

所以多机落地时端点条目的身份必须带上归属：**id 里含 `hostId`（或让 `remembered` / `hidden` /
`succeeded` 三份元数据按 host 分桶）**。这条与第 5 条（端点分桶、切走不删）是同一件事的两面。

### 10. 换网重连：同设备靠 relay 顶替，别把它和"另一台手机"混起来

relay 对同一个 `(connectorId, deviceId)` 的新数据通道会先 `closeLink(previous, …, 'replaced')`
再准入（`relay/src/server.ts:184-185`），而 `relay/src/core.ts:96-97` 还留着一条
"旧设备连接必须先关闭"的不变式。所以：

- **同一台手机换网重连**：靠 relay 的 replaced 语义自动恢复，**不要**在连接器再加一道门 ——
  否则换网会把自己挡在门外；
- **另一台手机的占用**：relay 看不见（`(connectorId, deviceId)` 不同就是不同 key），必须由连接器
  在准入处判 `device/busy`。

两者是两条不同的规则，混在一起就会出现"换网连不上自己"或"第二台手机把第一台挤掉"。

## 准入门槛（落地时逐条可机械判定）

1. **两个槽互不影响**：配对 A → 配对 B → A 的 `deviceToken` / `masterSeed` 逐字未变
   （真值取自 `PairingStore.load()`），且 `active == B`。
2. **迁移幂等**：旧平铺键 → 一次迁移后 `load()` 与原值逐字相等，再跑一次**不写第二遍**（判据是写次数）。
3. **切回来不掉状态**：A 的 `host.*`（last_session / 页签 / 草稿）在"切到 B 再切回 A"之后仍在，
   且 B 的清单刷新**没有**剪掉 A 的键（直接断言 `pruneSessions`，不靠界面）。
4. **独占可区分**：已有设备在服务时，第二台的失败原因是 `device/busy`（不是 `not-paired`、不是超时），
   且手机上显示占用者名字；错误码四处门禁（`error-table-parity` / `error-code-table` /
   `flow.test.ts` 的封闭+满射 31 / `methods.test.ts`）同批更新。
5. **切走即释放**：A 的手机切走后，电脑侧的占用位在**下一次**心跳之前就空（主动 close 的判据）。
6. **端点不丢**：切到 B 之后 A 报过的自动条目仍在表里（只降序），切回 A 首拨命中它。
7. **15 秒必须有结论**：模拟"三条端点全不通" → 15s 内出失败态 + 手动重试，且之后的重试是 60s 间隔
   的静默慢重试（不是继续刷屏、也不是再也不试）。
8. **水位按活跃集裁**：配对 3 台、只连 1 台时，缓冲仍能裁剪（用 `session-buffer` 的用例直接断言）。
8b. **端点归属不串**：同一 URL 先后属于两台电脑时，"曾经成功"与"记住的那条"各自独立
   （判据：给 A 的 URL 记一次成功、切到 B 后同 URL 不继承；A 的死地址在 B 的连接过程中不被保活）。
8c. **换网不挡自己**：同一设备在旧通道未 detach 时重连，仍能建立（relay 的 replaced 语义），
   而另一台设备在同一时刻被 `device/busy` 拒 —— 两条都要有用例。
8d. **竞速只赢一条**：给 3 条端点（2 条必挂）→ 只有 1 条 socket 走到握手，输家被关闭且不留半开；
   总耗时 ≈ 单条上限 + 错开（不再随端点条数线性增长）。
8e. **停用的设备不占位**：给一台设备打 `revokedAt` 后，它既不能占住占用位，也不能把占用位一直挂着；
   删掉行同样释放（占坑 DoS 的判据）。
9. **不许新增定时器/重试策略之外的兜底**：切换是用户动作，失败如实报（宿主没有"自动挑一台电脑"这回事）。

## 落地顺序（每步独立可验证，不一次性推）

按"先堵串台、再拆凭据、再修通道、最后做独占"排，因为前两步的错法会掩盖后两步的现象：

1. **归属**：`Endpoint.id` 带 `hostId`（或三份元数据分桶）+ `host.*` 分桶 + `pruneSessions` 限桶。
   纯逻辑，`app/test` 里可整组断言；不改 UI 形状。
2. **凭据**：`PairingStore` 分槽 + 幂等迁移 + `clear/clearAll` 拆分。判据是**写次数**，不是"看起来一样"。
3. **通道**：`session-buffer` 裁剪点改"当前 + 最近活跃设备集"；拨号改竞速（并行 socket / 串行握手）。
   这两条都不碰 UI，可直接用真机地址重放（2026-10-17 那三个死 IPv6 地址就是现成的靶子）。
4. **独占与切换**：`device/busy` 错误码（四处门禁同批）+ 占用位（含"停用不占位"）+ 切换状态机 +
   15s 总预算与分级文案。到此才第一次出现"用户体验"层面的改动，也是唯一需要真机验收的一步。

**本轮不写代码**：这是方案，四步各自都能独立开工、独立验证；每步落地时补一篇
`implemented/` 笔记并回指本页。

## Alternatives considered

1. **同时连多台（fan-in：所有电脑的通知都能收）**
   - 最强的理由：审批/提问不会因为"没连那台"而延迟；家里公司两台都在线，体验最完整。
   - 为何被否：用户已明确定 1:1 独占。技术上它要 N 条通道 + N 条电量账，还要防"在 A 的会话里点批准
     实际批到 B"，而收益只是"通知更全"——那不是这个产品的瓶颈。
2. **共用一份凭据（一个 master seed 连所有电脑）**
   - 最强的理由：凭据层零改动，一台手机一套身份，哪台都认（`devId` 两端同一算式，
     `pairing_store.dart:143-158`）。
   - 为何被否：那要改 `pairing_page.dart:244` 的"每次新生成"语义，而那条语义是安全属性
     （换电脑 = 换身份，旧电脑的令牌泄露不牵连新电脑）。省下存储改造，付出身份语义。
3. **只把地址做成集合、凭据不分槽**
   - 最强的理由：切换只是换地址，UI 状态完全不用动。
   - 为何被否：`deviceToken` 是**每台电脑签的**（摘要经 `POST /devices` 进名册，
     `relay/src/core.ts:53,106-109` 按 `(connectorId, deviceId)` 归户），一份令牌在另一台电脑上不认。
4. **用 `connectorId` 当 `hostId`**
   - 最强的理由：它已经在过线（transcript 里就有），不用新加字段。
   - 为何被否：默认值 `'local'` 会撞（`endpoint.dart:113` 的原话），而且它可改（改了要重配对）——
     身份必须不可变。
5. **抢占地踢掉旧连接（新来的赢）**
   - 最强的理由：用户不会被"幽灵连接"卡住，永远能连上。
   - 为何被否：那会让"正在另一台手机上操作的人"被无声踢下线（症状是"手机自己断了"）。
     幽灵连接用半开检测 + 显式接管解决，代价是那条罕见的等待。
6. **无限重试 + 一直转圈（不设总预算）**
   - 最强的理由：慢网下"再等等就好了"，不会误报失败。
   - 为何被否：用户看到的是"转圈"，无法判断是慢还是坏；而且串行拨号 N 条端点最坏要 30s+。
     15s 出结论 + 之后静默慢重试，两者兼得。

## Consequences

- 收益：一台手机可以记住多台电脑并随时切回；`host.*`、端点表、凭据三处第一次有同一个归属维度
  （`hostId`）；"连不上"第一次有分级原因（拨号 / 握手 / 同步 / 被占用），而不是一个转圈。
- 收益：独占模型砍掉了 fan-in、多路保活、每台一套连接状态机 —— 这是本方案最大的一笔减法。
- 代价（凭据层）：`PairingStore` 的 13 个常量键变成"前缀 + 槽"，`save/load/clear` 都要先算 `hostId`；
  迁移代码要活一段时间；`clear()` 的语义变了 —— "撤销配对"与"忘掉这一台"成为两个动作，界面必须分开表达。
- 代价（UI 状态）：`host.*` 全量键要按 `hostId` 重排，`pruneSessions` 必须带桶参数；这是唯一会碰
  `ui_state.dart` 既有迁移逻辑的地方（三类主人不变，但 `host.*` 从"一段"变成"一棵"）。
- 代价（通道）：独占是新增边界，要动契约 docs + 一个新错误码 + 四处错误码门禁；
  `connectorId` 与令牌 id 的比对如果要做到"不一致就拒绝"，还得动 relay ↔ connector 的协议面
  （`?id=` 之类），老连接器不带时必须继续放行 —— 这条兼容分支的生命周期要在落地时写死。
- 代价（协议）：`repo.info` 多一格 `hostName`（展示值，可缺）；`device/busy` 是新错误码。
- 仍未解决（本轮不碰）：同一台手机在同一台电脑上配两次仍走 `replaces`
  （`implemented/2026-10-17-repair-replaces-device-row.md`），与"多台电脑"是两个维度，别混。
