# Agent Note: 三方路径卡在"连接器的首帧没有抵达中转"

Status: proposed（一条用例已 `skip` 并指向本篇；本轮已落地的只有中转的日志与留声）

## 现象（有日志证据，不是猜测）

三方用例（中转子进程 + 连接器真连接层 + 带票升级的设备替身）走到"设备发一行"这一步时超时。
把中转的日志打开（`DSH_RELAY_DEBUG=1`，本轮给 `main.ts` 接上了 logger）后，输出是：

```
[relay:debug] 配对登记：hash-a… → conn-1
[relay:debug] 已发票给设备 dev-1（1 张待用）
[relay] 设备 dev-1 换到票，绑定连接器 conn-1      ← 认领成功 ⇒ controller 认为连接器**在线**
[relay:debug] 丢弃设备侧帧：这个 sid 还没有归属（sid_1） { deviceId: 'dev-1', t: 'req' }
[relay:debug] 中转丢弃一帧：这个 sid 还没有归属 { sid: 'sid_1' }
```

由此能确定两件事：

1. **设备侧一切正常**：换票、认领、升级、发帧都到位（它的帧到了中转，只是没有归属）。
2. **连接器那条 `ev`/`res` 帧没有进入 `core.onLine`**：否则 `routing.fromConnector` 会设置归属，
   设备帧就不会被丢；而且若它因"来源连接器不在线"被丢，日志里会有那一行 —— **没有**。

## 已经排除的

- 不是"连接器没连上"：同一地址、同一令牌的升级在本文件另一条用例里通过，
  且"认领成功"要求 `connectors.has('conn-1')` 为真（`core.ts` 的 `claimTicket`）。
- 不是"`ev` 被攒批耽误"：把首帧换成**不攒批**的 `res` 之后仍然超时。
- 不是 sid 解析：设备帧的 `sid_1` 被正确读出来（日志里打的就是它）。

## 下一步的诊断（按成本排序）

> **更新（同日第二轮观测）**：加上"包一层 `dial` 记录实际写出的字节"之后再跑，**中转日志里
> 不再出现"丢弃设备侧帧"** —— 也就是说这一轮归属**学到了**、设备那一帧**被转发了**，
> 而连接器的 `onFrame` 仍然是空的。症状因此从"中转没收到"**收窄**到：
> **连接器的入站路径（或中转那条 socket 的写出）**。两次运行的差异（一次丢、一次没丢）
> 本身也说明这里有一条**时序**在起作用（首帧与 `attachConnector` 的先后）。
> 下一步优先查两件事：① 中转把投递写给连接器时 `ws.send` 是否抛错（`ws` 的错误走 `error` 事件，
> 我的 `server.ts` 目前**没有监听它** —— 那是一条静默失败路径，值得补上并留声）；
> ② 连接器入站路径上是否有东西把这一帧挡掉（`assertHandshakePhase` / 重放守卫 / `needsBox`）。

1. **在 `core.onLine` 的连接器分支加一条 debug 留声**（本轮试过，但编辑因"文件已变"没落上）：
   它会把"收到/丢弃/投给谁"三态都记下来，一次运行就能定位到底哪一步。
   运行结果证明"投给谁"这一步是通的（本轮没有丢弃日志）。
2. **给中转的 socket 加 `error` 监听并留声**：`ws.send` 失败目前**完全静默**，
   而"对端没收到"与"写失败"在日志上无法区分。这是本轮新发现的一条静默路径。
3. **检查连接器侧的入站**：连接层把 `req` 帧交给 `options.onFrame` 之前会过
   `assertHandshakePhase` 与解箱；在明文通道模式下 `box` 原样透传 —— 值得在测试里
   直接断言"连接器收到了任何东西"，以区分"帧没到"与"帧到了但形状不符"。


## 本轮已落地（与上面那条待查无关的部分）

- **中转终于会留声**：`main.ts` 给 `startRelay` 传了 logger（`info`/`warn`/`error` 默认可见，
  `debug` 由 `DSH_RELAY_DEBUG=1` 打开）。此前中转**一条日志都不打**，这正是本轮排查第一次
  只能靠猜的原因；补上之后，上面那段证据是一次运行就拿到的。
- 三方用例本身作为 `skip` 保留（带原因指向本篇）：它记录了要走通的形状，
  比删掉它更有用；但**不许**把断言放宽来让它变绿。

## 为什么这一轮停在这里

上面三步诊断每一步都要动一条链路并重跑（每次约 1-6 秒），而本轮上下文已到极限 ——
继续改下去很可能在没跑通的情况下留下更乱的中间态。**树是绿的（259 通过 / 1 跳过）**，
证据与下一步都写在这里，下一轮从第 1 步开始。
