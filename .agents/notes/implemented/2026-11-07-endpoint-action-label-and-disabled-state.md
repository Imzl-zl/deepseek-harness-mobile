# Agent Note: 动作行只写动作，状态交给控件本身

Status: implemented

## Problem

真机反馈（原话）：

> 那个设置中的连接方式啊，我点击正在用的下面有一行已经在用，你就置灰按钮就行，
> 有必要多此一举吗？我是看不出来吗？还有你这按钮文案怎么想的这么 low 一点不专业啊？

两件事：

1. 端点弹框里，**正在用的那条**已经是置灰 + 打勾，偏偏又挂一行
   「已经在用这一条」；「选择连接方式」那张 sheet 同样挂了「当前连接」。
   控件已经用"灰 + 勾"说完了，再写一行等于把同一个事实说两遍。
2. 动作名写成了「现在用这条连」——口语，不像一个动作。

## Decision

1. **能由控件表达的状态，不再写标签**。两处端点列表（设置页行尾「⋯」的动作 sheet、
   「选择连接方式」）都去掉「当前连接 / 已经在用这一条」这类标签，
   只保留置灰（`enabled: false`，Opacity 0.45）与勾位。
2. 动作行用动词短语：「现在用这条连」→「**立即连接**」。
   「删除这个端点」保留 —— 它是动作 + 对象，且删除确认框里要靠它区分。

## Alternatives considered

1. **沿用它 2026-11-06 的「状态类可以留」**
   - 上一版把「已经在用这一条」列进了"可以留"的例外。
   - 为何改成不留：那条例外的前提是"控件表达不了"，而这里控件**正好能**
     表达（禁用 + 勾）。能用控件说清的事再写一句，读者要多扫一行，却不多知道一件事。
2. **保留标签、去掉置灰**（只靠标签说明"这条是当前的"）
   - 为何被否：那会让"当前"看起来仍可点，点下去要么无反应、要么真去重连 ——
     两种都不如"置灰 + 勾"干净。

## Consequences

- 判据收窄为一句：**控件能表达的（禁用、勾、排序、计数值）不写文字；控件表达不了的
  （首选、提供商默认、拨号结果、URL）才写**。旧的文案笔记不删，结论加一行指针。
- 用例：`settings_page_test` 的「行尾 ⋯」那条改为断言 `立即连接` 在、
  `已经在用这一条` 不在（回归"同一件事不说两遍"）。
- 代价：弹框里不再有一句话解释"这条就是当前用的"，新用户要自己把"灰 + 勾"读成当前 ——
  这与列表里其它选择类控件（模型、权限档）是同一套视觉语言。
