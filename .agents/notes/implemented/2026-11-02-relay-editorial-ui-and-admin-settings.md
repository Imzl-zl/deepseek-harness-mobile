# Agent Note: 编辑风 UI + 管理台可改 SMTP、注册与默认额度

Status: implemented

## Problem

两件事同时卡住：

1. 管理台只能「发测试邮件」，不能改 SMTP，也不能改注册开关/邮箱域名；每次改都要上服务器编辑
   `relay.config.json` 再重启。new-api 这类面板把这两组放在「设置」里，管理员不应为了换一个发件人
   去碰容器。
2. 用户端与管理台是深色 slate + 青绿圆角卡片，和"自托管、只转发"的产品气质无关；截图里大段解释
   文字进一步让它像说明书。需要一次破坏性视觉更新，而不是换一套颜色变量。

## Decision

### 设置页

- `/admin` 新增「设置」：SMTP（host/port/secure/starttls/user/pass/from/fromName）、注册
  （open/closed、邮箱域名白名单）与默认额度（默认电脑数、新账号默认月额度）。
- 默认电脑数写 `auth.limits.defaultMaxConnectors`，对没单独覆盖的用户生效；默认额度写
  `auth.limits.defaultQuotaBytes`，在注册时快照进用户行，所以只影响新账号。
- 保存顺序固定：**先写回 `relay.config.json`，再改运行时**。写失败回 500，界面不假装成功。
- 发信用一个门面 `Mailer`：`createAccountsFace` 启动时抓住门面，管理台换 SMTP 时只替换
  `currentMailer`，不重建账号面；测试邮件与验证码都走同一扇门。
- 注册策略改的是 `runtimeAuth.registration`（`parseAuthConfig` 快照的可变副本），`face` 每次请求
  读当下值，所以保存即生效。
- 密码留空 = 保持原值；接口只回 host/port/from 等公开摘要，不回密码。

### 视觉

- 纸张底色、衬线标题、细线分隔、单色朱红强调；按钮/输入/标签全部去圆角，靠字阶与留白分层。
- 亮/暗跟随系统：亮色是暖纸，暗色是近黑纸；同一套 token。
- 用户端（登录/控制台）重写 `ui/theme.ts`；管理台在旧 CSS 末尾追加一层 editorial skin，
  保留已有表格/图表类的结构。
- 设置页的 2 秒轮询不再重画：`refresh(force)` 在 `#/settings` 且非强制时只更新 `lastState`，
  保存成功才 `refresh(true)`；否则正在输入的表单每 2 秒被清空。

## Alternatives considered

1. **只换颜色，保留深色圆角卡片**
   - 最强的理由：改动最小，所有页面自动一致。
   - 为何被否：用户明确要"破坏性更新"；只换 hue 仍是同一套通用 SaaS 卡片，问题不在颜色。
2. **SMTP/注册继续只改配置文件**
   - 最强的理由：配置是启动期真值，不用处理运行时替换与写回失败。
   - 为何被否：这正是用户提出的缺口；new-api 已经证明管理员面板可以承担这类设置。
3. **把设置写进账号库，不写配置文件**
   - 最强的理由：事务简单，面板与库同源。
   - 为何被否：SMTP 是进程级配置，CLI `--check-smtp`、容器重启、非账号模式都读配置文件；
     写库会造出第二个真值。
4. **设置保存后重启进程**
   - 最强的理由：不用维护运行时可变策略，逻辑最简单。
   - 为何被否：容器里重启会断掉所有在线连接；面板改一个发件人不该有这种代价。
5. **设置页继续 2 秒整页重画，靠前端缓存输入**
   - 最强的理由：不改轮询语义。
   - 为何被否：缓存要覆盖所有字段与焦点，仍有竞态；直接在该视图跳过轮询重画更小、更可靠。

## Consequences

- 收益：管理员在面板内完成 SMTP/注册变更；保存即生效；密码不回显；视觉有明确产品性格。
- 代价：设置写回是整份 JSON 重写，与 CLI/令牌写入共享同一竞态面（已有纪律：先落盘再改内存）；
  写失败时配置与运行时都不变，界面回 500。
- 代价：管理台保留旧 CSS 再追加 skin，存在一层死样式；后续可把旧块整体删除，只留共享 token。
- 代价：`currentMailer` 是进程内单点；多副本部署时每台都要各自保存一次（当前中转是单进程）。
