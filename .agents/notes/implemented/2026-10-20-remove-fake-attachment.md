fix(app): 拔掉「＋」里的假附件（静默丢弃）—— 它比死按钮更糟

## 缺陷

`＋` 菜单的「附件」原先这么写（`chat_page.dart` 的 `_showAttachSheet`）：

```dart
case '附件':
  setState(() => _attachments.add(const PendingAttachment(name: '新增文件.txt')));
```

而 `_send()` 的 `content` **只有文本块**：

```dart
'content': [ {'type': 'text', 'text': text} ],
```

于是：用户点了「附件」→ 输入栏里出现一枚 `新增文件.txt` 芯片 →
发出去 → **芯片被清掉、附件从未发送**。用户以为传了文件。

**这比死按钮更糟**：死按钮是"没反应"，这个是"看起来成功了"。

## Decision

1. **移除「附件」那一行**。没有附件传输通路就不摆 —— 与"不做死按钮"
   同一条纪律，而且这条更严（它会骗人）。
2. **保留** `PendingAttachment` 与输入栏的附件轨道（那是已经做对的布局：
   卡片内部、文字行上方）。布局规则的测试**改成直接构造 composer**：
   这比经菜单验更准 —— 菜单那一步是"怎么来的"，要验的是"摆在哪"。
3. `widget_test` 里那条改成**防复发守栏**：断言菜单里**没有**「附件」
   （将来做附件管线时它会红，提醒把这条改掉）。
4. **示例数据里补一条 `TurnProcessItem`**：否则 2026-10-20 做的
   turn-tail 行（复制 + 用量 pill）要等真会话才出现，用户没法在看界面时评价它。
   数字是示例值（与这个文件里其它样例一样，照真实形状编）。

## 为什么不做成真的

`session.prompt` 的 `content` **已经能带非文本 part**
（`connector/src/handlers.ts` 的 `requireContent` 只校验"每项是带 type 的对象"），
缺的是手机侧整条管线：选图/选文件 → 编码成 DSH 的 `PromptPart` →
体积限额 → 附件读取。那要一个新依赖（picker）与一组新测试，**是独立一项**。
只做那张 sheet 就是一排加假芯片的按钮。

## Consequences

- 收益：不再有"以为传了文件其实没传"的路径；菜单里剩下的每一项要么真的做事
  （演示接管），要么老实说"还没做"。
- 代价：菜单少一项；示例数据多一行（`preview-2` 的 TurnProcessItem）。
- 测试：`composer_layout_test.dart` 新增"附件在卡片内部上方"（直接喂两个附件，
  断言芯片在文字行上方、且在 composer 矩形内）；`widget_test.dart` 那条改成
  守"菜单不再摆附件"。`flutter test 841` 全绿。
- **真机**：示例会话里 turn-tail 行显示
  `🕐 第 2 轮 2 分 36 秒 · 2 条消息 · 2 次工具` + `用量 94.4K tok` + `复制`
  （窄屏上 `Wrap` 自动把「复制」折到第二行）；
  点用量开出「本轮用量」：`94,408 tok` / `缓存命中 30%` /
  `未缓存输入 66,352 tok` / `缓存读取 27,946 tok` / `输出 110 tok` —— 全部验过。
