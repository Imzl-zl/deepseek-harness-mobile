# Agent Note: 中转的 HTTP 面 —— 状态码是客户端的输入，不是随手写的数字

Status: implemented（`relay/src/http-face.ts`；`http`/`ws` 服务器接线与令牌摘要表见"仍未做"）

## Problem

契约 §2 定下两个凭据路径（设备换票、连接器直连），§12.1 又加了"出码登记"。这三件事都需要一个
HTTP 面，而**它最容易写歪的地方是状态码**：如果"配对码过期"与"网络打不通"回同一个码，
手机就只能在"重试"和"重新配对"之间猜 —— 而猜错的代价是用户以为扫码成功了。

另外两处需要当场定死，否则会渗进实现里：

1. **配对不可用时绝不能发票**（哪怕是"先发票再让升级失败"也不行 —— 那张票本身就是凭据）。
2. **两个端点不接受对方的凭据**（连接器令牌换设备票、设备令牌替连接器登记，都必须明确拒绝）。

## Decision

`relay/src/http-face.ts` —— 只做"请求 → 判定 → 响应"，**不碰 HTTP 服务器**：
`ws`/`http` 的接线是薄薄一层，而"什么令牌换什么票、什么情况该拒"才是会被反复改、
也最该被单测盯住的部分。令牌校验做成**注入的端口**（`authenticate`），
因为"令牌摘要存在哪里"还没落地（那是中转的库，属于另一块）—— 但"校验失败一律 401"
这条判定现在就能定死。

| 状态码 | 含义 | 客户端该做什么 |
|---|---|---|
| `401` | 令牌无效/缺失 | **换票或重配**，而不是拿同一个令牌重试 |
| `409` | 配对登记不可用（没登记/过期/已认领/连接器离线） | 提示"请让电脑重新出码" |
| `400` | 请求本身不合法（缺 `codeHash`） | 客户端 bug —— 与 409 是两件事 |
| `403` | 凭据类型不对（拿连接器令牌换设备票） | 客户端 bug |
| `405` / `404` | 方法/路径不对 | 客户端 bug |

**409 里不细分原因**：那几种处境对手机是同一件事（重新出码），细分只会让客户端多几个
永远走不到的分支 —— 这与连接器侧"把失败原因翻成一句用户看得懂的话"是同一种取舍。

两个端点**都不接受配对码**：手机送 `codeHash`、电脑侧登记 `codeHash`（§12.1），
中转从头到尾没见过码 —— 与 §12 表里那一列 `code_hash` 一致。

准入门槛（可机械判定）：7 条用例 —— 换票成功且**票真的能用**（绑到换票时的设备）、
401 三种形态、409 两种形态且**拒绝时票数为 0**、403 两种方向、400、登记后真的换得到票、
405/404。

## Alternatives considered

1. 配对不可用时也发票，让 WS 升级那一步再失败
   - 最强的理由：HTTP 面更简单（只做认证与发票），配对判定集中在升级路径。
   - 为何被否：**票本身就是凭据** —— 发出去就存在了（会被记进客户端日志）。
     而且那样手机拿到的是一个"看起来成功、随后莫名失败"的结果，排错方向直接跑偏。
2. `409` 里带上具体原因（`expired` / `consumed` / `connector-offline`）
   - 最强的理由：客户端能显示更精确的文案。
   - 为何被否：对手机这三种是同一件事（让电脑重新出码）。而且"连接器离线"这种信息
     属于**中转的基础设施状态**，把它告诉设备等于让设备观察中转的内部 —— 与 I10 的精神相反。
3. 把 HTTP 面与服务器写在一起（一个 `server.ts` 从路由到监听一把梭）
   - 最强的理由：少一个文件，读起来"一眼看到全貌"。
   - 为何被否：那样状态码与判定只能靠起服务器来测（慢、脆、容易变成"测了但没断言"）。
     判定是会被反复改的部分，它必须能被 7 条几十毫秒的用例钉住。

## Consequences

- 收益：设备入口与登记入口的**判定**就绪且被测（relay 33 条：路由 7 + 登记 6 + 大脑 6 + 票 7 + HTTP 7）；
  状态码语义写成了表，客户端可以照着实现。
- 代价：真正的监听（`http` + `ws` 升级）与令牌摘要表仍未写；HTTP 面目前**没有调用方**。
- **仍未做（下一轮）**：
  1. `relay/` 的工程骨架（package.json / tsconfig / 测试脚本）—— 现在仍靠连接器的工具链跑测试。
  2. `http` + `ws` 接线：两个入口（连接器校验令牌 / 设备消费票），
     `ws` 在中转是**运行时依赖**（中转接受连接，而连接器只拨号、用 Node 自带客户端）。
  3. 令牌摘要表（§12.2 的 SQL 面）：`authenticate` 端口的真实实现。
  4. 电脑侧出码时调 `/pairing/register`（连接器侧的网络装配）。
