# Agent Note: 中转是选出来的一个默认值，不是要用户填的地址

Status: implemented

## Problem

「添加端点」里选中转，给的是一张空文本框（占位符 `wss://你的域名`）。可这个 App
自带一条中转（`wss://dsh.0t0.me`，`relay/` 部署在那台机器上）—— 开箱即用的东西被
做成了作业题。用户原话：

> 内置我的中转可以开箱即用，但是你这个居然是填写的。那用户换了自己的，之后又想用我的那咋办？
> 你这个应该是选择框的吧，可以选我的，可以自己输入。

真正的问题不是"少一个默认值"，而是**那条地址没有名字**：一旦用户换成自己的，
内置那条在界面上就再也回不去了（他得记得那个域名）。

## Decision

中转那一栏改成**二选一**：「内置中转」/「自定义」，默认落在内置。

准入门槛（可机械判定）：

1. 选中转 ⇒ 出现两行选项，内置那行选中，地址以标签形式**显示**（不是输入框）。
2. 内置态下不出现 `TextField`；提交的 `Endpoint.kind` 是 `relay`、`url` 是内置值。
3. 切「自定义」才出现输入框，填什么加什么；再点回「内置中转」就换回内置值。
4. 内置值只有一个出处：`core/endpoint.dart` 的 `kBuiltinRelayUrl`，
   `--dart-define=BUILTIN_RELAY` 可整体替换（与 `kAppVersion` 同一种做法）。

直连**没有**内置值：电脑的局域网地址只有那台电脑知道，连接器自报的那几条本来就在表里。

## Alternatives considered

1. **保留空白输入框，只把占位符换成内置地址**
   - 最强的理由：零改动，用户想填什么都能填。
   - 为何被否：占位符不是值 —— 不点键盘直接提交会拿到空串；而且"内置"这件事仍然没有
     名字，换回内置还是得背域名。
2. **把内置中转做成端点表里的一条预置记录（配对前就存在）**
   - 最强的理由：用户什么都不用做，列表里就有。
   - 为何被否：中转端点要凭据才拨得动（换票用设备令牌），没有配对时它是一条**必然拨不通**
     的记录 —— 端点表里摆一条死地址，比不摆更让人困惑。地址来自配对载荷的 `relay` 字段，
     那条路径已经通了。
3. **在设置页加一行"中转地址"配置**
   - 最强的理由：改地址是设置项，放设置页名正言顺。
   - 为何被否：那会把"端点表"变成两个真相源（设置里一个值 + 队列里若干条）。端点表本来
     就是用户手填与连接器自报的合集，多一条"配置值"只会多一处同步。

## Consequences

- 收益：装上就能用；换成自己的之后，切回内置是一下点击，不用记域名。
- 代价：域名进了源码常量（不是秘密 —— 每张配对载荷里都有它）；换一台中转要重新构建，
  或者用 `--dart-define` 覆盖。
- 代价：多了一个"内置"概念，界面上要靠标签把"这条不是用户填的"说清楚（现在靠 `开箱即用，不用填` 这个 tag）。
