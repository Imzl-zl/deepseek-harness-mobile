# Agent Note: 配对端点独立成层 —— 安全边界只能有一处实现

Status: implemented（`src/pairing-endpoint.ts` + 连接级 e2e；**产品的出码入口**仍未接，见"仍未做"）

## Problem

配对链路上"校验配对码 → 落设备行 → 回执"这一段是**安全边界**：谁成为设备由它决定。
而它有两个消费者：产品装配（`index.ts`）与测试 fixture。两边各写一遍必然分叉，
而分叉的表现是"测试里配对成功、真机上不行"（或反过来）—— 最难查的一类。

另外三个顺序/失败语义上的判断，写错了都不会报错：

1. 配对失败（码过期/不对/已用过）**不是协议错误**：手机要能显示"码过期了"，
   所以不能像协议错误那样关连接（§9），而要回一个带原因的回执。
2. **先落设备行、再回执**。反过来的话，手机收到回执立刻握手，而那时 `peerOf(devId)`
   还查不到 —— 表现为"配对成功但连不上"。
3. 落设备行**失败**就不能回 `ok`：那让手机拿着一个不存在的身份去握手。

## Decision

- **独立成层**（`pairing-endpoint.ts`），产品与 fixture 用同一处实现；
  这一层只依赖三个收窄的端口（`pairing` 核心、`putDevice`、`reply`），
  所以两端都不需要认识对方（产品传 `devices` 表与 `sendPairingFrame`，fixture 传内存表与同一个发送口）。
- **从不抛**：连"载荷不是 JSON"也只回一个原因（`配对请求格式不对`），**不关连接**。
- **先 put 后 reply**，并在测试里**断言这个顺序**（`order` 数组）—— 这是唯一容易被写反的地方。
- 落行失败 → 回 `电脑侧没能保存这台设备，请重试`，**不报 ok**。
- 失败原因在**电脑侧翻译成用户看得懂的话**（`REASON_TEXT`）：手机只管显示，
  不必再维护一张"错误码 → 文案"的映射（那种映射放在客户端必然滞后）。

准入门槛（可机械判定）：

1. 成功路径：落一行设备行（含 `pairingId`）+ 回执带 `devId` 与 6 位 SAS。
2. `order === ['put', 'reply']`。
3. 过期 / 不对 / 已用过 → 各自的原因文案，且**从不抛**。
4. 坏 JSON → 只回原因（不关连接）。
5. `putDevice` 失败 → 回执 `ok:false`。
6. 连接级 e2e：真 socket 上发 `pair` → 设备行落下 → 明文 `pair-ack` 过线（无 `fc`）→ 连接不关。

## Alternatives considered

1. 把这段逻辑直接写在 `index.ts` 里，fixture 里再写一份
   - 最强的理由：产品侧少一个文件，读起来"就近"。
   - 为何被否：那是把**安全边界**复制两份，而且两份都不会被测到对方那一份 ——
     分叉时的症状（测试绿、真机红）恰恰是最难定位的。抽取成本是一个文件 + 三个收窄端口。
2. 失败也回一个统一的 `ok:false`（不给原因）
   - 最强的理由：接口更小，手机侧只有一个分支。
   - 为何被否：用户看到"配对失败"却不知道为什么，只能反复试 ——
     而三种原因（过期/不对/已用过）**对应的动作不同**（重新出码 / 核对 / 重新出码）。
3. 回执里带设备名、公钥等更多信息
   - 最强的理由：手机可以顺便存下自己配给谁了。
   - 为何被否：手机本来就知道自己的公钥与名字（它刚发出去）；回执只需要给"**电脑侧认定的身份**"
     （`devId`）与"**供人带外核对的值**"（SAS）。多给的信息将来还要维护兼容。

## Consequences

- 收益：配对链路的三个顺序/失败语义各有一条会红的用例；产品与测试共用一处实现，
  分叉风险从"两份代码"降为"两个端口适配"。
- 代价：多一层间接（端口化的 `putDevice`/`reply`），以及 fixture 里为它加了三处装配
  （配对核心、内存设备表、`peerOf` 优先查表）。
- **仍未做（下一步）**：
  1. **产品的出码入口**：现在 `pairing.ts` 的核心只在测试与 fixture 里被创建。
     产品需要一条"电脑侧出码"的入口（DSH 命令或设置页），把二维码载荷给操作者看一眼。
     这一步要查 `ctx.commands` 的注册面（**不能猜**它的 API）。
  2. **`pair` → 握手的完整 e2e**：现在的 e2e 到"落行 + 明文回执"为止。
     再往前走需要把手机侧客户端**按配对得到的身份参数化**（现在它是固定种子/固定 `devId`），
     然后在**同一条连接**上跑握手 —— 那才是"配对成功就能连上"的端到端证据。
