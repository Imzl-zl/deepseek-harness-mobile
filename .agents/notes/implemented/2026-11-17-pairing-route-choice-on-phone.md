# Agent Note: 配对页同时探两条路，由用户选这次走哪条

Status: implemented

## Problem

2026-11-17 删掉电脑侧「这张码给谁用」之后，码里可能同时有局域网与中转两条腿，
而手机仍旧按 `device.route_policy` **只拨一条**（失败才换）：

1. 用户拿到一张"两条都在"的码，却看不到两条各自的状态 —— 只能从最终一句
   "局域网没通，改用中转…" 里猜另一边。
2. `auto` 下局域网先拨：每条死地址 3 s，出门在外时用户要等完这一串超时才看见中转。
3. 手机侧唯一的选择入口是全局策略（设置 → 连接方式），粒度是"这台手机此后"，
   不是"这一次"。
4. 码里**没有**的那条与**拨不通**的那条，在文案上长得很像；前者要修出码，
   后者要修网络，动作完全不同。

## Decision

1. **新增 `probePairing`**（`core/pairing_flow.dart`）：对**策略允许的**每条腿**并发**拨号，
   直接复用 `beginPairing(directOnly)` / `beginPairing(relayOnly)` —— 探测就是一次
   完整的受限握手，所以"探通"与"能配对"是同一件事，不存在第二套判据。
   **不抛异常**：每条腿各自带 `attempt` 或失败原因回来。
   - 策略决定**探测范围**，不只是预选：`directOnly` 不碰中转（连换票都不发生），
     `relayOnly` 不拨局域网。被排除的那条由界面写「按设置未尝试」，不写成"不通"。
2. **配对页扫完即探**，三张卡各说一件事：
   - `PairingOfferRoutes`：这张码里写了什么（承诺）；
   - `PairingRoutePicker`：此刻哪条通了、哪条不通（原因）、哪条**这张码不含**、
     哪条**按设置没探**（四种状态，各有各的说法）；
   - 确认卡：走这条，等你确认。
3. **选择归用户**：两条都通时点另一行改选；默认按 `route_policy` 在**允许的路由**里预选。
   策略与码冲突时（只含局域网 + 只用中转）给一句"去「连接方式」改成自动"，
   而不是笼统的"没通"。
4. **一选定就收口**：提交前关掉另一条；取消 / 退出页面收掉全部（电脑上不该留候选）。
5. **错误框移到页首**：这一页从一张卡变成三张，错误留在按钮下方要滚到底才看得见。

## Alternatives considered

1. **保持自动拨号，只在失败后说原因**
   - 最强的理由：少一屏、少一次握手，而且中转那张票不会被白烧。
   - 为何被否：用户要的是"先看见两条各自通不通，再决定走哪条"；先拨一条再换，
     看到的永远是结果，不是选择。这也正是上一轮"电脑替用户押一条路"的同一种病。
2. **用 TCP / HTTP 探活代替真拨**
   - 最强的理由：便宜，不消费中转票，也不占电脑侧候选名额。
   - 为何被否：端口开不等于能配对 —— offer 过期、中转未登记、握手失败都表现为
     "通但配不上"；而且会引入两套"能不能用"的判据（探活用一套、真拨用另一套）。
3. **两条总探，策略只管预选**
   - 最强的理由：选择面最大 —— 用户的意图变了也不必回去改设置。
   - 为何被否：`directOnly` 是"别碰中转"的明确表态，而探测中转会真的换一次票
     （HTTP + 一次性票），那已经算碰了；反过来 `relayOnly` 在只含局域网的码上
     会被静默改用局域网。策略要么管住探测，要么就不配叫"只用"。
4. **串行探（先 LAN，再 relay）**
   - 最强的理由：少一次并发握手，失败面更简单。
   - 为何被否：局域网全死时用户要等完 N × 3 s 才看到中转的状态；并发把总等待
     压到 `max(3s, 10s)`。
5. **电脑侧出两张码**
   - 最强的理由：一眼就知道扫哪张。
   - 为何被否：11-17 已否 —— 同一时刻两条一次性邀请，过期、清理、面板画哪张都要两套。

## Consequences

- 收益：一次扫完看到两条的真实状态；"不含"与"不通"分开说；选择粒度到"这一次"。
- 收益：不再有"N 个 3 秒超时才知道中转行不行"的等待 —— 两条并发。
- 代价：中转那张票在探测时就被换掉；用户最后选局域网时它作废（一次性、不含秘密，
  也不占电脑侧状态）。
- 代价：每次配对多一次并发握手；两条都通时电脑侧会短暂出现两条候选连接，
  提交或取消时收掉另一条。
- 代价：配对页从"一张码卡 + 确认卡"变成三张卡，页面更长。
- 收益（顺手修掉的老漏）：中转握手失败时现在会 `close()` 那条半开连接
  （`tryRelay` 的 catch）。局域网那条一直有这一步，中转曾没有 —— 而"中转连不上"
  恰恰是最常见的失败，重试几次就会攒下多条半开 socket。
- 边界：`route_policy` 决定**探测范围与预选**；被策略排除的路由不探、不可选，
  行里写「按设置未尝试」。配对成功之后的自动拨号仍按策略过滤候选。
- 边界：改选不重新探测 —— 两条已经在探的时候开着。
- 边界：`directOnly` / `relayOnly` 下没有"本次改走另一条"的开关；要改先改设置
  （或等 `auto`）。这是刻意的：让"只用"真的只用。
