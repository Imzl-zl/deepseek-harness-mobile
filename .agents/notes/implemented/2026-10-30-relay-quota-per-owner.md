# Agent Note: 按人的流量额度（中转可观测/限额/面板 第 2 批）

Status: implemented

## Problem

中转原来只有**请求数**限流（令牌桶，按身份每秒几次），没有任何**字节**口径：
一条通道可以整天转发大文件，而中转"只转发与记账"里那半个"记账"并不存在。
运营者想在服务器上回答"这个人这个月用了多少、还能用多少"，今天一个数都拿不到。

## Decision

1. **主体是人**：`owner`；没配退回 `connector:<id>`。与限流桶同一个判据
   （`digest-auth.ts` 的 `rateKeyOf`）。同一人的两台电脑共用一个额度 —— 否则
   "多开一台电脑"就是免费加额度。
2. **只算业务通道的双向帧**（`purpose === 'paired'`），**配对候选不计量**：
   额度用满的人仍然要能重新扫码（配对是唯一的恢复路径）。
3. **计数点**：`core.onLine` 的返回从"投递列表"改成 `{ deliveries, bytes }`，
   中转在同一个同步块里记一笔、投递、必要时收口。`Buffer.byteLength` 因此每帧只算一次
   （背压判断与计量共用同一个数），热路径零分配。
4. **口径**：`period` = `month` / `day` / `none`，UTC 周期键、**惰性结算**（读时发现
   周期变了就归零）。没有为额度新增任何定时器。
5. **用满的处置**按 `enforce` 三档：`cut`（默认）把这个人名下**所有**通道以
   `4003 + rate-limited quota` 收口，之后换票/升级回 `429 + retryAfterMs`；
   `block` 只挡新建；`off` 只记账。**不新增错误码**：`rate-limited` 已在契约 §3.1
   的封闭表里，动作是退避重试，手机两侧都认。
6. **落盘可选**：默认内存态（与名册/票同一条纪律），`persist: true` 才写
   `statePath`（默认与配置同目录的 `relay.state.json`；原子替换、5 s 节流、
   关闭前冲一次）。损坏时改名 `.corrupt` 留证并从零起算 —— 计数器坏了不该让整台中转起不来。

## Alternatives considered

1. **每秒限速（把转发速率压在某个 bytes/s 以内）**
   - 最强的理由：超了不中断，只是变慢，用户体验连续。
   - 为何被否：要按住发送方 socket（`ws.pause()`），而那会**连心跳一起按住**，
     半开判定（两个周期）会被自己的限速触发；而且它是另一种需求（带宽整形），
     在额度这个总量口径下没有收益。
2. **每条通道各自一个额度**
   - 最强的理由：实现最直白，通道销毁即释放，不需要"主体"这个概念。
   - 为何被否：多开一台电脑就多领一份，与 HEAD 已定的 `owner` 合桶决定冲突
     （`2026-10-30-relay-multi-tenant-isolation.md` 的补充一节）。
3. **新错误码（如 `relay/quota-exceeded`）**
   - 最强的理由：手机能显示"额度用完了"，而不只是"重连中"。
   - 为何被否：契约 §3.1 加行要四处同批（`errors.ts` 的 `ERROR_TABLE` + `ClientAction`、
     `errors.dart`、契约表、`flow.test.ts` 的 36→37），而**手机动作不变**（退避重试）。
     显示文案是 app 侧的一小批，不与中转绑定。
4. **配额放到电脑侧**
   - 最强的理由：电脑侧知道自己的会话量与附件，判据更贴近成本来源。
   - 为何被否：电脑侧看不到**同一个人另一台电脑**的流量，也拒不了换票（票由中转发）。
5. **把计数落 SQLite / 独立计量进程**
   - 最强的理由：跨重启、可查询、可对账。
   - 为何被否：单容器 1 核 256 MB，原生模块等于给"无构建步骤"的镜像加一条构建链；
     JSON 状态文件已够本期口径。
6. **配对候选也计量**
   - 最强的理由：口径统一，"所有过中转的字节都算"。
   - 为何被否：一个人把额度用完会连"重新扫码"都做不到 —— 恢复路径被自己的限额锁死。

## Consequences

- 收益：运营者第一次能回答"谁用了多少、谁被挡住了"；面板（第 4 批）直接读同一份计数。
- 收益：热路径只多一次 Map 查询 + 一次整数加法；`Buffer.byteLength` 从每帧两次降到一次。
- 代价：默认内存态，**重启清零**（等于送一次额度）。跨重启要显式 `persist`，
  代价是多一个要挂载/备份的文件，且最多丢最后 5 秒的用量。
- 代价：额度是**单实例**口径。多实例部署时每个人在每个实例上各有一份额度 ——
  与限流同一条已知边界，契约 §12 的完整形态要求共享存储。
- 代价：允许**超出一帧**（最大 8 MiB）。帧是原子的，不能在中间切；`cut` 发生在
  这一帧转发之后。
- 代价：`owner` 改了要重启（它来自配置里的令牌条目）。运行中改归属不在本期。
- 未覆盖：面板的"每人剩余/重置"在第 4 批；本批只有 `metering` 的读取面与 429/4003。
