# Agent Note: 中转接成能跑的服务 —— 判定与 socket 分家的那一刻

Status: implemented（`relay/src/server.ts` + 3 条冒烟用例；令牌摘要表见"仍未做"）

## Problem

判定层（路由 / 登记 / 大脑 / 票 / HTTP 面）此前零依赖、33 条几十毫秒的用例，但**没有任何东西在监听**。
要让它真的能转发，必须写"碰 socket"的那一层，而这一层要把三件事定清楚：

1. **两个入口各自的凭据放在哪**：连接器是长连凭据、设备是短命票，位置不同是有理由的；
2. **升级失败怎么办**：那时还没有任何帧交换，回协议帧没有意义；
3. **同一个身份再连上来怎么办**。

## Decision

`relay/src/server.ts` 只做"碰 socket"的三件事（读 HTTP、升级并认证、把行交给 `core` 并写回投递），
判定仍然全在 `http-face.ts` / `core.ts` 里 —— **依赖边界与第 33 轮写下的那条一致**。

- **凭据位置**：连接器 `Authorization: Bearer <连接器令牌>`；设备 `?ticket=<一次性票>`。
  后者正是 `tickets.ts` 存在的理由（凭据进 URL 的代价被压缩成一张 60 秒、用过即废的随机票）。
  于是**长连凭据永远不进 URL**，而"设备令牌拿来当连接器令牌"会在升级时被拒（冒烟用例钉住）。
- **升级失败只回状态码再断开**（`401` / `404`），不进入协议层：这时两端还没交换任何帧，
  发协议帧只会让对端以为"连接建立了但内容不对"。
- **每个身份只留一条连接**：同一 `id` 再连上来会把旧的关掉。少了这条，`core` 的"在线集合"
  会与真实 socket 脱节，投递打到僵尸 socket 上 —— 症状是"消息偶尔丢失且查不出为什么"。
  断开回调里还要判一句"这条 socket 是不是当前那条"，否则**被替换的旧 socket 关闭时会把新连接
  从表里删掉**（一个很容易漏、又很难复现的坑）。
- 投递目标不在表里时不报错、只留声：`core` 已按在线集合过滤过，能走到那里只可能是并发断开。

准入门槛（可机械判定）：3 条冒烟用例 ——
① 端到端：真 HTTP 换票 → 两条真 WS 升级 → 设备发一行 → **连接器收到同一行**（原样转发），
再反过来断言设备收到连接器的那一行；
② 升级认证：没票 / 没令牌 / 凭据类型不对 / 未知路径，分别 401/404；
③ 同一身份重连：旧连接被关掉、新连接继续服务、在线集合里只有一条。

## Alternatives considered

1. 让 `core` 直接持有 socket（判定层顺带收发）
   - 最强的理由：少一层收发代码，读起来"一步到位"。
   - 为何被否：那会把 33 条零依赖判定用例变成"要起 socket"，而它们盯住的恰是最容易静默出错的部分
     （窗口裁剪、归属学习、失效规则、状态码）。第 33 轮已把这条写成依赖边界，这里只是兑现。
2. 连接器也用一次性票（两个入口统一）
   - 最强的理由：入口对称，认证路径只有一条。
   - 为何被否：**连接器是长连**（它一直挂着等事件），给它发票等于让它每隔 60 秒换一次票 ——
     多一条必须维护的续票路径，而它本来就是"带着自己的凭据上来的"。契约 §2 也是这么分的。
3. 升级失败直接 `socket.destroy()`（不写响应）
   - 最强的理由：更短，少 2 行。
   - 为何被否：客户端会看到一个"连接被重置"，无法区分"令牌不对"与"网络断了" ——
     而这两者的下一步动作完全相反（换票/重配 vs 重试）。回 401 只需两行。

## Consequences

- 收益：中转**真的能跑**了 —— `startRelay({ port, authenticate })` 起服务，
  真 HTTP + 真 WS + 真路由跑通（relay 36 条：判定 33 + 冒烟 3）。
  "配对请求经中转"与"设备经中转收发"两条路的**传输**都已在位。
- 代价：`server.ts` 是唯一 import `ws` 的文件（依赖边界收在这里）；令牌摘要表仍未实现，
  所以 `authenticate` 现在只能由装配方注入（测试里是内存表）。
- **仍未做（下一轮）**：
  1. **令牌摘要表**（§12.2 的 SQL 面）+ 设备/连接器令牌的签发与吊销 —— `authenticate` 的真实实现。
  2. **电脑侧出码时调 `/pairing/register`**（连接器侧的网络装配：出码命令 + 这次登记）。
  3. **连接器侧的 `case 'pair'` 与 `devices` 写入**（`index.ts` 的 `handleFrame`），
     以及"监听面 vs 每连接状态"那个仍未决定的岔口。
