# Agent Note: 摘要表改成可变 + 管理面凭据（中转可观测/限额/面板 第 1 批）

Status: implemented

## Problem

管理面要能"吊销立刻生效"。而摘要表在启动那一刻由 `createDigestAuthenticator` 建好
就再也不变（`relay/src/main.ts:126` 的装配、`digest-auth.ts` 的一次性循环）：
吊销只能改配置 + 重启，重启前"已吊销的连接器"照旧连得上。这不是缺一个功能，
是**已有能力（吊销）的生效时机与操作者的预期不一致** —— 他在面板上点了吊销，
看到 200，而那条连接还在转发。

同时有一处并发口子：控制面认证发生在 `http.on('upgrade')` 的同步段，而真正的接受
在 `wss.handleUpgrade` 的**异步回调**里。两者之间吊销执行完，连接照样建立 ——
与"停用一台在线设备却不收连接"（`device-admin` 的 `disconnect` 那条）同一类错误。

## Decision

1. **摘要表变成可变**：新模块 `relay/src/token-table.ts` 持 `id → 条目` 与
   `hash → 身份` 两张 Map；`revoke(id)` 先摘索引再记 `revokedAt`（软吊销，条目留着），
   `restore(id)` 放回索引。`digest-auth.ts` 的 `createDigestAuthenticator` 改成它的
   薄包装 —— 校验规则只有一份，旧调用方（`main.ts` 自检、测试）形状不变。
2. **同一 `id` 出现两次拒绝建表**：吊销/恢复按 `id` 定位，重复条目会让"吊销的是哪一条"
   变成猜。配置写入方（`appendTokenToConfig`）本来就按 `(kind,id)` 去重，这条只接住手写的重复。
3. **管理面凭据独立一张摘要**：配置新增 `admin: { id, hash }`，不进 `tokens` 表 ——
   连接器令牌的权力是"替一台电脑报名册、拨数据面"，不该交给浏览器。
   `--issue-admin <id>` 签发，只把摘要写进配置、明文打印一次（与连接器令牌同规格）。
4. **没配 `admin` 就没有这张面**：`/admin*` 一律 404，与未知路径同形。这是"绝不裸奔"的
   结构性保证 —— 不依赖端口绑在哪、也不依赖反代配置对不对。
5. **接受前重验**：控制面与数据面的 `handleUpgrade` 回调里各再调一次
   `authenticate(原令牌)`，认不出或换了 id 就 `close(4000, 'credential revoked')`。

## Alternatives considered

1. **保留不可变表，吊销 = 改配置 + 重启**
   - 最强的理由：零新代码、零并发面；配置本来就是"这台机器的状态"。
   - 为何被否：重启会掐掉**所有**在线连接（手机、电脑各自退避重连），而吊销一台
     不该波及别人；何况面板点一下就要重启，操作者不会用，最后等于没做。
2. **复用连接器令牌做管理凭据（单独一条 `tokens` 条目）**
   - 最强的理由：少一个概念、少一套签发路径。
   - 为何被否：`digest-auth.ts` 硬拒非 connector 条目正是"表里只有连接器"这条分层；
     要复用得在那边开口子，而且把"能替电脑报名册"的长期凭据放进浏览器，权限过大。
3. **管理面单独端口 + 只绑 127.0.0.1**
   - 最强的理由：网络位置就是一层保护，漏配令牌也不至于全裸。
   - 为何被否：部署在公网服务器上、从操作者自己的电脑访问，绑回环意味着必须
     SSH 隧道或反代；而"漏配令牌"这个风险已经由"没配就没这张面"从结构上关掉。
4. **把重验放进 `acceptControl` 内部（拿 `caller` 再判一次 id）**
   - 最强的理由：调用点少一处，忘不了。
   - 为何被否：`acceptControl` 拿不到令牌原文，只能判"id 还在不在表里"，
     而"同一个 id 换了摘要"（重新签发）那种情况它会放过。原文重算一次 sha256 很便宜。

## Consequences

- 收益：吊销/恢复在**下一个请求**就生效，不重启、不波及其他连接。
- 收益：管理面第一次有了独立凭据，"没配就不存在"是可测的结构而非约定。
- 收益：控制面/数据面不再接受"认证之后、接受之前被吊销"的连接。
- 代价：摘要表从"启动即定"变成"运行时会变"，`authenticate` 不再是纯函数式的一次性装配 ——
  任何缓存"认证结果"的新代码都会引入陈旧判断，所以本批没有引入任何缓存。
- 代价：`admin` 是配置里第二个凭据面，运维多一个要备份/轮换的东西；
  轮换目前要重启（`setAdminInConfig` 只写文件，内存表在装配时读一次）。
- 代价：手写的重复 `id` 从"后一条覆盖前一条"变成"拒绝启动"。配置写入方不会产生这种形状，
  但旧的、手改过的配置会因此起不来 —— 错误信息里写明原因与修法。

- `node --test` → **106 / 106**（批前 96，新增 10：`tests/token-table.test.ts` 6 条 +

  - `revoke` 不摘认证索引 → **恰 1 红**（`token-table` 的"吊销立刻生效"）。
