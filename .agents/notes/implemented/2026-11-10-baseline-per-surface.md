# Agent Note: 一个面只有一条基线 —— 原型退到"会话页与输入栏"

Status: implemented

## Problem

`AGENTS.md` 与 `tools.md` 都把 `mock/proto/` 写成"**交互基线原型**（唯一可运行的完整形态）"，
并要求"改基线要同步改落地端，不允许两边各自漂移"。这条规则曾经是对的：项目早期只有一页对话，
原型就是它的可执行规格。

现在的事实：

| | 规模 | 最近一次改动 |
|---|---|---|
| `mock/proto/` | `index.html` 694 行（含 drawer / side / tasks / settings 四块） | `dfe114c`（11-07，之后的近 60 次提交里只碰过 1 个文件） |
| `app/lib/ui/` | 26,684 行 / 8 个页面（用量、插件、轨迹、文件、设置、配对、扫码、会话） | 每次提交都在动 |

近 60 次提交的目录分布：`app` 197 个文件、`connector` 57、`docs` 53、`mock` **1**。

于是这条规则的成本与收益倒过来了：**它要求同步的那个方向已经没人走**（产品不再从原型改），
而它给出的方向（新页面进原型）会让同一件事被写两遍。任何按文档接手的人第一件事都会花在这条
死路上，然后为了"两边不漂移"往原型里塞不该有的东西 —— 那不是守住了不变量，那是把一条面的
真值拆成两处。

还有一个更细的错位：`verify-authz.mjs` 的 18 项授权矩阵是 AGENTS.md 点名的必过门禁，而它打的是
**原型页面**（`PAGE_URL` 默认 `../index.html`）。产品侧等价约束在
`app/test/takeover_test.dart` / `chat_takeover_wiring_test.dart` 里，覆盖是在的 —— 但"门禁的对象"
和"产品的对象"不是同一个东西，而文档里没有一句说清这件事。

## Decision

把"基线"按**面**划分，一个面只有一条基线；原型退到它实际承担的那部分。

| 面 | 基线 | 守卫 |
|---|---|---|
| 会话页、输入栏、抽屉、右侧面板、后台任务页的手势与布局 | `mock/proto/` | `verify-proto` / `verify-authz` / `verify-picker` / `verify-tasks` / `verify-drawer` |
| 用量、插件、轨迹、文件预览、设置、配对、扫码 | `docs/` + `app/test/` | `flutter test` |

三条推论（写进 `docs/architecture.md` 的「基线划分」）：

1. **原型里有的面**：改基线要同步改落地端（`verify-*.mjs` 的断言就是这份基线）。
2. **原型里没有的面**：基线是 `docs/`。**不要为了"同步"塞进原型。**
3. **落地端有意偏离原型时**：偏离写进 `docs/`（"有意偏离 + 原因"），不靠改原型来"对齐"。

同批改的三处文字（只改文档，不动任何代码行为）：

- `AGENTS.md` 常驻军规第 4 条、§3 的 `mock/proto/` 条目（去掉"唯一可运行的完整形态"这句已不成立的话）。
- `tools.md` 的「主链路」：改成"改 `app/`（产品）；改 `mock/proto/` 只在会话页与输入栏这条面上"。
- `verify-authz.mjs` 文件头补一句"钉的是交互基线的授权口径，产品侧等价性在哪"。

## Alternatives considered

1. **把原型补齐到和产品一样**（继续执行原规则）
   - 最强的理由：规则不变，不用解释。
   - 为何被否：等于把 26,684 行的 UI 用纯 DOM 再写一遍，且换不到任何信息 ——
     用户在原型里能看的东西，真机上已经能看，还更真。
2. **直接删掉 `mock/proto/`**
   - 最强的理由：一条不存在的基线就不会漂。
   - 为何被否：五个 `verify-*.mjs` 的断言对象会一起没掉，而它们覆盖的是**手势与授权口径**
     （`verify-authz` 18 项、`verify-picker` 列表列固定、`verify-drawer` 25 项），
     这些在 Flutter 侧的 widget 测试里都没等价物（合成手势 `adb` 走不通，`tools.md` 里记过）。
     退到"只覆盖会话页"比删掉收益高得多。
3. **把授权矩阵那 18 项搬到 `integration_test/` 打真机**
   - 最强的理由：门禁对象就变成产品了。
   - 为何被否：它需要真机 + 真中转 + 真电脑侧，成本从"十几秒"变成"一次真机回合"，
     而 `takeover_test.dart` 已经在 controller 层钉住了同样的不变量
     （`allowOnce` 回执是 `allowed-once`、"一次就是一次"、未回答时提交无操作）。
     缺的只是"UI 到 controller"那一跳，`chat_takeover_wiring_test.dart` 覆盖了。
     真要补，该在 Flutter 侧补，不是把浏览器矩阵搬进真机。

## Consequences

- 收益：接手者不再被派去走一条没人走的路；"两边不漂移"这句话被拆成三条可执行的判据，
  而不是一条无法满足的通则。
- 收益：`verify-authz` 的**作用域**从"隐含在默认参数里"变成写在文件头的事实 ——
  下次有人问"授权矩阵到底验的是谁"，答案在代码里。
- 代价：没有守卫能检查"这个新页面该不该进原型"。它靠 `docs/architecture.md` 那张表判断，
  属于**语义判断**，进不了机械门禁（与「不新增宿主没有的边界」同一类）。
  代价是它可能被忘掉，所以那张表放在 `docs/architecture.md` 的第一节，而不是藏在 notes 里。
- 代价：原型从此进入"维护但不再扩建"的状态。它的寿命由会话页那几个 `verify-*.mjs` 决定 ——
  如果哪天 Flutter 侧的 widget 测试能覆盖同样的手势判据，这几条就可以一起退场。
