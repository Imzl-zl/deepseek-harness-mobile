# Agent Note: 思考行的标题钉在视口顶部（Flutter 里的 position: sticky）

Status: implemented

## Problem

展开后的「思考过程」可以很长，而 DSH 的正文是**不封顶**的。RC5 靠 CSS
`position: sticky`（`packages/client/ui-chat/src/client/chat/ReasoningRow.module.css:15-21`）
把标题行（图标 + 「思考」+ chevron）钉在视口顶部 —— 正文滚到哪，"想折叠"都够得着。

手机上没有这个：正文跟着对话滚，标题跟着滚出屏幕，想折叠得先滚回那一行
（用户 2026-11-04 原话："点开不是会直接超过屏幕，你想点击折叠就要滚动好久"）。

第一版把正文**封顶半屏、自己滚**。那只是"块不超过半屏"，标题照样会随对话滚走 ——
用户当场退回："思考也还是不会置顶"。

## Decision

用一个**粘顶宿主**（`app/lib/ui/sticky_note.dart` 的 `StickyNoteHost`）包住聊天列表：
展开的折叠行把自己的标题/正文的 `GlobalKey` 登记进去；滚动时若"标题已滚到视口顶之上、
正文还在视口里"，就在列表顶部**画一份同样的标题**（点它即折叠）。

准入门槛：

1. **量的时机在帧之后**：滚动通知是在 `setPixels` 里发的，那一刻子节点 paint offset
   还是上一帧的 —— 当场 `localToGlobal` 读到"没滚"的坐标，标题永远不出现
   （第一版就栽在这，`sticky_note_test.dart` 三条用例钉住）。
2. **标题只有一份定义**：钉住的那份由 `_CollapsibleNote._buildHeader()` 产出，
   与行里那份是同一个 widget —— 两处各写一份必然漂。
3. **只有展开的思考正文参与**（`markdownBody`）：系统提示词 / 命令的正文是 141px
   滚动区，永远出不了屏幕，钉它没有意义。
4. **收起即注销**：`dispose` 与 `_toggle` 都要 detach，否则会钉住一个已经收起的行。

## Alternatives considered

1. 把聊天流改成 sliver 分组（`SliverPersistentHeader`）
   - 最强的理由：这是 Flutter 里与 `position: sticky` 等价的原生机制，滚动/布局都由
     框架管，不需要每帧量矩形。
   - 为何被否：粘顶要求"标题"与"正文"是**两个相邻的 sliver**，而正文现在长在消息条目
     内部（`AssistantTurn` 里）；要拆就得让消息渲染产出多个 sliver，等于重写对话流。
   代价远大于收益，且改动面覆盖整条渲染链。
2. 正文封顶 + 内部滚动（第一版）
   - 最强的理由：不碰列表结构，二十行代码，与"系统提示词 141px"同一档既有取舍。
   - 为何被否：它不是"置顶" —— 对话一滚，整块（标题 + 封顶正文）照样滚走；
     而且给聊天流引入嵌套滚动，手机上容易变成"滚不动"的陷阱。用户实测后明确退回。
3. 展开时在屏幕角落浮一个"折叠"按钮
   - 最强的理由：实现最省，且一定能点到。
   - 为何被否：DSH 没有这个东西，它是我们发明的控件；而用户要的是"标题在顶上"，
     不是一个额外的按钮。

## Consequences

- 收益：与 RC5 同一种手感（标题一直在视野里），而且**不碰消息渲染**；
  钉住的那份与行里那份是同一个 widget，不会漂。
- 代价：展开期间每次滚动都要在**帧后**量几个矩形（几个 `RenderBox.localToGlobal`），
  只有"钉谁变了"才重建 —— 但它是"每帧一次测量"，不是框架级的 sliver 方案。
- 边界：同一时刻只钉**一个**（多个折叠行同时展开时取最后登记的那个），
  与 DOM 里后一个 sticky 把前一个顶出去同向；不做多段堆叠。
