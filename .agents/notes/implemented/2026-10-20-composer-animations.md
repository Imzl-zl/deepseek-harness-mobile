feat(app): 输入栏两处动画 —— 发送键换形态、附件芯片入场

用户：「它的动画也挺丝滑…当然我们虽然技术栈不一样可以参考优秀的设计是吧」
（rikkahub 那套）。我们此前**几乎没有动画**：发送⇄停止⇄转圈是硬切，
选了图芯片直接蹦出来。

## 1. 发送键的三个形态之间淡入 + 缩放

照 rikkahub 的 `AnimatedVisibility(enter = fadeIn() + scaleIn(),
exit = fadeOut() + scaleOut())`（`ui/components/ai/ChatInput.kt:391-402`）。

**为什么值得动画**：这三个形态是**同一个按键的不同含义**（发送 / 停止 /
转圈），硬切读成"按钮被换掉了"，尤其"运行中 → 停止"那一下底色还从蓝变橙；
淡入缩放读成"同一个键换了含义"。

**只动图标、不动底色**：`Material` 的底色承载 `InkWell` 的水波（水波画在
Material 上、在 child 底下），把它换成 `AnimatedContainer` 会把水波盖住。
取舍：水波留着，底色瞬时切。

## 2. 附件芯片入场

用 `TweenAnimationBuilder`（首次构建跑一遍，不必为一次性的入场维持
7 个 `AnimationController`），160ms / easeOutCubic —— 与发送键那次**同一个
节奏**，两处一致才不显得杂。

## 验证

`composer_layout_test.dart` 新增一条**真的查中间态**的判据：
只 `pump()` 一帧时，芯片的 `Opacity < 1`；走完 160ms 后必须 `== 1`。
**为什么这样写**：只断言"有个 Opacity"的话，把它换成 `opacity: 1` 也照样绿 ——
那就变成"测了但没测到"。**一处变异验证**：把入场起点从 0 改成 1（等于没动画）
→ 1 条红。

- `flutter test 867` 全绿；构建通过。
- **真机未验**：两处动画都要"能发消息"才看得到（未配对时输入栏置灰）。
  判据留给配对后：发一条 → 运行中点停止键，形态是**渐变**不是闪切；
  选一张图 → 芯片**淡入**。
