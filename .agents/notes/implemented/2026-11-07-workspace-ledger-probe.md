# Agent Note: 账本落后时补问一次（新建会话不再先落「未分组」）

Status: implemented

## Problem

真机（2026-11-07）：在**电脑上**新建一个会话，手机抽屉里它先出现在「未分组」，
过一会儿才归到工作区。

根因不是分组算法：`bucketSessionsByWorkspace` 是纯函数，只认 `workspace.list` 的
`sessionIds`。问题在**触发面**：`host_state.dart` 的登记表里，账本
（`workspace.list`）没有 `notification` 触发点 —— 当初的口径是"工作区没有宿主事件，
不给它编一个触发源"。而"别人新建了一个会话"到我们这边只是**会话清单多一行**，
清单走了 `notification`、账本没走，于是两半不同步：新行谁也不认领 ⇒ 未分组。
它要等下一次回前台 / 重连 / 切会话才归位。

## Decision

会话清单落地后，如果**有会话不在任何工作区里**，就补问一次账本
（`AppModel._probeWorkspaceLedger`）。同一个 sid 只问一次：问过还没归组，
说明宿主此刻确实没把它放进工作区 —— 再问就是替宿主发明重试。

## Alternatives considered

1. **给账本加 `notification` 触发点**（登记表里那一列补上）
   - 最强的理由：一行改动，语义上是"通知到了就把九项都对一遍"。
   - 为何被否：通知到达时账本**未必**已经更新（宿主的两次写不同步），
     照通知就重取等于每次通知都多一枪，而且不解决"这次没更新"的情形；
     而按"有未归组的会话"触发，只在**真的缺**的时候问，问一次就够。
2. **按 `cwd` 猜一个分组**
   - 为何被否：既有规则写死了不猜（`workspace.dart` 的注释：`cwd` 与工作区不是一对一，
     猜错比不分组更难查）。这里同样不猜，只是去问宿主。
3. **抽屉打开时对一遍账本**
   - 为何被否：抽屉打开是 UI 事件，频道层拿不到；而且"未归组"这件事在清单到达时就知道，
     不必等到用户拉开抽屉。

## Consequences

- 新会话最多多一次 `workspace.list`（一个 sid 一次），之后正常走原有触发面。
- 宿主确实没归组时，界面**如实**停在「未分组」—— 不是我们造一个分组。
- 判据：`app/test/workspace_ledger_probe_test.dart`（两条：会补问、只问一次），
  并做过变异校验（去掉那一枪恰好两条红）。
