# Agent Note: 文件与类的尺寸预算做成棘轮门禁 —— 只降不升

Status: implemented

## Problem

本仓别的结构性约束都有机械守卫：分层（`verify-platform-boundary.mjs` 9 条）、协议知识只在
`wire/`（`verify-rpc-single-caller.mjs`，零例外）、图标只有一个来源、工具脚本不许写盘符。
**唯独"这一坨代码该多大"没有**，于是：

| | 规模 |
|---|---|
| `data/app_model.dart` | 5209 行 / `AppModel` 178 个方法 / 235 个可变字段 |
| `ui/chat_page.dart` | 5278 行 / `ChatPageState` 65 个方法 / `_mainScaffold` 单方法 414 行 |

收窄提案（`proposed/2026-10-27-ui-state-design.md` 的三簇、`implemented/2026-11-06-*` 的
`HostScope` 路线）是真的在推进，`EndpointBook` / `HostCatalogs` / `UiStateStore` 都是它的产物。
但那是一条**倡议**：拆完这一轮，下一轮谁都可以再往 `AppModel` 里加十个方法，而没有任何东西
会提醒他"这里已经 178 个方法了"。**倡议的敌人不是反对，是遗忘。**

不做重构，只缺一条判据：**明天不能比今天更大，除非有人明确付账。**

## Decision

新增 `app/tools/verify-size.mjs`，4 条规则，全部在 `app/lib` 上：

1. **`file-lines`** —— 表内 15 个文件各自有行数上限；表外的文件 ≤ `DEFAULT_FILE_LINES`（800）。
2. **`class-methods`** —— 表内 4 个类有方法数上限；表外的类 ≤ `DEFAULT_CLASS_METHODS`（30）。
3. **`budget-applies`** —— 表里每一项都必须扫到真文件 / 真类。扫到 0 个就红：一条永不求值的
   预算就是一条永不作废的假绿（`verify-platform-boundary.mjs` 在 `app/packages` 与
   `platform/registry.dart` 上两次栽在这一条，见 `implemented/2026-11-09-boundary-gate-must-scan-real-shapes.md`）。
4. **`budget-not-stale`** —— 表里的数字必须与实测对上。瘦下来却留着旧数字 = 红。

准入的机械判据（三条都实测过）：

1. **给 `AppModel` 加一个方法 → 红，且只有 `class-methods` + `budget-not-stale` 两条**。
2. **给 `plugins_page.dart` 加 60 行 → 红**（`file-lines`，922 > 900）；**删 60 行 → 也红**
   （`budget-not-stale`，要求把上限收紧到 5250 那一格）。
3. **把表里某个路径抄错一个字母 → 红**（`budget-applies`），且同一条规则的自检样本也要能红。

## 为什么不锁"函数长度"

第一版想锁单函数行数，量出来 `_isStateOnlyEvent` 是 **285 行**。实际它是一行：

```dart
static bool _isStateOnlyEvent(String type) => type == 'goal/change';
```

正则 + 括号深度被注释与字符串里的 `{}` 骗了（`chat_item.dart` 的注释占 50%），一路把下一个
方法的收尾 `}` 也算了进去。**一个会撒谎的门禁比没有门禁更糟**：它给出的数字没人敢信，
于是所有人都绕过它，而"绕过"会连它本来对的那部分一起作废。

所以只数两样**确定可数**的东西：文件行数（数 `\n`，与 `wc -l` 同口径）与"2 空格缩进的成员声明"。
它们不是复杂度，是**不会骗人的代理指标**，而代理指标的全部价值就在于可信。

顺带记一笔方法论上的教训：这条 finding 我在评审里写错过一次（说 `_isStateOnlyEvent` 是 285 行的
if 链、建议改成表）。**测量脚本输出的数字必须先被质疑，再被引用**。

## 方法数余量 = 0，行数余量 = 50（这条区别是刻意的）

第一版两者都取整（方法取 5、行取 50），自检 16 条全绿。变异校验给 `AppModel` 加一个方法时
**没红** —— 因为 178 → 179 还在取整后的 180 以下。**那 2 个空档就是暗门**：一个暗门足够放下
一次真实的功能改动，而门禁的价值全在"一次都不能悄悄过"。

改成：**方法数精确等于实测值**（只在有人加/删成员时才变，那正是要拦的结构性信号）；
**行数取整到 50**（行数会因改注释、格式化、字符串换行而变，精确值会把一次错字修复变成一次
表格改动）。两个方向都红：长了要削或把数字提上去（提是一次可见的 diff），瘦了要把数字压下来。

## Alternatives considered

1. **直接锁 `dart analyze` 的复杂度 lint**
   - 最强的理由：不写新脚本，走官方工具链。
   - 为何被否：Dart 官方 lint **不提供**函数长度/类成员数/文件行数这三类规则（`flutter_lints`
     里没有，`dart analyze` 也不是可扩展的 lint 框架）。全局军规说"尺寸限制属于 linter 配置"，
     但这条在本项目里落不到 Dart 的 linter 上 —— 所以按本仓既有手法（`node` 脚本当门禁）落地。
2. **只出报告、不设退出码**（每轮打印 top 10）
   - 最强的理由：零摩擦，不会把一次 bugfix 变成一次重构。
   - 为何被否：本仓已经证明过"看得见但不会失败"的东西没人看（`connectionDiagnosis` 那条：
     只给测试看的诊断面，在真机上等于没有诊断面）。报告要能失败才有约束力。
3. **一次到位把 `AppModel` 拆完，不加门禁**
   - 最强的理由：直接消灭问题。
   - 为何被否：那是 5000 行、39% 注释、跨 20 多个测试文件的改动面，与"保持稳定"直接冲突。
     门禁是**先止血**：它不承诺拆分，只保证"不再长"。拆分按
     `proposed/2026-10-27-ui-state-design.md` 的分簇继续走。
4. **用 `--split-per-abi` 那批一起做**（APK 体积）
   - 最强的理由：都是"交付面"的优化，一起做省一次门禁。
   - 为何被否：APK 拆分要改 `release.yml` 的产物名与更新流程的落点，属于另一个决定面
     （下载入口会不会变成"选哪个 ABI"），不该和"代码尺寸"混在一批。**它仍在待办里。**

## Consequences

- 收益：`AppModel` / `ChatPageState` 的增长从"无声"变成"提交时红"。这是所有后续收窄的**机械抓手** ——
  没有它，`proposed/` 里那三簇拆完之后还会长回去。
- 代价：表内 15 个文件是**承认超线**的清单。它们不会因为上了表就变好；表的作用是让"再长"
  必须是一次明确的、在 diff 里看得见的动作（改数字那一行）。
- 代价：`DEFAULT_FILE_LINES=800` / `DEFAULT_CLASS_METHODS=30` 是**唯二拍出来的数**（取今天
  `app/lib` 的分布：>800 行 15 个文件、>30 方法 4 个类）。它们只决定"要不要上表"，不决定
  "能不能长" —— 上表之后照样是棘轮。
- 已知盲区：**方法计数基于文本形态**。签名折行成 `Future<Map<String, Object?>>\n  foo(` 这种
  写法会漏计 —— 今天 `app/lib` 里没有这种写法（折行一律发生在 `(` 之后）。真要精确到 AST，
  得接 `package:analyzer`，那时这条限制才消失。写在这里，别当成"已经不会漏"。
- 已知盲区：**"注释不算成员"这条性质不靠专门判注释，靠 `METHOD_DECL` 的形态**（2 空格后
  直接要求类型记号，`//` 接不上）。它依赖的是**判据**，不是文本识别；哪天有人放松 `METHOD_DECL`，
  两条自检样本（两空格行注释 / 文档注释）会先红。第一版曾写过一个 `COMMENT_LINE` 前置判断，
  自检证明它对结果没有任何影响 —— 按「不留不可达防御代码」删了。
- 接线：`ci.yml` 的 `protocol` job（不需要 Flutter 工程）；`AGENTS.md` §0/§5 与 `tools.md`
  的命令清单同批更新；`docs/architecture.md` 的「结构性约束与守卫」表加了这一行。
