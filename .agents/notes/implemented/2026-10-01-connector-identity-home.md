# Agent Note: 电脑侧身份种子落凭据 seam、配对标识进设备记录 —— 两处都不能靠"再算一次"

Status: implemented

## Problem

§4.1 说设备身份是**一个 32 字节主种子**（两把长期密钥都由它派生），§12.1 说电脑侧在配对时生成它，
§8.1 的设备记录里却只有公钥。而 §4.1 的 HKDF 还要一个 `info|pairingId`
（§12.1：配对标识 = 配对码的 HKDF 输出）。于是驱动器要构造出来，缺两样东西：

1. 主种子在电脑侧**存哪**，谁也没有写；
2. `pairingId` 在电脑侧**没有落点** —— 而配对码本身一次性、5 分钟失效，不存就再也算不出来。

两样都属于"算不出来就永远握不上手，而症状看起来像验签失败"的那类。

## Decision

- 主种子进 `ctx.credentials` 的**具名记录面**：`credentialKey('dsh-mobile-connector','identity')`，
  载荷是 `grant` 记录里的 `{ masterSeed }`。没有记录就生成一次并落盘；**已有记录但读不懂则抛错，绝不覆盖**。
- `pairingId` 进设备记录（§8.1），业务 schema 升到 **v2**；迁移只动 `meta`。

准入门槛（可机械判定）：

1. 身份记录只被本插件的作用域寻址；读不懂的记录（类型不对、种子不是 32 字节 hex）一律抛错，写次数为 0。
2. 首启并发时以**记录里那条**为准（`modifyRecord` 返回什么就用什么），不是自己生成的那条 ——
   否则两端身份会悄悄分叉。
3. 设备记录缺 `pairingId` 或为空串即 schema 不合法（不可能"配了对但握不了手"）。
4. v1 → v2 只改版本号，其余字段原样带过；跳代（v0 → v2）必须报"缺少迁移"。

## Alternatives considered

1. 主种子进设置（settings）或配置文件
   - 最强的理由：可读可导出，用户换机时能手工搬。
   - 为何被否：密钥不能有读面。设置面天然带读（`describe` 会返回 `value`），
     而凭据 seam 的记录面按定义"载荷由拥有者解释"，读权只在本插件里。
2. 主种子进 store（`ctx.storage` domain KV）
   - 最强的理由：与设备表、别名表同一套落盘，迁移机制也现成。
   - 为何被否：那是**明文**存储。§8.1 的存储边界表把"设备身份种子"划在系统安全存储一侧，
     电脑侧的对应物是凭据 seam，不是 domain KV。
3. `pairingId` 放 `meta`（全局一条）
   - 最强的理由：不用动设备记录的 schema，迁移更省事。
   - 为何被否：一台电脑可以配 8 台设备（`deviceLimit`），每台的配对码不同；
     全局一条会让"第二台设备配对"覆盖掉第一台 —— 而症状是第一台突然连不上。
4. 不加字段，用 `connectorId` 顶替 `pairingId`
   - 最强的理由：零迁移、零新字段，`connectorId` 反正已经进 transcript。
   - 为何被否：那是把"配对标识"偷换成"电脑标识"。它会让所有设备共享同一份 HKDF 上下文，
     等于删掉了配对这一层的域分隔 —— 而删掉它不会让任何测试变红。
5. 迁移时为老设备补一个 `pairingId`
   - 最强的理由：schema 变更看起来更"完整"。
   - 为何被否：**补不出来**。配对标识只能是当初那个配对码的 HKDF 输出，凭空造一个等于让该设备永远验签失败；
     而设备记录至今没有任何写入方（配对流程还没落地），所以根本不存在需要补的历史行。

## Consequences

- 收益：驱动器要的两样东西都有确定落点；身份首次挂载即就绪，早于配对（二维码里要带电脑公钥，
  所以身份必须先存在）——这与 §12.1 的次序一致。
- 代价：业务 schema 从 v1 升到 v2（`meta.schema` 的逐代迁移表里多一条）；
  新增一个挂载步骤 `load-identity`，`credentials` 同时从"可选能力"升为**必需服务**（进 `inject`）：
  身份是握手的构造前提，把它当可选项等于允许插件挂载成一个永远握不了手的空壳。
  已核实它由 `@deepseek-ai/dsh-base` 提供（`packages/bundle/base/cordis.patch.yml:117-118` 注册
  `@deepseek-ai/dsh-credentials-local`），而 base 本来就是任何可跑 profile 的前提。
