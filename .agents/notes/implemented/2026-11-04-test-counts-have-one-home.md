# 测试项数只有一个家，而且它必须会自己变旧

- 日期：2026-11-04
- 触发：README / `memory.md` / `tools.md` 三处抄同一批项数，已经漂过三次
- 状态：implemented

## 背景

同一个数字在三个地方各写一份。main（#2/#3 合入后）实测是 relay **174**、connector **845**、
app **1739**；而 README 还写着 161 / 831 / 1659，`memory.md` 写着 173 / 845 / 1738。

更糟的是**项数本身是环境相关的**：连接器那条跨语言用例在没有 Dart SDK 的机器上跳过
（844 绿 + 1 跳过），装了 Flutter 的 CI 上是 845 全绿 —— 也就是说"把数字抄对"
这件事**永远做不到同步正确**，只能做到"某个时间点某个环境是对的"。

`AGENTS.md` §5 其实早就写了正确做法：「项数见 `tools.md` —— 不在此处复述，免得两处漂移」，
但 README 与 `memory.md` 恰恰复述了。

## 决定

1. **项数只写在 `tools.md` 一处**，并带上"最近一次实测的日期/环境"。
2. `README.md` 与 `memory.md` 只保留**稳定不变量**：`454 / 26 / 49`（跨端协议断言数，
   两侧实现必须相等，这是真正的门禁），以及平台边界那一项（它随文件数变，但变的时候
   一定是同一次改动里由脚本自己报出来的）。
3. `memory.md` 的门禁表不再写每个套件的项数，统一指向 `tools.md`。

## 被否掉的

- **把三处数字统一刷成最新值**：下一个改动进来立刻又不一致；这是把定期订正变成了工作量。
- **删掉所有数字、只留"全绿"**：`454 / 26 / 49` 是**跨端对等**判据（TS 与 Dart 各实现一遍，
  断言数必须相等），删了就把一条真门禁降级成"跑得过就行"。
- **让 CI 把项数写回文档**：多一条会改仓库的流水线，而且本仓的 CI 只读。

## 代价

- README 的"门禁表"信息量下降：读者要跳到 `tools.md` 才知道规模。可接受 —— 它本来就该是
  命令清单，不是规模仪表盘。
- `tools.md` 的那几个数字仍然会旧。区别是：**只有一处会旧**，而且旁边有日期。
- 现在 #4（IME）/ #5（添加电脑）/ #6（平台边界）还是 draft；它们合入后 app 会从 1739
  变成 1743、平台边界从 728/25 变成 736/31。到时只改 `tools.md` 一处，README/memory
  不再跟着改。

## 验证

- main（#2/#3 合入后）实测：
  - protocol `454 / 26 / 49`；
  - `relay` **174 / 174**；
  - `connector` **845 / 845**；
  - `app` `flutter test` **1739 / 1739**；
  - `verify-platform-boundary` **728 项**（25 条自检 + 167 个 Dart 文件）。
- `tools.md` 只在这一个文件写 174 / 845 / 1739；README 与 `memory.md` 不再复述每套件项数。
