# 测试项数只有一个家，而且它必须会自己变旧

- 日期：2026-11-04
- 触发：README / `memory.md` / `tools.md` 三处抄同一批项数，已经漂过三次
- 状态：implemented

## 背景

同一个数字在三个地方各写一份，实测的漂移：

| 来源 | 连接器 | 手机端 | 中转 |
|---|---|---|---|
| `README.md`（门禁表） | 831 | 1659 | 161 |
| `memory.md`（门禁表） | 831 | 1649 | 161 |
| `tools.md`（正文） | 794 | 1619 | 152 |

四个来源四个数。更糟的是**项数本身是环境相关的**：连接器那条跨语言用例在没有 Dart SDK 的
机器上跳过（本机实测 844 绿 + 1 跳过），装了 Flutter 的 CI 上是 845 全绿 —— 也就是说
"把数字抄对"这件事**永远做不到同步正确**，只能做到"某个时间点某个环境是对的"。

`AGENTS.md` §5 其实早就写了正确做法：「项数见 `tools.md` —— 不在此处复述，免得两处漂移」，
但 README 与 `memory.md` 恰恰复述了。

## 决定

1. **项数只写在 `tools.md` 一处**，并带上"最近一次实测的日期"。
2. `README.md` 与 `memory.md` 只保留**稳定不变量**：`454 / 26 / 49`（跨端协议断言数，
   两侧实现必须相等，这是真正的门禁），以及平台边界那一项（它随文件数变，但变的时候
   一定是同一次改动里由脚本自己报出来的）。
3. `memory.md` 里复验不了的那一格**如实标注**（"本机没有 Flutter SDK，未复验"），
   而不是抄一个看起来新的数字。

## 被否掉的

- **把三处数字统一刷成最新值**：下一个改动进来立刻又不一致；这是把定期订正变成了工作量。
- **删掉所有数字、只留"全绿"**：`454 / 26 / 49` 是**跨端对等**判据（TS 与 Dart 各实现一遍，
  断言数必须相等），删了就把一条真门禁降级成"跑得过就行"。
- **让 CI 把项数写回文档**：多一条会改仓库的流水线，而且本仓的 CI 只读。

## 代价

- README 的"门禁表"信息量下降：读者要跳到 `tools.md` 才知道规模。可接受 —— 它本来就该是
  命令清单，不是规模仪表盘。
- `tools.md` 的那几个数字仍然会旧。区别是：**只有一处会旧**，而且旁边有日期。

## 验证

  `memory.md` / `tools.md` / `app-platform-boundaries.md` §6 三处写的数字一致。
- `relay`: 166 条、`connector`: 845 条（844 + 1 跳过）—— 本次实测，写进 `tools.md` 与
  `memory.md` 并注明日期/环境。
- 手机端 1684 项**未复验**（本机 `where flutter` / `where dart` 均为空，`D:\soft\flutter` 不存在），
  文档里如实标注日期而不是装作刚跑过。
