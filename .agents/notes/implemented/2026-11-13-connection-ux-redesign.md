# Agent Note: 连接面板从 11 行收到 6 行，连接方式收成一张二级页

Status: implemented

## Problem

点顶栏绿点弹出的连接面板（`app/lib/ui/connection_actions_sheet.dart:101-271`）最多有 11 行：
当前连接块、切换电脑、切回上一台、换个连接方式、手动填写地址、重新连接、重试连接、
添加电脑、重新配对、**打开侧面板**、断开连接、取消。

四个具体问题：

1. **同义动作并排**：「重新连接」「重试连接」「重新配对」三行都是 refresh 图标，后果完全不同，
   用户得读副标题才知道点哪个。
2. **与连接无关的入口混进来**：「打开侧面板」打开的是右侧内容抽屉，而这个抽屉本来就能从
   右缘跟手拖出（`app/lib/ui/chat_page.dart:895-907` 用原生 `endDrawer`）。用户原话：
   "打开侧边栏，这有必要吗我侧滑都打开了，用得着点开在这里打开吗？"
3. **小字注释泛滥**：6 条副标题里只有两条是不可从标题推断的后果，其余是使用说明
   （"换网络后连不上时用；加了不会自动连"）。用户原话："小字注释有的没必须注释吧"。
4. **空态重复同一个入口**：没有会话时空态给一个「打开会话抽屉」按钮
   （`chat_page.dart:4238-4243`），而顶栏有 `☰`、左缘也能跟手拖出。

## Decision

**一级面板只留"当前 + 三个动作"，管理项下沉。** 正常态 4 行、故障态 6 行：

```
● 已连接                             ⟳
  局域网直连 · 192.168.2.71
  直连没通，已走中转                          ← 只在回落/故障时出现
────────────────────────────────
  连接方式                     自动 ›
  切换电脑                      2 台 ›        ← 仅多台
  重新配对（换一台电脑）                       ← 故障恢复的 ≤2 步硬判据
  断开连接
```

- 删「打开侧面板」「手动填写地址」「添加电脑」「重试连接」四条：前两条没有存在理由，
  后两条进「连接方式 ›」与设置页端点区。
- 「重新连接」与「重试连接」合成一条：只有它，放弃自动重连后标题变「重试连接」。
- 「重新配对」保留在一级：`chat_page.dart:1514` 的硬判据是"任何状态 ≤2 步走到重新配对"，
  下沉到二级就变成 3 步。

**「连接方式」= 一张二级页，策略与地址列表在同一处**（这是"想连哪个就连哪个"的唯一落点）：

```
连接方式
  ○ 自动（推荐）    直连优先，不通自动走中转
  ○ 只用直连        中转不参与
  ○ 只用中转        直连不参与
可用地址
  ✓ 局域网直连 192.168.2.71   已连接
    中转 dsh.0t0.me           上次失败 12:03
    ＋ 添加地址
```

点一行地址 = **立刻用它连**（`AppModel.useEndpointNow`，失败回自动并说明）；当前那条打勾不可点。
端点排序 / 删除留在设置页（低频管理），不在这一页。

**小字三原则**（逐条判，写进评审口径）：

> 副标题只在三种情况出现：① 后果不可逆；② 与相邻项后果相反；③ 值是动态事实。
> 其余一律删。常驻解释换成"异常时的一行状态 + 一个动作"。

| 现在 | 处理 |
|---|---|
| 切换电脑「还有 N 台已配对的电脑」 | 改成右侧值 `2 台` |
| 手动填写「换网络后连不上时用；加了不会自动连」 | 删（进二级页，标题已够） |
| 添加电脑「再配一台；现在这台保留」 | 保留，缩短为「保留这台」（②） |
| 重新配对「会清掉本机凭据，需要重新扫码」 | 保留（①） |
| 断开「凭据保留，随时可以连回来」 | 保留，缩短为「配对保留」（②） |
| 打开侧面板 / 空态「打开会话抽屉」 | 整行删除 |

**空态**：删按钮与「会话历史在左侧抽屉里」小字，只留一句「选一个会话」。
入口靠顶栏 `☰`（可发现）与左缘拖出（快捷），不再第三处。

**出码卡**：一个主按钮 + 一组用途二选一（`同一 WiFi` / `任何网络`，默认按通道真值选，
不可用档禁用并给一行原因）。详见 `2026-11-13-connection-route-model.md`。

## Alternatives considered

1. 保留全部行，只把文案改短
   - 最强的理由：零结构风险，一次文案批就能发版。
   - 为何被否：乱的原因是**行数与同义项**，不是字数。11 行里仍有三个同义刷新图标和一条与连接无关的入口，改字救不了。
2. 把「连接设置」做成独立三级页
   - 最强的理由：一级最干净，所有管理项集中。
   - 为何被否：`chat_page.dart:1514` 的硬判据要求任何状态 ≤2 步到重新配对；三级就违反，而重新配对正是故障时最需要的动作。
3. 出码给三个按钮（局域网码 / 中转码 / 通用码）
   - 最强的理由：完全显式，用户想怎么配就怎么配。
   - 为何被否：三个按钮每次都要选，而其中至少一个当前不可用；二选一 + 默认值给出同样的控制力，少一次决策。
4. 把策略与地址列表分成两页
   - 最强的理由：各自职责单一。
   - 为何被否："想走哪条"和"现在有哪几条能走"是同一个问题的两半；分开后用户要在两页之间对照，正是现在设置页与连接面板各有一套的地方。
5. 空态保留「打开会话抽屉」给新用户做发现
   - 最强的理由：侧滑不是所有人都知道。
   - 为何被否：顶栏 `☰` 已经常驻且是同一入口；三处入口里删一处不损失发现性，而它正是用户点名的冗余。

## Consequences

- 收益：一级面板从 11 行降到 4–6 行；同义动作只剩一个；三个入口（绿点 / 空态 / 抽屉行）仍然共用同一份内容，不新增漂移点。
- 收益：小字有了可评审的判据（三原则），后续新增项不必再靠"感觉"决定要不要写说明。
- 代价：`connection_actions_sheet.dart` 的参数集要重排（`onManualEndpoint` / `onAddHost` / `onOpenSide` 从一级移到二级页），三个调用点（`chat_page.dart`、`main.dart`、设置页）都要同步。
- 代价：新增一张"连接方式"二级页（策略三档 + 地址列表），与设置页端点卡存在职责重叠——已删掉设置页那份「配对拨号顺序」行并改名「连接方式」指向新页，否则又变成两处。
- 代价：删掉的两个入口会让"添加电脑 / 手动地址"多一步；这是低频动作，接受。
