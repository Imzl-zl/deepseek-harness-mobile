# Agent Note: 文件面板的假表头与三个死按钮（同类：生产路径上的假数据）

Status: implemented

## Problem

2026-10-20 自查（用户："其他的需要你也自己摸索摸索"）发现文件面板有两处
和刚拔掉的假附件**同一类**的问题：

1. **表头是写死的假数据**：
   ```dart
   SidePanel.file => const SideHeader(
     title: 'chat_page.dart',
     subtitle: 'app/lib/ui/chat_page.dart',
     added: 128,
     removed: 46,
   ),
   ```
   而面板体（`_fileBody`）显示的是 `_EmptyFilePane`：「还没有改动 …
   数据来自会话投影 deliverables」。
   **表头声称某个文件有 128 行改动，面板体说根本没有改动** ——
   两句话互相矛盾，而且那不是示例，是在生产路径上摆着。
2. **底部三个动作全是死按钮**：`复制路径` / `在电脑打开` / `分享`，
   每一个 `onTap` 都是 `_notWired(...)`，且它们挂在**没有内容**的面板上。
   而 `settings_page.dart` 的文件头早就写下了这条纪律：
   > 一行点下去只弹"还没做"的假入口，比没有这一行更糟（用户会以为功能坏了）。

   也就是说：**我们自己的规则禁止我们自己的实现**。

## Decision

1. 文件面板表头改成 `SideHeader(title: '文件')` —— 与面板体的空态同一口径。
   等接上真的 `deliverables` 投影再从数据里取标题与 `added/removed`。
2. 删掉 `_fileActions()` 与 `_FileAction` 类（连带调用点）；
   等有真内容时再做那三个动作 —— 那时"复制路径"才有路径可复制。

## Alternatives considered（否掉的）

- **保留按钮但改成禁用态**：禁用而不解释等于"看起来坏掉了"；
  而"点了弹还没做"已经被本项目规则明确否掉。否。
- **把表头改成动态但仍为空**（比如 `未选择文件`）：空态已经有面板体在说，
  表头再重复一遍是噪音。只留「文件」这个词最省。否（更简的那版胜出）。

## Consequences

- 收益：文件面板从"自相矛盾 + 一排死按钮"变成"一句实话 + 空态"。
- 代价：菜单/面板少三个按钮；`SidePane.fileActions` 参数暂时没有调用方
  （保留着，等文件面板真接上时用）。
- 测试：`flutter test 841` 全绿（没有测试断言过那个假表头或那三个按钮 ——
  这也说明它们本来就没有被当作"功能"对待）。
- **真机**：文件面板表头显示「文件」，无 `+128 −46`，无底部动作条；已验。

## 这一类问题的规律（值得复用）

**"替身/示例看起来合理"是最容易漏的一类**：它不报错、不空屏、
样式也对，只是数字/名字是编的。抓法有两条：
1. 在 `lib/` 里搜**写死的中文/文件名/数字**（`chat_page.dart`、`+128` 这么搜出来的）；
2. 搜 `_notWired(` / `还没做` —— 每一个都是"承诺了但没做"的入口。
本仓现在 `_notWired` 只剩 `＋` 菜单里那几项（它们各自说的是"还没做"，
不是假装做了），以及这个方法的定义本身。
