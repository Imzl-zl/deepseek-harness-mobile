# Agent Note: 提醒只默认"需要你操作"的三类，后台任务通知降为默认关

Status: implemented

## Problem

四类提醒里，审批、提问、整轮跑完都对应"用户该动手了"；**后台任务结束不对应任何操作**。
而它是逐条的：一次会话里跑五个命令，退到后台就是五条通知，再叠一条"跑完了"
（`app/lib/data/notices.dart:141-166`、`:167-177`）。

"前台不打扰"也只覆盖"正看着那个会话"一种情形（`notices.dart:106-108`）——在 App 里看别的
页面时照样每条都贴，这是"太频繁"的主要来源。用户原话：审批、提问、会话完成没毛病，
每个后台任务确实没必要。

## Decision

默认只贴三类**需要操作**的：审批、提问、整轮跑完。后台任务通知改由设备本地策略控制：

`device.notify_tasks` = `off`（默认）/ `failures` / `all`

- `off`：不贴任何任务通知（`desiredNotices` 不生成 `kind: job` 的条目）。
- `failures`：只贴终态为 `failed` / `killed` 的任务（`core/job.dart:79-84` 的 `statusText` 两个失败档）。
- `all`：保持现状（终态 + 30 分钟窗口 + 按 `jobId` 去重）。

准入门槛（可机械判定）：

1. 默认值（键不存在 / 读不出 / 值非法）下 `desiredNotices` 返回的集合里 job 类为 **0 条**，单测断言。
2. `failures` 档：`completed` 的任务一条都不贴，`failed` / `killed` 各贴一条（同一 `jobId` 只一条）。
3. 三类的行为与现在逐字一致（含"看着它就不提醒"、"30 分钟窗口"、"按台撤"）。
4. 设置页只有一行入口，三档；文案说明"默认关，因为任务结束不需要你操作"。

## Alternatives considered

1. 直接删掉任务通知这一类
   - 最强的理由：最贴"只提醒需要操作"，判据一条不多，与宿主 DSH 只有 `completionUnread` 一致。
   - 为何被否：长任务失败时那一轮可能还要跑二十分钟，删掉就彻底没有信号。保留一个默认关的开关，成本只有一行设置。
2. 保持现状（每个任务都提醒）
   - 最强的理由：任务身份完整、与 `implemented/2026-11-09-job-completion-notice.md` 的决定一致；长任务结束立刻可见。
   - 为何被否：通知的价值在稀缺。用户的体感已经证明它过度，而"任务结束"本身不需要任何操作。
3. 同一轮合并成"这一轮 N 个任务结束"
   - 最强的理由：不刷屏，又保留了"有任务结束"这件事。
   - 为何被否：任务身份丢了（2026-11-09 已判过），而用户并不关心数量——他关心的是"要不要我动手"。
4. 把三类也做成开关
   - 最强的理由：配置自由，一次做全。
   - 为何被否：审批/提问/完成是安全与推进的必要信号，关掉只会制造"不知道在等我"的故障；多两个旋钮换不来价值。

## Consequences

- 收益：默认安静；一次会话从 N+1 条降到 1 条；任务失败仍可主动订阅。
- 收益：删掉"任务类必须逐条解释"的文档负担，`notifications.md` §3 的四类表收敛为"三类 + 一档可选"。
- 代价：多一个设备键 `device.notify_tasks` 与一条读值兜底（读不到按 `off`）。
- 代价：默认配置下长任务失败不会主动提醒，用户要自己发现；这是刻意用"安静"换"不打断"。
- 代价：`implemented/2026-11-09-job-completion-notice.md` 的结论被部分取代（逐条仍保留在 `all` 档），已在它开头加一行"默认值已由 2026-11-13 这篇改掉"，而不是改写它。
