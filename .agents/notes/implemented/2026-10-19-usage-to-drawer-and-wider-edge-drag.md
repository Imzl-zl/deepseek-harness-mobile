# Agent Note: 用量搬到侧滑抽屉 + 抽屉拖出区放宽（四条反馈）

Status: implemented

## Problem

用户 2026-10-19 四条反馈：

1. 「用量你最好也是做成一个页面的，你看 D:\sudy\github\rikkahub 你这样信息量不多，
   单页面的话信息量可以做很多，总量，单个项目使用量是吧」。
2. 「用量在侧滑窗口菜单单独页面啊，这不是显眼，因为这个挺常用的，你藏太深了」。
3. 「这个你参考 rikkahub，它就是的，不过技术栈不一样，你需要看看你这个技术栈
   怎么搞，别猜」。
4. 「会话页怎么怪怪的啊？」—— **待用户补充**（当时手机未配对，我看不到会话页）。

## 调查

### 用量独立页（DSH 没有对应物）

DSH 只有**统计条**（`ui-chat/src/client/chat/StatsPills.tsx`，单会话的轮次/步数/
耗时），没有独立统计页。所以这一页是我们自己的形态 —— 但**每个数字仍来自
DSH 的持久真值**（`tokenUsage` 投影经插件聚合，`usage.summary`），
不是本地记账。

"单个项目"的数据来源：`session.list` 的 `cwd`（`connector/src/dsh/sessions.ts`）。
**不用 `workspace.title`**：`SessionSummary` 里没有 `workspaceId`
（`connector/src/dsh/workspaces.ts:9` 明说只有 `cwd`），要拿标题得多一次往返
加一次 id 映射；按 `cwd` 分组**一次调用就够**。项目名显示**路径末段**
（`D:\sudy\myproject\dsh-mobile` → `dsh-mobile`）。

### 抽屉拖出区（Flutter 这一侧怎么搞）

`material/drawer.dart:657-665`：拖出区宽度由 `edgeDragWidth` 指定，
**默认只有 20px + 安全区**。我们原先设 32px。**从没设过更大** ——
所以"只能从最边缘滑"。

rikkahub 用 Compose 的 `ModalNavigationDrawer`（`ChatPage.kt:225`），
其"整页都能滑"的手感来自 Compose 的手势判定，与 Flutter 不是一套。
**技术栈不同的部分照搬不了**，但"拖出区可以更宽"这件事在 Flutter 侧有
对应的官方参数。

## Decision

### 1. 用量搬到侧滑抽屉底栏

抽屉底栏原是 `文件 / 归档 / 设置` 三枚，**加第四枚「用量」**
（`main.dart` 的 `DrawerFootItem`，`gauge` 图标）。点开是独立一页。

**同时删掉设置页里的用量入口** —— 用户说"藏太深了"，那就不该留两处；
设置页只留不常改的偏好（主题 / 步骤展示 / 性能 / 繁忙时发送 / 端点）。

### 2. 拖出区 `min(屏宽 28%, 64px)`

**两条上限都是实测撞出来的**：

- **64px 硬顶**：先试了 45%，真机 + widget 测试都显示底部**统计条的横滑**
  被抽屉手势抢走（`16 轮 650 步 · 338M tok · 缓存命中 97%` 那一行四枚 chip，
  横滑是为"四位数也滑得到"专门做的 —— `widget_test.dart` 的
  "统计条横滚不裁切"那条断言直接红：滑完第三项 dx 仍是 566 ≥ 320）。
  320px 窄屏上 28% = 89.6px，已超过统计条可起手的范围。
- **28% 比例顶**：宽屏上 64px 太窄，仍是"从最边缘起手"。

两者取小 ⇒ 窄屏 64px、宽屏 28%。**这仍是默认 20px 的 3 倍多。**

### 3. 与系统返回的关系（没动）

那 192dp 的排除带仍按原样给（`platform/gesture_exclusion.dart`，
官方每条边上限 200dp）。**排除带只是"系统别抢这一段"，与"App 的拖出区多宽"
是两件事**，重叠不矛盾。**没有把排除带加宽去凑整页** —— 那条 API 是逃生舱，
官方明说只该给真正需要的那一小块（`gesture_exclusion.dart:18-19`）。

## Alternatives considered（否掉的）

- **把拖出区设成 45% 甚至更大**（更接近 rikkahub 的"整页"）：实测抢走统计条
  横滑。否。**真要整页，得先让统计条不依赖左缘起手**（它自己的事）。
- **用量入口两处都留**（抽屉 + 设置页）：用户说"藏太深"，留两处等于没搬。否。
- **按 `workspace.title` 显示项目名**（而不是路径末段）：要多一次往返 +
  id 映射，而 `cwd` 一次调用就够。否。

## Consequences

- 收益：用量从"设置页第三层"变成"抽屉底栏一枚 + 独立一页"；抽屉拖出区
  从 32px 变成 `min(28%, 64px)`（窄屏 64px / 宽屏 28%）。
- 代价：抽屉底栏多一枚（四枚在 360px 抽屉上仍放得下，`Expanded` 均分）；
  统计条左缘 64px 内起手的横滑被抽屉接管（**已知取舍**，见上）。
- 测试：`settings_page_test.dart` 两条用例换成一条"设置页不再摆用量入口"
  （守的是"别又长回来"）；`widget_test.dart` 的统计条横滚用例恢复绿
  （它同时是"拖出区别抢统计条"的守栏）。
  `flutter test 815` 全绿。
- **真机**：抽屉底栏四枚、用量独立页（空态"拉不到用量 · 连接不在服务态"）
  都验过；**有数据的用量页要等用户配对后看**。
