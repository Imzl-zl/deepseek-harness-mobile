# Agent Note: 界面字号改成「两层倍率、全局等比放大」

Status: implemented

## Problem

`2026-10-22-type-scale-base-plus-delta.md` 按 DSH 把"字号大小"做成 **base + delta、只作用于
会话内容**（正文/标题/用户气泡/工具名/运行条/输入框），chrome 与 caption 固定。

用户当场退回：「这个字体大小我看了**非常的丑**，而且**有的地方字又很小**，所以我想的是**全局**」。

实测证据（2026-10-22 晚）：

1. `app/lib/` 里 **217 处** `fontSize:`，分布 `11×72 / 12×63 / 13×47 / 14×19 / 15×7 / 16×4…`
   —— **62% 的字在 11–12px**。"有的地方字小"是结构性的。
2. 只放大内容 ⇒ 内容/chrome 对比从 14/11 = **1.27** 拉到 22/11 = **2.0**。
   两块差一倍的界面读起来不像同一个 App —— 这是"丑"的机械解释。
3. App 本来就跟随系统字号（`MediaQuery.textScaler` 没被覆盖）。用系统 `font_scale` 做压力测试
   （隔离实例 63900、有工具卡/代码块/diff 的会话，**不跑模型**，只是选会话读历史）：
   1.15 / 1.3 / 1.5 都不溢出；2.0 不溢出但明显发挤。**但图标、内边距、36/44 定高不跟着走**。

## Decision

1. **App 内设置从"内容字号 10–22"改成"界面字号四档倍率"**：较小 0.9 / 标准 1.0 /
   较大 1.15 / 特大 1.3（默认 1.0）。常量在 `model/preferences.dart`，落盘键 `ui_scale_index`。
2. **实现走 `MediaQuery.textScaler`**：`main.dart` 的 `_uiScaled` 把
   `平台倍率 × App 倍率` 算出来，`clamp(0.85, 2.0)`，包一层 `MediaQuery`。
   等比放大 ⇒ **所有**文字（含 chrome 与 caption）一起长，**且对比关系不变** —— 这就是"全局"。
3. **图标跟随**：`DshIcon` 按同一倍率放大，`clamp(1.0, 1.4)`，装饰性大图可用
   `scalesWithText: false` 退出。改的是生成器模板（`app/tools/dsh_icons.template.dart`），
   再跑 `node app/tools/extract-dsh-icons-dart.mjs`。
4. **带文字的定高改 `minHeight`**：披露行 36、sheet 底部按钮 44、抽屉「新建会话」44、搜索框 36。
5. `DshType` 退化成**设计基准角色表**（正文 14，不随设置变）；`DshTypeScope` 删掉，
   `context.dshType` 恒返回 `DshType.standard`。

## Alternatives considered

1. **保持"只放大内容"，但把上限从 22 压到 18**
   - 最强理由：改动最小，一行常量。
   - 为何被否：18/11 = 1.64 仍然差一半；而且用户要的是**全局**（原话），压上限只是把问题缩小。
2. **保持只放大内容，同时把 chrome 也纳入 delta（压缩半个 delta）**
   - 最强理由：既"全局感"又不让 chrome 涨太多。
   - 为何被否：那是**造第二套规则** —— 每个用到 chrome 字号的调用点都要判"这是 chrome 还是内容"，
     217 处里有一半要逐个归档，且新人不可能知道某处该算哪一类。
     等比放大没有这个歧义：一个倍率，所有文字同一个系数。
3. **不用 `MediaQuery.textScaler`，逐处把 `fontSize` 乘上倍率**
   - 最强理由：每处可独立控制（"标题少放大一点"之类）。
   - 为何被否：等价于 217 处都要改 + 永远有新代码忘记乘。`textScaler` 是平台机制，
     连第三方组件都会跟着走。
4. **App 内不给设置，只跟随系统**
   - 最强理由：最少代码。
   - 为何被否：**用户在系统里调过之后进 App 还要能再调**是手机 App 的通行预期；
     而且系统字号最大 2.0，很多人只调到 1.0 就以为"这个 App 字就是小"。

## Consequences

- 收益：一个开关治住整个界面；对比不再随设置翻倍（"丑"消失）；图标与文字同步；
  `11–12px` 占 62% 的"字小"问题被倍率整体抬起来（1.15 档相当于 12.65–13.8）。
- 代价：
  - 与 DSH 的 `fontSize`（10–22、只影响内容）**有意偏离**，DSH 的设置面因此不能逐字照搬；
  - `DshTypeScope` 被删，`context.dshType` 不再反映设置（它只是角色表）——
    以后要"只调某一档"就得回到 option 3；
  - 图标最大放大 1.4，特大档（1.3）+ 系统 1.3 = 1.69 时图标会略小于文字（**有意**：图标抢戏更难看）；
  - 已知边角：1.3 档下右缘的书签胶囊（最早/最新）与卡片右箭头轻微重叠。
- 真机证据（`d61cf622`，系统字号 1.0）：`shots-2026-10-22/ui-scale-{90,100,130}-chat.png`
  与 `ui-scale-130-settings.png` —— 设置页在 1.3 下整页（含说明文字、开关、图标）等比放大，
  会话页的 tool 卡 / 思考行 / 列表 / 输入框 / 统计条同步放大且无溢出。
- 单测：`type_scale_test.dart`（角色表逐档、四档表、落盘/夹取/读回、390dp×1.3 不溢出）
  与 `settings_font_size_test.dart`（行默认档、sheet 四档、选完落到模型）。
