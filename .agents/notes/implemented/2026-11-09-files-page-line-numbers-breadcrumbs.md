# Agent Note: 文件预览给行号，位置行改成可点的面包屑

Status: implemented

## Problem

文件页两处"看得出在哪、看的是第几行"的东西缺着：

1. 位置行只是**一段纯文本**（`src/lib/ui`）。要回上一层，只能点「上级」一层层退，
   想跳回根目录得退三步；手机窄屏上也没有桌面那棵常驻目录树。
2. 预览正文**没有行号**。读代码时"第 42 行"是跟别人说话、跟日志对位置的最小单位，
   而没有行号的等宽文本只能靠肉眼数。

## Decision

1. 位置行换成**面包屑**：`工作区根 › src › lib`，每段是一个 `TextButton`，点了就用那一段的
   路径重新 `file.list`；当前目录那一段禁用；整条横向滚动、不折行。**不假装是目录树**
   （没有展开/收起，也不列兄弟目录）。
2. 预览正文左列加**文件行号**：单列、从 1 起、按最大号补齐宽度；行号用弱色、与正文同一个
   等宽块（仍是 `SelectableText.rich`，可整段选中复制）。

准入门槛（可机械判定）：

1. `filePreviewLines(text)` 是行号的唯一来源：末尾换行不算一行（`'a\nb\n'` 与 `'a\nb'` 都是两行），空行算一行。
2. 面包屑每一段的点击结果 = 那一段的路径（测试断言 `file.list` 的 `path` 序列是 `['', 'src', '']`）；当前段 `onPressed == null`。
3. 行号与 diff 的双列行号无关：`model/diff.dart` 的 `DiffLine` 是"旧/新两侧"，这里只有一列。

## Alternatives considered

1. 只加「上级」并保留纯文本路径
   - 最强的理由：改动最小，路径长时可省略号截断，不占额外高度。
   - 为何被否：从 `src/lib/ui` 回根要退三次；而"我在哪"是文件页最常问的问题，纯文本答不了"怎么回去"。
2. 做一个真正的目录树（桌面那棵常驻树）
   - 最强的理由：与桌面同形，一次能看到全部层级与兄弟目录。
   - 为何被否：手机窄屏上树要么占掉半屏（挤掉文件清单），要么变成二级面板（多一次点击才看到文件）。面包屑把"层级感"和"跳回去"两件事都给了，代价只是不列兄弟目录。
3. 行号做成独立的行号栏（两列布局）
   - 最强的理由：选中复制时不会把行号一起复制进去。
   - 为何被否：独立一列要么与正文不同步滚动（要额外控制器），要么两列各自换行后错位；而 `SelectableText.rich` 一个块里天然对齐。复制带行号的代价可以接受（用户复制的是代码时通常会自己清）。
4. 用现成的 `DshDiff` / 代码高亮组件来画
   - 最强的理由：行号与高亮都是现成的。
   - 为何被否：那是 diff 的双列行号 + 行级着色，语义是"改动"；预览要的是文件行号。混用会让"这一行是新增的"和"这是第 42 行"变成同一套颜色。

## Consequences

- 收益：任意层级一步跳回；预览能对着日志/报错说"第几行"。
- 代价：面包屑在深路径上要横向滚动才看得全（不折行是有意的：折行会把清单往下挤）。
- 代价：复制正文会把行号一起带走（见替代方案 3 的取舍）。
- 代价：`filePreviewLines` 按 `\n` 切分，`\r\n` 的文件行尾会留一个 `\r`（渲染成一个不可见字符）。目前没有按行尾归一 —— 若真机遇到 Windows 换行的文件出现怪空白，改这里，不要改调用点。
