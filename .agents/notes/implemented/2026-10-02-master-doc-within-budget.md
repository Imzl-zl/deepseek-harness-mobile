# Agent Note: 总纲超预算时,砍的是"手抄副本"与"下沉没做完的细节",不是约束

Status: implemented（2026-10-02;总纲 3,450 → 2,953 词,章节号与全部约束不变）

## Problem

### 一、总纲超出 `docs/AGENTS.md` 的词数预算

`docs/AGENTS.md` §字数预算规定 `design-and-tech-plan.md` ≤3,000 词,而它实际 3,450 词。
超预算本身不是灾难,但它有一个具体的坏后果:**"新增内容优先下沉"这条规则会失效** ——
一份已经超限的文档,再往进加东西时没人会觉得是问题,于是它继续膨胀,直到没人通读。

### 二、两处膨胀是**违反 `docs/AGENTS.md` 其它规则**造成的,不只是"写得多"

按该文件 §去废话守则逐条对照,超出的部分主要来自两处**规则性违规**:

1. **§5.7 手抄了一份 Dart 色板草图** —— 违反守则 2「严禁人肉手抄生成物」。
   它抄的是 `app/lib/theme/dsh_colors.dart` + `dsh_theme.dart`,而且**已经漂移**:
   草图写 `menuSurface` / `fileDiffAddMk` / `fileDiffDelMk`,实际代码是
   `menu` / `fileDiffAddMarker` / `fileDiffDelMarker`。同时违反守则 3(代码块须能编译)——
   那份草图**编译不过**(字段名对不上)。
2. **§8.5 把 DSH 全部 ui-* 包列成五张对照表**、**§12/§13 复述了专项文档的细节** ——
   违反守则 4 的顺序(该先"下沉迁移",而专项文档 `plugin-and-jobs-notes.md` /
   `standalone-mode-notes.md` 里**已经有**这些内容)。

**所以这不是一次"文风精简",而是把该在别处的东西放回别处。**

## Decision

**按 `docs/AGENTS.md` 守则 4 的顺序压缩:先下沉(删掉已在别处的副本)→ 再浓缩。不删约束。**

1. **§5.7**:整块 Dart 草图删除,改成指针(指向两个 Dart 文件 + 一句"改色板改 Dart 文件")。
2. **§8.5**:五张表压成四段行内清单,★/○/△ 分级与全部包名保留(这是"清单"的用途),
   删掉重复的"界面"描述列。
3. **§12 / §13**:各自开头加"逐条依据见 `<专项文档>`",正文压成边界结论;
   细节(源码行号、Schemastery 元数据字段、rikkahub 数据结构)全部交给专项文档。
4. `docs/AGENTS.md` 的字数预算行同步改成实际值。

**硬约束:章节号一个都不许动。** 该文档的章节号被仓库内几十处引用
(`AGENTS.md` §7.2/§7.9/§7.10/§12、`docs/architecture.md`、`standalone-mode-notes.md` 十余处、
`styles.css:3` 引 §5、`.agents/notes/` 多篇),重编号会打断全部交叉引用。
本次只压正文,`## 1`–`## 13` 与 `### 7.1`–`### 7.10` 编号全部保持原样。

准入门槛(可机械判定):

1. 去空白后按空白分词 ≤3,000 词。
2. `## ` 与 `### ` 标题的**编号前缀集合**与压缩前相同(标题正文允许改 —— 本次只改了
   §5.7 一处:去掉"(`lib/theme/dsh_colors.dart` 草图)",因为草图已删,标题不该再指向它)。
3. 关键约束仍在文档内:grep `密钥不回传` / `绝不生效` / `有意偏离` / `不承诺删除` /
   `不乐观更新` / `架构性限制` / `HUKS` 均 ≥1 命中。

## Alternatives considered

1. **重新编号、把 §8.5 与 §5.7 整体删掉**
   - 最强的理由:能省最多篇幅,文档结构也更干净。
   - 为何被否:§8.5 是"对着 DSH 全部 ui-* 包核对,避免遗漏"的**清单**,删了就没有
     "哪些包还没覆盖"的对照物;而重编号会打断几十处外部引用(见 Decision 的硬约束)。
     省篇幅不该拿"可追溯性"和"引用完整性"换。
2. **按"每段砍 10%"均匀精简**
   - 最强的理由:最省事,不用判断哪段重要。
   - 为何被否:均匀精简会把**约束**和**废话**一起削弱 —— 例如"未授权绝不生效""密钥不回传"
     这类句子砍掉几个字就损失了判定力。而真正该砍的是**副本**(手抄代码、已下沉的细节),
     它们的价值本来就是零。判断哪里是副本需要读一遍,不能靠比例。
3. **只删 §5.7 的草图(单点修复),不动 §8.5/§12/§13**
   - 最强的理由:§5.7 是唯一"违反守则且已造成实际漂移"的地方,优先修它性价比最高。
   - 为何被否:删完仍有约 3,250 词,依然超预算 —— 等于没解决"规则失效"这个根因。
     而且 §12/§13 的复述与专项文档已经构成第二处来源,迟早会漂移(与 §5.7 同类)。
4. **申请提高预算(守则 4 的第三步)**
   - 最强的理由:这份总纲内容确实多,3,000 词对"定位+架构+技术栈+设计系统+逐屏+协议+路线+风险"偏紧。
   - 为何被否:守则 4 明令顺序是「下沉迁移 → 精简浓缩 → 申请提额」,**不允许先提额**。
     而本次证明前两步足够(3,450 → 2,953),说明预算并非不合理,是内容放错了地方。

## Consequences

- 收益:总纲回到预算内(2,953 词);**消除了两处"第二来源"** —— 手抄色板(已漂移)与
  §12/§13 对专项文档的复述;§5.7 从"编译不过的代码块"变成正确指针;
  §8.5 保留全部包名与分级,仍可当覆盖清单用;章节号与全部约束未动,几十处外部引用不受影响。
- 代价:**读总纲看不到色板与插件细节了,要跳一次文件**。这是守则 4 明确选择的代价
  (上层只放单行链接,细节下沉);对"想快速了解全貌"的读者是多一跳。
- 代价:`docs/AGENTS.md` 预算行写了"当前约 2,960" —— 这个数字**会随编辑漂移**,
  和 `tools.md` 里"项数唯一出处"那条是同一类需要手工同步的负担。若将来它反复漂移,
  应考虑改成范围表述(如"≤3,000 词")而不是记具体值。
- 遗留:本次只动了总纲。`remote-channel.md` 已 4,012 词(分析类预算 5,500,尚有余量),
  未处理;`channel-review-notes.md` 1,947 词,健康。
