# Agent Note: 连上之后落到"上次看的 → 在跑的 → 最新的"，不追桌面的"当前会话"

Status: implemented

## Problem

用户真机提问：桌面开着一个会话（甚至正在跑），这时手机才连上 —— 按正常体验，手机应该
直接落在那个会话，并在跑就显示在跑。手机此前连上后只拉列表，**不打开任何会话**，
停在上一屏或空白 hero，看起来像"没动静"。

## Decision

落点四档（`AppModel.landingSessionOf`）：

1. 上次看的会话还在 → 回到它（`last_session` 偏好，`openSession` 时落盘）；
2. 否则 `running` 里 `updatedAt` 最新的；
3. 再否则 `updatedAt` 最新的；
4. 都没有 → 空白，不发明会话。

触发点在进服务态、`refreshSessions()` 回来之后；已有会话不覆盖。

**不追桌面的"当前会话"**：那是浏览器本地 UI 状态（`ctx.uiWorkspace.openSession`），
宿主没有这个字段。硬做只有两条路：给宿主加字段（自创，违反"不新增宿主没有的边界"），
或者只按"最近活动"近似（本条选的就是近似，且明确写清它不是"跟随")。

## Alternatives considered

1. **给宿主加"当前会话"字段 / 连接器自己记一份**
   - 最强的理由：完全符合"手机跟随桌面"的直觉。
   - 被否：桌面同时可以开多个窗口/标签，谁是"当前"没有唯一答案；宿主没有这个事实，
     编一个出来就是第二份真值，之后每处都要维护它。
2. **连上永远跳到 `updatedAt` 最新，不管"上次看的"**
   - 最强的理由：规则更短。
   - 被否：用户在手机上看历史会话时重新连一次就被甩到别的会话（真机上经常发生）；
     "上次看的"是唯一能跨连接保持的意图。记住它只用一个偏好键。
3. **只在有 `running` 时才自动打开，其它情况停在空白**
   - 最强的理由：最不打扰。
   - 被否：用户回到手机最常见的诉求是"接着看刚才那个"，空白屏等于每次都要再点一次。

## Consequences

- 收益：连上就有内容；电脑在跑时，手机直接显示那一轮的运行条。
- 收益：不再需要"重连按代号重建 running"那套推断 —— running 的实时来源是
  `api-session/status` 帧（本来就已接上）。
- 代价：手机不会跟着桌面**切换**会话（做不到，见上）。
- 代价：`last_session` 是手机本地偏好，换电脑后可能失效，失效时回落到规则 2/3。
- 代价：落点选中的会话若本机没有历史条目，页面走空白 hero，运行条不出现（空会话无内容可画）。
