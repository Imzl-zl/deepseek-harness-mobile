# Agent Note: 配对阶段把 `lan` 全部一起拨，失败只给一句

Status: implemented

## Problem

电脑侧从 2026-11-24 起把**此刻全部局域网 IPv4** 写进码（`.agents/notes/implemented/2026-11-24-offer-carries-current-lan-addresses.md`），
一台普通开发机就有 2–4 条（WLAN + 以太网 + 两条 VMware host-only）。

手机侧原来按码里的顺序**逐条**拨、每条等满超时（直连 3 s / 10 s 量级）。三条候选里前两条
拨不通时，人在配对页上干等十几秒，然后看到一串「拨不通：…」—— 用户 2026-11-24 的原话：
「我怎么看报错连不上啥的？」那一串字里既有真因（码过期、不同 WiFi），也有挡路的噪音。

## Decision

**同一轮内对全部 `lan` 候选并发发起受限握手，先通先用；其余候选（含还在握手中的）当场收掉。
全部失败时对外只给一句「局域网不通（试了 N 个地址，是否同一 Wi-Fi？）」，每条的原始错误进诊断日志。**

准入门槛（可机械判定）：

1. `app/lib/core/pairing_flow.dart` 的 `tryLan` 在同一轮里对 `lan` 全量发起；**赢家一确定就
   关闭其余全部**（含仍在握手的），并 `await` 收干净再进确认卡。`app/test/pairing_flow_test.dart`
   的「并行：三条握手是同时发起」必须红过一次（改回串行）。
2. 失败文案里**不出现具体地址**：`app/test/pairing_flow_test.dart` 断言那句汇总
   「试了 N 个地址」且不含 `192.168.` 之类。改回拼接明细要红。
3. 中转那条腿的原因**仍然单独说**（`_rethrowWithLanNote` 只加前缀，保留错误码）——
   两条腿对用户是两件事，这条沿用 `app/lib/core/endpoint_transport.dart` 的既有口径。
4. `lanOnly` / `directOnly` 的码不把局域网那侧显示成"不通"（既有行为，不许退）。
5. 面板仍是**两行**（局域网 / 中转），局域网那行标题带地址总数（`局域网直连（3 个地址）`），
   不为每条地址加一行。

## Alternatives considered

1. **保持串行，按"最可能通"的排序先拨**
   - 最强的理由：不占多条 socket、日志干净，而且第一条多半就通（默认路由那条排第一）。
   - 为何被否：排序靠的是**通用偏好**，而"这台手机能不能到这个 IP"取决于 AP 隔离、双网卡、
     子网划分 —— 恰恰是猜不准的那些事。串行的失败代价是**线性的**：3 条不通 = 十几秒。
2. **串行但把超时缩短到 1 s**
   - 最强的理由：最坏耗时可控，改动最小。
   - 为何被否：1 s 在慢一点的 WiFi / 握手重试下会误杀真正能通的地址；而且"改超时"是
     给判据加档位，属于新增边界（项目军规：宿主没有的边界不要加）。
3. **逐条显示每个地址的"通 / 不通"**
   - 最强的理由：诊断信息最全，用户能看出哪条死。
   - 为何被否：配对页是"扫码 → 连上"的一条直线，不是诊断面板。逐条红字在 2026-11 的真机上
     把"配对码已过期"这个真因淹掉了（`tools.md` 里那条坑记的就是这个）。明细进
     `debugPrint('[pair] …')`，要查的人看得到，不查的人不用读。
4. **只在 `lan` 超过 1 条时才并行**
   - 最强的理由：最常见情况（一条）走原来的路径，改动面最小。
   - 为何被否：两条代码路径 → 两条行为、两套测试。并行对一条候选与多条候选是同一件事
     （一条时它就是"一个任务"），没有分叉的理由。

## Consequences

- 收益：配对耗时从"候选条数 × 超时"压回"一条超时"；失败面从一串红字收成一句。
- 代价：一轮里最多 N 条并发握手（N = 电脑此刻报的条数，通常是 1–4）。电脑侧会同时看到
  几条候选连接，输家立刻被手机关掉 —— `pairing-lan.ts` 没有"同一 offer 只许一条候选"的
  限制，但这条**跨端**行为只在单测里验过，真机要复扫一次确认（写进验收清单）。
- 代价：`pairing_channel.dart` 的 `close()` 必须给卡在握手里的 `open()` 一个当场答案，
  否则被收掉的候选会挂在永不完成的 Future 上（已按此改，`_ready.future.ignore()`）。
