# Agent Note: 协作体系每个事实只留一个家，并把「同批提交」变成可执行

Status: implemented

## Problem

协作体系本身长成了它要防的形状——同一件事被抄成多份，然后各自漂移：

- **可验证数字没人对账。** `tools.md` 写边界校验「自带规则自检 10 条」，实际跑出来是 13 条（6 条规则 × 13 个合成样本）。这类数字散落在 `tools.md`、`memory.md` 门禁表、根 `AGENTS.md` §5 三处，改一处实现不会让另外两处变红。
- **坑点有两份。** `memory.md`「仍需注意的坑点」9 条里有 8 条与 `tools.md`「Pitfalls」逐字重复；CDP 端口那条两边都写了，而两边都没写「9400 也可能被上一轮遗留的 headless Chrome 占着」——本次就是这个情况真的挡住了门禁（`cdp.ps1` 报 `port 9400 already in use`）。
- **`.serena/memories/project_overview.md` 是体系外的第二真值源。** 85 行里重复了 `memory.md` 与 `docs/` 的「已锁定决策 / 当前进度 / 下一步 / 参考项目」，且已过期：仍写「工作目录…当前基本为空，设计阶段」（实际已有原型与协议层），「下一步」写 Flutter 落地（与 `memory.md` 的 `connector/` 骨架冲突）。
- **`docs/architecture.md` 没跟上分层。** 只描述「两个层面」，完全没提 `protocol/`；子系统索引漏掉 `connector-and-relay` / `app-channel-client` / `channel-bootstrap` / `channel-review-notes`；验证入口只列 4 条且端口写成 9410（仓库默认为 9400）。
- **规则位置自相矛盾。** 根 `AGENTS.md` §3 声明「模块级约束就近写在该目录的 `AGENTS.md`」，但 `mock/proto/` 根本没有该文件，它的机械规则（图标、`styles.css` 括号平衡、sheet/drawer 层、CSS 覆盖）全堆在根 §6 与 `tools.md`。
- **最根本的一条：「代码与笔记同批提交」不可执行。** 根 `AGENTS.md` §4、`.agents/notes/AGENTS.md` 都把它写成不变量，`docs/AGENTS.md` 去废话守则第 1 条写「历史属于 git 和 `.agents/notes/`」——而仓库不是 git 仓库（`git rev-parse` 退出 128）。一条写在三处、却无法被任何操作满足的规则，比没有这条规则更糟：它让所有未提交的改动看起来都「合规」。

## Decision

协作体系按「每个事实只有一个家」归一，并把只能靠自觉的不变量改成可执行的：

- 现状事实 → `docs/`；因果取舍 → `.agents/notes/`；命令/路径/模式/**坑点** → `tools.md`；当前状态 → `memory.md`；常驻军规 → 根 `AGENTS.md`。
- 模块级约束只写在该目录的 `AGENTS.md`，根上只留一行指针。
- 建 git 仓库并接远端，让「代码与笔记同批提交」成为一次真实提交。

准入门槛（可机械判定）：

1. **同一事实只出现在一个文件。** 坑点只在 `tools.md` → `Pitfalls`；门禁的精确命令与断言条数只在 `tools.md`，根 `AGENTS.md` §5 与 `memory.md` 只引用不复述。
2. **写进文档的数字必须来自脚本实际输出，不许估。** 本次全部复核：边界校验 17 项（规则自检 13 条 + 扫描 2 个 Dart 文件）、`verify-authz` 18、`verify-settings` 27、`verify-tasks` 53、fixtures 486 项/16 条、回环 26、向量 33。
3. **模块级规则必须落在该目录的 `AGENTS.md`。** 根 `AGENTS.md` 只允许出现常驻军规与该目录的一行指针。
4. **门禁全绿才算这一批完成。** 参数改动的批次必须跑对应门禁；跑不了要在总结里写明原因与替代检查。
5. **代码与笔记同批提交。** 非平凡改动的提交里必须同时含笔记；本次即本文件与文件改动同批。
6. **浏览器门禁以独立 headless 那组为准。** chrome-devtools MCP 可以驱动日常浏览器里已打开的 `mock/proto/index.html` 做交互式排查，但它连的是有 70+ 标签页的日常浏览器，不作为门禁证据。
7. **截断第二真值源之前，必须逐项证明它的独有内容在别处有家。** 做法是拿它的每个主题词去全仓 grep，命中即算有家，未命中的要么迁走要么明写放弃。本次据此从 `.serena` 那份捞回两处当时无处可寻的内容：DSH 开发者文档 URL 与五篇 DSH 架构决策笔记的路径（均落在 `tools.md` 的「DSH 侧高信号入口」）。不查就删，等于静默丢事实。

## Alternatives considered

1. 按技能模板重写一份 canonical 根 `AGENTS.md`
   - 最强的理由：外观与模板完全一致，一次到位，不留历史包袱，后续维护只需对照模板。
   - 为何被否：现有根 `AGENTS.md` 仅 1,427 个中文字符，骨架 §0–§7 与常驻军规都已齐备且指名了 `decision-notes`，本仓特有约束（输入区三条硬规则、选择类列表、授权路径、密钥单向、有意偏离须写文档）也都在正确的层级。重写唯一的收益是外观统一，代价是这些约束在搬运中被改写或丢失——而它们正是这份文件最有价值的部分。改为定向修正 6 处已证伪的内容。
2. 保留 `memory.md` 与 `tools.md` 各一份坑点，图个就近可见
   - 最强的理由：`memory.md` 是新会话第一入口，坑点就近可读，少一次跳转；两份内容重叠也便于交叉印证。
   - 为何被否：它们已经漂移过（`tools.md` 的「10 条」与实现脱节），且 9 条里 8 条重复，交叉印证并没有发生，发生的只是两份各自腐化。就近便利抵不过第二真值源的持续成本，改为一行指针并写明「唯一出处」。
3. 删掉 `.serena/memories/project_overview.md`
   - 最强的理由：彻底消除竞争真值源，不留任何残留，最干净。
   - 为何被否：它是 Serena 与本项目的记忆关联点，直接删文件会丢掉这层关联。清空为指针同样消除了真值源，同时保住关联，代价更小。
4. 把 `mock/proto/` 的机械规则继续留在根 `AGENTS.md` §6
   - 最强的理由：根文件每次会话必读，规则放这里必然被看到；下沉到子目录有「agent 没读到」的风险。
   - 为何被否：根 §3 已经声明模块约束就近放，留着就是自相矛盾；而且子目录 `AGENTS.md` 在进入该目录工作时会被自动注入（本次 `docs/AGENTS.md`、`.agents/notes/AGENTS.md` 就是这样生效的），可见性并没有下降。真正下降的是根文件的信噪比——那才是它最该保护的。
5. 不起 git，继续只靠时间戳备份
   - 最强的理由：改动面最小，不改变仓库形态，不接触远端与凭据；备份足以在改坏时回滚。
   - 为何被否：备份只能证明「改前长什么样」，无法表达「这一批一起改了什么」——而后者正是「同批提交」要保证的东西（笔记与代码必须能被一起 review、一起回滚）。三处文档都把它写成不变量，不建 git 就只能继续让它不可执行。

## Consequences

- 收益：每条事实只有一个家，改实现不会再有三处数字不同步；所有写进文档的条数都来自本次实测输出；「代码与笔记同批提交」从纸面变成一次真实提交；`mock/proto/` 的机械规则有了就近的家，根 `AGENTS.md` 卸下模块细节、信噪比提高；`docs/architecture.md` 恢复为可用导航（补上 `protocol/` 与四个子系统）；`.serena/` 从竞争真值源变成纯指针。
- 代价：引入了 git 仓库与远端，协作面变大；`mock/proto/shots/`（约 9 MB 生成物）与 `setup-collaboration-files.backup/` 需要靠 `.gitignore` 维护，多一处要记得改的地方；坑点集中到 `tools.md` 后，只读 `memory.md` 的人要多一次跳转；**首次提交的内容已经是归一后的状态**，归一前的差异只能从 `setup-collaboration-files.backup/2026-10-01-0732/` 看，不在 git 历史里。
