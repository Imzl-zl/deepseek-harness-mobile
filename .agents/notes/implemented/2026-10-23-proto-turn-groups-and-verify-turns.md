# Agent Note: 原型轮组 = 落地端的「一轮一个可折叠组」+ `verify-turns.mjs`

Status: implemented（2026-10-23）。

## 起因

2026-10-22 落地端做了轮组（阶段 1），原型 `mock/proto` 当时**没同步**：`#msgs` 还是
静态平铺（`.turn--u` 用户气泡 / `.turn a` 助手块），没有组头、没有折叠；全仓 mock/proto 里
「轮组」零命中。`memory.md` 的待办 1 把这条记成"与子代理面板未跟上同一类"。

基线里没有的形态，下一个会话读原型时就会得出"手机上没有这个结构"的结论 ——
而 `mock/proto/` 是本仓的**交互基线**（根 `AGENTS.md` §2），"改基线要同步改落地端、
不允许两边各自漂移"是常驻军规。这一轮**不新增 App 行为**（App 领先），只让原型追平，
并补一个能跑通的脚本把结构钉住。**0 个真机回合**（只跑 headless CDP + 单测）。

## 判据出处（DSH 的形状）

- 折叠的是 `processMember`（`packages/client/ui-chat/src/client/chat/ChatNodeSeat.tsx:78-83`）；
  用户消息与最终回答是独立节点、始终可见；审批与提问是"等用户决策"的东西，收起来等于找不到待办。
- 组头在 `turn.status !== 'closed'` 时整行不渲染（`TurnProcessNodeView.tsx:18`）⇒ 运行中的一轮
  没有组头、不可折；箭头是 `chevronDown` + `rotate(180deg)`（`TurnProcessNodeView.module.css:37-39`）。
- 命令卡（`GenericCommandCard`）与压缩卡（`CompactionItem`）是过程、但不是"助手在说话"，
  不拿助手头；上下文注入行（`ContextInjectionRow.tsx:55`）算助手侧，系统提示词不算。
- 两档收起时机与 DSH 同名同义（`packages/client/ui-chat/src/chat-settings.ts:15,21`，默认 `completion`）。
- 现状事实与完整判据表在 `docs/subsystems/turn-groups.md`（§1/§2/§2.1/§3/§5）。

## 决定

1. **一个 `.tgrp` = 一轮**；`data-turn` 缺席 = 未归属组（历史窗口没加载到这一轮的
   `turn/start`），**永不折叠**（§1）。`data-closed="1"` = 已收口 ⇒ 才画组头（§3）。
2. **过程条目挂 `data-proc`，收起只按这一个标记**：`styles.css` 一条
   `.tgrp.is-folded [data-proc] { display:none !important }`。清单只存在于标记里 ——
   JS 不另列一份"哪些算过程"，脚本按组件类（`.tool` / `.idiff` / …）断言**可见性**，
   不按标记选元素（否则去掉标记时断言会"空过"，见"判据"的变异校验）。
3. **组头由 `app.js` 渲染在轮次末尾**：`第 N 轮` + 箭头 + 统计三段
   （`data-dur` / `data-msgs` / `data-tools`，**为 0 的项不列**）+ 用量 pill + 复制 pill。
   用量 pill 的 `10.6M` 与明细 sheet 的合计**同源**（`data-tok-in/cache/out` 相加再
   `formatTokens`，与落地端 `formatTokenCount` 同一条），不写两个数。
   末尾位置是**上一轮已定案的有意偏离**（`turn-groups.md` §4），这一轮不改。
4. **助手头改成"每组一个、在轮次开头"**（§2.1）：`index.html` 里每条助手块自带的
   `.a-head` 收成每组一枚，位置在第一条助手侧条目上方；头像换成 DSH 鲸鱼（引
   `app/assets/brand/dsh-whale.png`，落地端同一枚 `DshBrandMark`），名字是
   `DeepSeek Harness`，**不再挂模型名**（落地端 `AssistantHead` 已删掉那个参数）。
5. **补齐 §2.1 需要的四种行**：系统提示词、上下文注入（三行，生产者各一个）、
   斜杠命令卡、压缩卡 —— 没有它们，"上下文注入算助手侧 / 系统提示词不算 /
   命令卡与压缩卡不拿头"这三条在原型里根本看不见。
6. **运行中的一轮由发送流程创建**：`beginTurn()` 建组（用户消息 + 思考行 + 工具卡 + 流式正文），
   **不画组头、不可折**；`finishTurn()` 补 `data-closed` 与组头。发送后的 1.4 秒定时器与
   `PROTO.finishTurn()` **调同一个函数** —— 验证脚本不必等动画，也不会走另一条路。
   定时器带着**自己那一轮**的引用，且这一轮已收口时什么都不做：否则迟到的定时器会收掉
   **下一轮**的运行指示，或者把「已停止」改写成完整回答。**打断也是收口**（`stopTurn()`：
   组头说「已停止」、不摆计数，照 DSH 的 `message.stopped` 与落地端 `statsWith` 的 stopped 档）——
   不收的话那一组永远停在"运行中"的样子。
7. **设置页补「工作步骤收起时机」**（`回答结束后` 默认 / `下次有新消息时`）：一行 + 一个
   sheet，文案与落地端 `CollapseTiming` 逐字一致；行为是 `next-input` 只让**最后一组**
   保持展开（判据是"是不是最后一组"，不是"最后一个可折的轮"），手动点过则听用户的（三档优先）。
8. **审批 / 提问 / 计划回执并进最后一组**（`appendItem()`，插在组头之前）：
   它们属于当前这一轮。原来顶层 `append` 会让它们成为"没有轮号的散条"。
9. **顺手修掉统计条那一句**：`setRunning(false)` 原先把第一格写成 `第 1 轮 · 3 步`，
   与 DSH 的 `stats.counts`（**没有「第」**）冲突、而且同一句在 `index.html` 与 `app.js`
   各写一遍。改成**记住初值、结束后还原**。

## 代价与边界

- **原型第一次依赖 `app/` 的资产**（鲸鱼 PNG）。单独把 `mock/proto` 拷出去会缺头像；
  现状原型本来就在仓内跑，收益是"品牌图只有一份"。
- **新增过程类条目必须带 `data-proc`**，否则不会被收起（脚本会红）。这是有意的：
  标记就是清单，少一处就少一条。
- **`next-input` 的手动展开不落盘**：关页面回默认（与落地端"关 App 回默认"同一条）。
- **回执按"当前最后一组"归属**：原型没有"哪一轮问的"这条数据；真机上回执带自己的轮号。
- **演示数据是四条**（未归属组 + 第 1/2/3 轮）加发送产生的第 4/5 轮；第 2 轮只有一条思考行
  作为过程，用来说明"过程收起、待办留下"。
- **没有做**：滚动位置保持（§7 的已知边界，仍在 App 侧）、阶段 2「语义过程组」（已定案不做）。

## 判据

- `node mock/proto/tools/verify-turns.mjs` —— **60 项**全绿（headless CDP，0 个真机回合）。
- **变异校验**（各跑一次、当场撤回）：
  - 去掉第 1 轮工具卡的 `data-proc` → **2 项红**（"收起时工具卡不在" / "再点收起:工具卡不在"），
    其余 58 绿。**这次变异先暴露了断言本身的弱点**：原来用 `.tool[data-proc]` 选元素，
    去掉标记后选择器落空、`!vis(null)` 恒真 —— 已改成按组件类选，再变异才红。
  - `next-input` 的判据从"最后一组"改成"第一组" → **2 项红**
    （"最新一轮(第 4 轮)默认展开" / "收口后第 5 轮是最新一组 ⇒ 展开"）。
- 门禁：icons 100 / tool-paths **23**（新增脚本进扫描集）/ verify-proto 31 / settings 28
  （通用页行数 11 → 12）/ authz 18 / tasks 53 / drawer 25 / picker / subs 41 /
  **turns 60** —— 全绿；`node --check app.js` 与 `interactions.js` 通过；
  `styles.css` 的 `{` 与 `}` 计数相等（714 / 714）。

## 被否掉的替代

- **把整个消息流改成数据驱动渲染**（像 `renderSubs` 那样从模型生成）
  - 最强理由：助手头落点、折叠与组头都能"算"出来，不必在 HTML 里手写位置。
  - 为何被否：`#sampleCode` / `#codeWrap` / 长按绑定 / 文件预览入口都挂在静态标记里，
    整段搬进模板字符串是把"内容"与"结构"一起搬家；收益只是"看起来更一致"，
    风险是这一轮最贵的东西（既有门禁）全都要重跑一遍。
- **用 `hidden` 属性折叠**
  - 最强理由：语义直白，`hidden` 本来就该藏。
  - 为何被否：组件级 `display:flex` 会盖掉 `[hidden]`（本仓已踩过两次），
    要写一串 `[hidden]{display:none!important}`；一个类 + 一条规则只表达一次。
- **组头挪到轮次开头**（照 DSH 的 `processControl`）
  - 最强理由：与 Web 完全一致，折叠开关在它控制的内容上方。
  - 为何被否：上一轮已定案（`turn-groups.md` §4）—— 这一行同时是 turn-tail（复制 + 用量），
    另开一行会有两条 `第 N 轮`。这一轮不重开已定案的事。
- **让验证脚本真实等 1.4 秒看运行中 → 收口**
  - 最强理由：完全走用户路径，不暴露测试缝。
  - 为何被否：时序断言会随机器忙闲漂（本仓已有"心跳 40ms 的用例随机变红"的先例）；
    暴露 `PROTO.finishTurn()` 且与定时器共用同一个函数，既确定又不走第二条路。
- **回执继续顶层追加**
  - 最强理由：不动 `interactions.js` 的三处节点。
  - 为何被否：顶层节点不属于任何组，等于把它们当"未归属组"——而"未归属"的语义是
    "历史窗口没加载到这一轮的起点"，不是"回执"。语义错了，脚本也就没法断言。
