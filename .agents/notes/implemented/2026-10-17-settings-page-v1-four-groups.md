# Agent Note: 设置页第一版落四组（通用 / 模型 / 连接方式 / 关于），纯 UI 偏好改存手机本地

Status: implemented

## Problem

设置页此前只有「连接方式」一组。`docs/settings-porting-notes.md` §10 定的
第一版是 5 组，其余组要么需要新连接器方法（账号 / 内置插件 / Agent 预设），
要么只是占位。

真机反馈（2026-10-17）："还有设置中需要对接的也对接上"。

## Decision

1. **落地判据 = 这一行点了真的有作用**。本版四组：
   - **通用**：工作步骤展示（四档，直接控制工具卡默认展开）、性能与用量
     （二档，直接控制统计 pill 的简洁/详细）、繁忙时发送（就是输入区那个
     二选一，同一状态两个入口，与 DSH 桌面放设置页一致）。三项全部
     **落手机本地**（`meta` 表，与发送模式同一条路）。
   - **模型**：只读。当前模型与 provider 目录来自电脑侧真值；**拉取失败的
     provider 列出来**（`modelCatalog.failures`）。
   - **连接方式**：端点选择器（原有）。
   - **关于与连接**：App 版本（`--dart-define` 注入，没注入显示 `dev`，
     不猜版本号）+ 连接状态。
2. **账号 / 内置插件 / Agent 预设不进本版**：三者都要先扩连接器方法面
   （`settings.describe` 之外的账号/插件/预设查询今天都不存在），
   摆一行点下去只弹"还没做"的假入口比没有这一行更糟（项目硬规则）。
   原型里有那三组（交互基线），app 侧按 §10 分批。
3. **三项通用偏好存本地是有意偏离 DSH**：DSH 把它们存在电脑上
   （Host user-settings，`settings-porting-notes.md` §7.1 逐条列了出处）
   为的是跨浏览器跟随；手机只有自己看，下发既无意义也会互相覆盖。
   偏离写在设置页的小字里，避免以后有人"修"成同步。
4. **`_toast` 拆成两个助手**：原来所有 SnackBar 都被缀上"还没接上数据"——
   于是"已切到 deepseek-chat"在界面上变成"已切到 deepseek-chat 还没接上
   数据"，一句谎话（它确实切了）。结论与未接线从此分开说。

## Alternatives considered（否掉的）

- **把六组全摆上，未实现的摆占位行**：项目规则明确禁止（假入口比没有更糟），
   且真机上用户已经为"点了没反应"骂过。
- **偏好下发到电脑**（`settings.update`）：契约有这两个方法但本期未接；
   且 UI 偏好下发会覆盖电脑上的设置，与 §7.1 的结论冲突。
- **外观/语言也搬**：浅色主题与 i18n 是独立两块（主题层今天只有深色），
   搬一半等于摆一个切了不动的开关。

## Consequences

- 收益：设置页四组全部有真实作用；偏好重启后恢复；版本/连接状态可查。
- 代价：`AppModel` 多两个偏好键与恢复路径；统计条与工具卡的渲染多两个
   偏好输入（`_autoOpenToolDetail` / compact pill）；设置页测试要从
   "只有连接方式"改成先滚动再点（页面变长，ListView 懒加载）。
- `_ModelSection` 的 failures 行是 `modelCatalog` 解析真形状后的直接收益。
