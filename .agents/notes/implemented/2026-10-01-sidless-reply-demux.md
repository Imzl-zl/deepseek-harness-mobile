# Agent Note: 无 `sid` 回帧无法在中继处解复用 —— 一个协议层的缺口

Status: **已解决**（按出路 1 落地：回帧回显请求的 `id`。结论见下，诊断过程保留）

## 结论与落地

在 `handshake-driver.ts` 里把 `hello-ack` 的 `id` 从 `newFrameId()` 改成 **`frame.id`**（回显请求），
并在契约 §3 写明这条规则（`pair-ack` 一直就是这么做的）。**握手随即经中继成立**，
带密钥的三方链路用例从"卡在握手"变成**通过**（真签名 + 真 transcript + 真 AEAD 双向）。

两处顺带确认的事实：

- **`id` 不参与 transcript**（`transcriptFromFields` 只拼 `box` 里的字段）⇒ 改它**不影响签名**，
  **不必重生成 protocol 向量**（那三条门禁 486/49/26 改完全绿）。
- 测试里设备的第一条业务帧原本带 `sid: 'sid_1'` —— 那是**测试的形状错了**：生产里请求帧
  **不带 `sid`**（`sid` 由 `params` 携带），靠"设备→绑定的连接器"这条无 `sid` 路由走；
  带 `sid` 的是**事件帧**（`ev`/`live`），由连接器发出，中继的归属表也正是在那时学到的。
  改掉之后一次通过。

## 现象与证据

带密钥的三方链路跑到"连接器握手成立"时超时。开 `DSH_RELAY_DEBUG=1` 后，中继的逐帧留声给出：

```
[relay:debug] 配对登记：hash-key… → conn-1
[relay:debug] 已发票给设备 dev-1（1 张待用）
[relay]        设备 dev-1 换到票，绑定连接器 conn-1
[relay:debug] 中转丢弃一帧：hello-ack 找不到对应设备 { requestId: '-dvrTwpBbOjOLSiVTsdHvg' }
```

也就是说：设备发的 `hello` **到了连接器**（没有丢弃日志）、连接器**回了** `hello-ack`，
而中继**认不出这条回帧该给谁**。

## 根因：两端的 `id` 不是同一个

设备那一帧的 `id` 是我在测试里写的 `'h1'`；而连接器回的 `hello-ack` 带的是
`-dvrTwpBbOjOLSiVTsdHvg`（22 字符 = 16 字节 base64url）——**电脑侧自己生成的 id**。

中继第 47 轮那条规则（无 `sid` 的帧按 `id` 关联回程）因此**只对"回显请求 id"的帧成立**：
- 配对帧满足它（手机发的 `pair` 与电脑回的 `pair-ack` 用的是同一个 id ✓ 实测通过）；
- **握手帧不满足**（`hello` 与 `hello-ack` 各带各的 id）。

这不是实现 bug，而是**规格缺口**：一条帧要能被中继投递，必须有一个"中继可用来定向的字段"，
而当前握手帧里没有这样的字段（连接在直连拓扑下是唯一的，所以直连时不需要它；
一旦中间有中继，且**一台电脑同时服务多台设备**，就必须有）。

## 三条出路（需要定夺）

1. **回帧回显请求的 `id`**（把 `id` 定义成"请求/应答的关联标记"，两端都遵守）
   - 影响：契约 §3/§4.1 要写明；连接器的握手驱动器要改成回显 `hello` 的 `id`；
     手机端实现照此办。手机端还没写，所以只有连接器一处要改。
   - 代价：握手帧的 `id` 语义变了（现在是"各自生成"）；protocol 的 fixtures/向量可能要跟着动
     （那部分有逐字节断言，改动要重新生成向量）。
   - 好处：中继的规则保持**一条**（"无 `sid` 就按 `id` 回程"），与配对帧同形。
2. **中继为每条设备连接维护"待回程"槽位**（设备发过无 `sid` 帧 → 把它记成该连接器当前的
   "握手对象"；连接器的无 `sid` 帧投给这个槽位）
   - 影响：只动中继（`core.ts`），规格只需提一句。
   - 代价：**一台电脑同时与两台设备握手时会串**（后一台覆盖前一台的槽位）。
     概率低但**后果是"握手材料发给错误的设备"**，而那正是授权边界附近的东西。
3. **让设备侧的第一跳也有 `sid`**（例如设备升级时就带上它要操作的目标会话）
   - 影响：手机在握手前必须已经知道要操作哪个会话 —— 而握手发生在**任何会话打开之前**
     （第 47 轮的笔记里已否过一次"给无 `sid` 帧伪造 `sid`"）。
   - 代价：把"连接级"的握手绑到"会话级"的地址上，语义上不成立。

**我的建议是 1**：它保住"中继只有一条判据"，并且与配对帧的形状一致；
代价是握手帧的 `id` 语义要在契约里写明、连接器侧改一处、向量可能要重生成。
**但这是一次协议变更，需要你定夺**——我不擅自改握手帧的线上语义。

## 已经排除的（本轮之前）

  说明"带 `sid` 的帧两向都对"；缺的只是**无 `sid` 回帧**这一条。
