# Agent Note: 首配秘密与中转路由分离，数据连接按设备隔离

## Problem

中转登记并转发的 `codeHash` 同时被电脑当作授权凭据，拥有该哈希就能提交任意设备公钥；SAS 在设备写入后才显示，无法充当授权门。连接器同时用一条加密连接承载多台手机，握手进度、密钥与计数器的生命周期不匹配，连同一台手机重新握手也会被当作重放。

## Decision

公开邀请 `offerId` 与二维码秘密独立。候选通过扫码固定的电脑身份建立受限加密通道，用户确认后才在密文里提交秘密，电脑校验后登记设备，长期令牌同样经密文返回。候选公钥只住在独立连接作用域，握手成功不等于业务授权。

先落实每设备独立数据连接与单独控制面，复用现有握手、封箱、连接和订阅原语；移除按请求 ID 猜设备的回程机制。旧明文首配明确拒绝，正常已配对设备的业务握手不做无理由迁移。

用户选择的后续单控范围仅为远程设备之间；电脑本地不纳入互斥。该控制租约与本次配对身份认证是不同的边界。

## Alternatives considered

- 再散列一次 `codeHash`：验证端若接受中转已知值，仍是同一个 bearer 漏洞。
- 只把 SAS 确认按钮往前挪：没有端到端秘密验证，不能满足中转不可信的威胁模型。
- 删除 E2EE 或让中转签发设备身份：改变安全目标，不接受。
- 首配复制一套密码算法或自造多路复用流：增加独立协议实现与密钥状态，复用已有原语更可验证。

## Consequences

代价是明确区分候选、已认证配对通道和正式设备，升级首配载荷与相关测试；收益是中转不再持有授权秘密，多设备的密钥和连接生命周期互不污染。待配对连接必须有限额与超时，回执丢失必须表达结果待确认，不能伪称已经回滚。
