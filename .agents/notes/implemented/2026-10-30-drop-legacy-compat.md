# Agent Note: 不做旧数据/旧客户端兼容（协议未发版）

Status: implemented

用户 2026-10-30 定调：**这套协议还没发版、没有存量安装，不要为了"旧版本"留兼容分支。**
本笔记记录这次删掉了哪些，以及为什么它们原本存在。

## Problem

前三步与第 4 步的路上，为了让"升级"不炸，陆续留下了四条**旧形状兼容**：

1. 中转控制面：不带 `?id=` 的连接器放行（第 4 步新增，注释写"下个 minor 删"）；
2. `PairingStore`：首次读取时把升级前的平铺键 `dsh.<field>` 一次性搬进槽并删旧键；
3. `UiStateStore`：拿到电脑身份后把平铺 `host.<field>` 一次性搬进 `host.<hostId>.*`；
4. 端点元数据（`remembered` / `hidden` / `succeeded`）：读时按"开头是 `ws[s]://`"把裸 url
   补成 `hostId|url`。

它们各自都带着一条"读时迁移 + 判据是写次数"的测试，看起来是严谨的。代价却是：
每一处都有**两种形状**要判，而"新形状"与"旧形状"只要有一处判反（第 2 步就真的踩过：
判别写成"值里含 `://`"，而新 id 里也有 —— 症状是 `host|host|url`），问题会静默很久。

## Decision

四条一起删，按"当前只有一种形状"重写读取路径：

| 位置 | 现在 |
|---|---|
| `relay/src/server.ts` 控制面 | `?id=` **必带**且必须等于令牌 id，否则 403 |
| `PairingStore.load()` | 只看 `hostId ?? active`；没有就是 `null`，**不迁移、不删旧键** |
| `UiStateStore.open()` | 只读当前桶；平铺键只代表"状态不属于某台电脑"，**不搬进桶** |
| `PairingStore._decodeEndpointMeta` | 三份集合原样用（`Endpoint.id` 恒为 `hostId\|url`） |

**"不删旧键"是刻意的**：不认识的键不属于这个版本的东西，顺手删掉等于在没有迁移的地方
做半个迁移（删了却读不出来）—— 那是比"留着"更差的状态。要清就清整个存储
（`clearAll()` / 卸载重装）。

## Alternatives considered

1. **保留四条，标注"下个 minor 删"**
   - 最强的理由：发版后用户升级不丢配对与草稿。
   - 为何被否：现在没有发版，也就没有"升级用户"；这些分支的存在只会在**当前**制造
     第二种形状（第 2 步已经因此踩过一次 `host|host|url`）。
2. **只删中转那条（它影响面最小），App 侧迁移留着**
   - 最强的理由：迁移测试已经把"写次数"钉住了，风险可控。
   - 为何被否：用户的口径是"都不兼容"；而且 `UiStateStore` 的平铺键本来就还有
     "未配对时"这一合法用途，留着迁移会让同一组键有两种含义（旧数据 vs 没身份）。
3. **迁移代码保留但默认关（开关打开才跑）**
   - 最强的理由：将来真要发版时一键恢复。
   - 为何被否：一个没人跑的迁移分支等于死代码 + 它会继续要求读取路径容忍两种形状；
     真要迁移时按当时的形状重写比复活一段没被跑过的旧代码更可靠。

## Consequences

- 收益：凭据、UI 状态、端点元数据、控制面 URL 各只剩**一种**形状；读取路径不再有
  "判别开头/前缀"这类会判反的代码。
- 收益：`UiStateStore.open()` 与 `PairingStore.load()` 不再写盘/删键，判据从"写次数"
  变成"根本不写"。
- 代价：**装着旧版本 App / 旧连接器的环境升级后读不到旧数据**（配对要重扫、草稿/页签
  与端点记忆丢失）。当前没有这种环境；若真出现，按当时的形状重写迁移。
- 代价：契约与文档里"迁移幂等"那几条要一起改（`remote-channel` §4.1、`connector-and-relay`
  §1.6、`app-channel-client` §6.3、`ui-state` §2 已同批更新）。
- 未覆盖：`ItemStore` 自己的 schema 迁移（`storeDataMigrations[1]`）没动 —— 那是本地库
  的版本机制（`schema.data_version`），不是"旧版本协议"的兼容；它保留着将来真要发版时的钩子。
