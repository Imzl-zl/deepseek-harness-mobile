# Agent Note: 管理台自己签发令牌 + 连续失败锁定

Status: implemented

## Problem

两件事，都在 2026-11-03 真机上撞到：

1. **管理员加不了电脑**。管理台「我的电脑 / 添加我的电脑」指向 `/console`，而控制台的准入是
   **用户会话 cookie**；break-glass 管理员（`--issue-admin` 签的令牌存在 sessionStorage 里）
   没有 cookie，点过去被静默 302 到 `/login`（用户原话：「什么鬼」）。
   管理台此前只做吊销/恢复/删除，**签发只在控制台与 CLI**。
2. **登录/管理面没有"猜错就停"**。只有限流（`rate-limit.ts` 的令牌桶）：
   桶里还有令牌就放行，猜错一百次也只是变慢。管理面 `/admin/api/*` 认证失败按地址分桶限流，
   但同样不阻断 —— 爆破只需要比限流慢一点。

## Decision

1. **`POST /admin/api/tokens/issue`**：管理员直接签一张连接器令牌。
   - 入参 `{ id, name? }`；`id` 就是连接器控制面自报的 `?id=`（默认 `local`，
     `connector/src/index.ts` 的 `DEFAULT_CONNECTOR_ID`），形状 `^[a-z][a-z0-9-]{0,63}$`。
   - **同 id 已有活跃令牌 → 409 `token-exists`**：落盘按 `(kind,id)` 替换，静默换掉一张正在用的
     令牌等于让那台电脑当场失联。要轮换先吊销。
   - 明文**只在应答里出现一次**：内存表与配置文件都只收摘要，审计日志只记 id。
   - 面板：令牌页多一个「添加我的电脑」（id 预填 `local` + 备注名），签完把令牌显示在视图里
     （不是一次性 DOM —— 2 秒轮询会重画这一页），点「已复制，收起」消失。
2. **连续失败锁定**（`relay/src/lockout.ts`）：按来源地址数**连续失败**次数，
   连错 **5** 次锁 **15 分钟**，成功一次清零。
   - 管理面认证失败（`/admin/api/*` 的 401）与登录页的 `bad-credentials` **共用一份计数**：
     爆破方不会挑门。
   - **锁定期内连正确的密码/令牌也不放行** —— 否则每 N 次能试一次，锁定等于没设。
   - **到期自动放行，且计数从零开始**：一次手误不该把人永远锁在门外（这条与"递增惩罚"相反，
     是有意的）。
   - 配置 `lockout: { failures, cooldownMs }`；`failures: 0` = 关闭。

## Alternatives considered

1. **管理员加电脑仍走用户控制台**（原设计，2026-11-02 的决定）
   - 最强的理由：一套流程、一处真值 —— 电脑归属总是某个账号，管理员不该有第二套。
   - 为何被否：break-glass 管理员没有账号，这条路对他是死的；而"静默跳登录页"把
     "设计如此"伪装成"坏了"。要保留原设计就得先让管理台能建账号会话，那是更大的事。
     现在两条路并存：管理台签**未归属**令牌（不绑定账号），控制台签**归属**令牌。
2. **同 id 直接替换（轮换）**
   - 最强的理由：少一次吊销操作。
   - 为何被否：替换是静默的破坏性动作 —— 在用的那台电脑会当场失联而面板上没有任何提示。
3. **永久封禁 IP**
   - 最强的理由：最省事，也最"安全"。
   - 为何被否：配置在服务器上，"在外面输错五次"就等于"回家改配置才能进门"。
     冷却到期自动放行，代价只是爆破速率被压到 5 次 / 15 分钟。
4. **锁定也告诉对方还剩几次**
   - 最强的理由：对正常用户更友好。
   - 为何被否：那是给爆破方的进度条。锁上之前一律回 401。

## Consequences

- 收益：管理员不用再登录成用户就能加电脑；爆破被压到 5 次 / 15 分钟，且两个入口共用计数。
- 代价：`AdminOps` 多一个 `issueToken`；内存表与配置的写入顺序是"先内存、后落盘"，
  半途失败会留下一张"能用但重启后消失"的令牌（与吊销/恢复同一条顺序，没有更好的一侧）。
- 代价：锁定按 `remoteAddress` 算。反代（Caddy）后面所有请求的来源地址都是反代自己 ——
  要按真实 IP 分桶得先配信任边界，那是部署的事，这次没做。
- 代价：管理员签的是**未归属**令牌（没有 `userId`），所以它不占某个账号的电脑额度；
  用量面板里会落进「未归属主体」那一栏。

## 判据

- relay `pnpm typecheck` → 0；`node --test` → **158 条全绿**
  （新增 6 条：锁定 5 条 —— 连错 5 次就锁 / 成功清零 / 冷却到期从零重数 / `failures:0` 关闭 /
  按地址分桶；签发 1 条 —— 活跃 id 409、新 id 200 且明文只回一次、审计里没有明文、形状不对 400）。

  「重连中」变「已连接」。
