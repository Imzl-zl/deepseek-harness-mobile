# Agent Note: 中转的准入门是账号 + 首连绑定，不是"手机登录"

Status: implemented

## Problem

公开中转的 `POST /connector/enroll` 在 `connectorAuth: "open"` 下**不认证就发令牌**：
任何人拿到地址就能当一台电脑连上来，匿名占用带宽与连接。令牌里只有一个可选字符串
`owner`，它不是账号——没有"停用一个人、断他所有连接"的手段，也没有"这个人最多几台电脑"
的判据。每台电脑本来就只服务一台手机（1:1），所以限手机数并不减少带宽；真正的杠杆是
**电脑数与月流量**。旧 UI 只有 break-glass 管理令牌，没有用户登录、注册与控制台。

## Decision

账号只落在"谁拥有电脑、能用多少流量"这一层；**手机不登录**，设备身份仍由电脑侧签发。
登录用户创建电脑令牌，令牌第一次连上时绑定 `?id=<pcId>`；账号默认 2 台电脑、5 GiB/月，
注册默认只允许 `qq.com` 邮箱。

准入条件（可机械判定）：

1. `auth` 段存在 ⇒ `connectorAuth` 必须是 `"required"`；写成 `"open"` **启动失败**。
2. 控制台建令牌必须已登录，且该账号未吊销令牌数 `< maxConnectors`；超限回 409 `connector-limit`。
3. 新令牌 id 是随机的 `tk_…`；第一次 `/ws/connector?id=pcId` 写入 `connectorId`，之后不一致 403。
4. 注册邮箱必须过 `emailProblem`（当前只允许 `qq.com`），验证码 6 位 / 10 分钟 / 5 次尝试，
   密码 scrypt（N=16384）；登录失败统一 `bad-credentials`。
5. 账号 `status !== "active"` ⇒ 新的控制面/数据面升级 403；已有连接由 `closeUser` 立刻收掉。
6. 额度主体是 `user:<id>`，上限优先读 `users.quota_bytes`（`null` = 不限），其次配置。

## Alternatives considered

1. **设备码（device code）绑定电脑**：电脑显示 4 位码，用户登录后批准，令牌自动写回连接器。
   - 最强的理由：用户完全不用复制令牌，绑定天然可信；这是 `gh auth login` 那一类最顺的 UX。
   - 为何被否：要改 connector 的 `enroll`、面板显示与轮询，本轮目标是先把公开准入关上；
     首连绑定用**零连接器改动**达到同一安全边界。设备码留作后续 UX 升级，不影响这套账号模型。
2. **账号直接写 `relay.config.json`**：不引数据库，沿用现有配置与 CLI。
   - 最强的理由：零新存储、零迁移，和令牌摘要表同一份文件，备份简单。
   - 为何被否：公开注册会把"登录一次"变成整份凭据表重写；没有查询/索引，管理台按邮箱找人与
     分页都要全表扫；密码摘要与令牌摘要混在一个文件，权限与备份边界也混。
3. **手机 App 也登录**：一个账号统一电脑与手机。
   - 最强的理由：产品叙事完整，"所有设备都在一个账号下"。
   - 为何被否：设备身份已经由配对 v2 的电脑侧签发；再加一层登录会出现两套"谁能连"的判据，
     扫码即用的路径被破坏，手机端还要新增登录 UI 与凭据存储。账号只做额度与电脑归属就够了。
4. **限制手机数而不是电脑数**：像流媒体"同时几台设备"。
   - 最强的理由：直观，用户容易理解；也确实能限制账号共享。
   - 为何被否：中转每台电脑本来就只服务一台手机（1:1），手机数不改变带宽；账号共享的带宽
     上限仍由电脑数 + 月流量决定。限手机只会增加"去电脑上删设备"的运维负担。
5. **只保留 break-glass 管理令牌**：零账号代码，最快。
   - 最强的理由：现有实现已经能发/吊销令牌，改动面最小。
   - 为何被否：令牌无法让普通用户自助建电脑；公开中转仍要人工发令牌，运维不可持续，也没有
     "停用一个人"的语义。
6. **JWT 代替服务端会话**：无状态，代码短。
   - 最强的理由：不查库、水平扩展容易。
   - 为何被否：吊销与"改密码踢其它设备"要立刻生效；服务端会话只多一张 `sessions` 表，
     换来可撤销与可列出。

## Consequences

- 收益：匿名兑换关闭；每账号电脑数与月流量可执行；停用账号立刻断线；登录/注册/控制台/管理台
  成为一套完整产品；旧配置不写 `auth` 时行为完全不变；旧令牌不失效。
- 代价：多一个 SQLite 库与 schema 迁移（`node:sqlite` 仍标 experimental，启动会打一行 warning）；
  令牌仍在配置文件，账号与令牌是两个存储，CLI 与面板同时写 `tokens` 仍有跨进程竞争；
  旧令牌不归属任何账号，管理台不能一键认领；没有 Linux.do、邀请码、邮箱换绑、用户自删；
  验证码只在内存，重启失效；限流与会话都是单实例语义。
