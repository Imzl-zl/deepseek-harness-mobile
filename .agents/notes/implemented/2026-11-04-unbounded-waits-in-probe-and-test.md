# 无界的等待，就是把"环境问题"伪装成"产品问题"

- 日期：2026-11-04
- 触发：评审 + 本机复现（机器没装 Dart，跨语言用例真的等满 180 秒）
- 状态：implemented

## 背景

两处等待都没有上界，且**失败时的表现都是错的**：

1. **跨语言用例**（`connector/tests/cross-language-handshake.test.ts`）：`spawn` 用了
   `shell: true`（Windows 上 `dart` 是 `.bat` shim，Node 不许直接 spawn）。
   找不到 `dart` 时 shell 自己起得来、然后以非零码退出 —— **`error` 事件不会触发**，
   而 `readLine()` 只挂了 180 秒的超时定时器。于是"这台机器没装 SDK"表现为
   "3 分钟后一条用例报超时"，看起来像两边实现不一致。
2. **局域网地址探针**（`connector/src/lan-address.ts`）：`dgram.connect` 只给了
   回调与 `error` 两条出路。都不发生时 Promise 永挂，而它坐在**启动路径**上
   （出码、端点自报）—— 症状会是"局域网功能像没做"，比"拿不到地址"难查得多。

## 决定

1. 用例先探活 `dart --version`：**判据是退出码**，没装就 `t.skip`；同时给 `startProbe`
   补 `close` / `error`，挂起中的读立刻失败。
2. 探针加 500ms 兜底，超时与"没有默认路由"走同一条退路：回 `null`。

## 被否掉的

- **只补子进程退出监听、不加探活**：找不到 `dart` 会变成"用例红"。那把一个环境问题
  报成实现不一致 —— 而这正是本仓反复强调"判据要能区分'没命中'与'没实现'"的反面。
- **用 stderr 文案判断"没装 dart"**：随系统语言变（中文 Windows 写「不是内部或外部命令」，
  Linux 写 `not found`）。退出码是唯一稳定判据。
- **把 180 秒调小**：真跑起来第一次要编译 + 跑 build hooks，调小会让 CI 偶发红。
  问题不在阈值大小，在"该失败的时候没失败"。
- **局域网那条不加超时**（按 AGENTS「不新增宿主没有的边界」）：这一档是在补**我们自己探针**
  的漏洞，删掉它宿主也不会给出答案；而超时的后果是"退回配置里的地址"，
  与"拿不到默认路由"是同一条降级路径，不是替宿主做决定。

## 代价

- 探活多一次进程（约 50–100ms，模块加载期一次）。
- 500ms 上限在极端负载下可能把一次合法选路判成"拿不到"：二维码少一个 `lan` 候选，
  配对走中转 —— 这是 11-03 第六批已有的降级路径（`pairing-without-relay.md`），不是失败。
- **局域网那一档没有可判定的用例**：正常机器上超时分支不可达，写一条"500ms 内返回"的断言
  是恒真的假门禁（变异校验时它不会红）。所以它只有退化环境能验，这里如实记下。

## 验证

- **无 Dart 本机**（把 Flutter 从 `PATH` 摘掉）：用例从"等 180 秒后红"变成 **0.63ms 跳过**
  （`skipped 1`）。
- **变异校验（模拟"装了 SDK 但探针起不来"：把 `DART_AVAILABLE` 强制成 `true`）**：
  **26.8ms** 失败，报的是 shell 的原话 `'dart' is not recognized as an internal or external command`，
  不再是 180 秒超时；还原 → 跳过。
- `connector`：`tsc --noEmit` 0、`pnpm test` **845 条**
  （本机有 Dart 时 845 绿；没有 Dart 时 844 绿 + 1 跳过 —— 跳过的那条就是本用例）。
