# Agent Note: 空态把"没配对"与"连不上"分开说（真机把排查方向整个带反过）

Status: implemented

> **2026-10-26 晚勘误**：本文「顺带查清的一件事」最初的结论是错的
> （把"首次安装"判成"被重装清数据"）。已按实测修正，过程留在那一节里 ——
> 那条错结论也曾写进当次的 commit message，一并在此作废。

## Problem

2026-10-26 真机（公司网络）看到：手机显示 **"还没连电脑"**，而电脑侧的
设备名册里明明有这台手机（6 条已登记）、DSH 也在 `0.0.0.0:8790` 监听。

用户读这句话会理解成"我从没配对过"，于是去点「连电脑（配对）」——
那要**电脑重新出码**。而真正该先试的是顶栏状态点里的「重新连接」
（电脑换过网络/重启过，地址变了，凭据还有效）。

**排查方向整个反了**：一次本该 10 秒解决的重连，被引向一趟重新扫码。

## 根因：文案与 `paired` 的实际含义不符

`_EmptyChat` 的第一支判据是 `!paired`，而 `paired` 来自
`_credentials != null`（`main.dart:412`）—— 它的实际含义是
**"手里有配对凭据"**，不是"连上了"。

所以那一支的准确说法是"还没配对"。旧文案"还没连电脑"把
"没有凭据"说成了"没连上"，而后者在中文里更常指"配过但连不上"。

## Decision

### 1. 第一支改成"还没配对"

```dart
!paired ? ('globe', '还没配对', '界面可以先看。要看到真实会话，先在电脑上出码，再扫一次。')
```

### 2. `disconnected` 支的兜底文案给**明确动作**

原来是"连上之后，会话列表会自动出现。"—— 一句正确的废话。
改成指向具体那一行：

```dart
connectionNote ?? error ?? '换过网络或电脑重启过？先试顶栏状态点里的「重新连接」。'
```

`connectionNote` 优先（它是 `connectionSummary` 的 note，如
"N 个端点都拨不通（电脑可能不在线，或换了网络地址）"—— 那句更具体），
没有诊断时才用这句兜底。

## Alternatives considered（否掉的）

- **把"重新连接"按钮直接放进空态**（不用去顶栏点）：空态已经有
  「打开会话抽屉」+「重新配对」两个钮，再加一个是三个。而顶栏状态点
  一直是重连的入口（`connection_actions_sheet.dart`），指过去比再造一个近。
- **自动判断"该重连还是该重配对"**（凭据在但电脑侧名册里没有 ⇒ 建议重配对）：
  那要一次额外的往返，而且电脑侧名册手机看不到。否。
- **把 `paired` 改名成 `hasCredentials`**：更准确，但要动 6 个文件与
  全部测试。文案改对就够，命名留着（`main.dart:412` 的注释已说明它的含义）。

## Consequences

- 收益：有凭据但连不上时，用户被引向「重新连接」而不是重新扫码。
- 代价：三个测试断言的字句更新（它们守的是"四支分开说"这条规则，
  不是具体字句 —— 已在用例名里写明为什么改）。
- 测试：`chat_empty_state_test.dart` 两支、`widget_test.dart` 一支更新。
  `flutter test 810` 全绿。
- **这条不修"连不上"本身**：它只修"连不上时告诉用户该干什么"。

## 顺带查清的一件事（与代码无关，但值得记）

真机上"要重新配对"的原因，**我第一次判错了，记下修正过程**：

**错的判断**：看到 `dumpsys package` 里 `firstInstallTime == lastUpdateTime`
（都是 18:57:02），认定"App 被完整重装、凭据被清空"。

**修正**：又装了一次（`adb install -r`）之后看 ——
`firstInstallTime` **仍是 18:57:02**，只有 `lastUpdateTime` 变成 19:35:41。
说明 **`adb install -r` 确实保住首次安装时间**（`tools.md:96` 那条是对的），
而 18:57 那次是**这一版 App 首次装到这台手机上**——它从没在这台机上配对过
（家里那次配对的是更早的装包）。

**教训**：`firstInstallTime == lastUpdateTime` 只说明"这是首次安装"，
**不说明"被重装清数据"**。要判断有没有被卸过，得跟**上一次装包时记下的**
`firstInstallTime` 比。我少了一步，就写出了个错的结论。
