# Agent Note: 「手机」面板：设备随时可删、中转是选项、确认框挂 body

Status: implemented

## Problem

DSH Web 侧边栏「手机」弹框（`connector/client.js`）的三个毛病，都是真机看到的：

1. **在用的那台设备没有「删除」**：活跃行只有「停用」，删除只出现在「已停用」里。
   用户原话：「连接的都不能删除？我就奇怪了那我想删除咋办？人家用户自己的东西，
   你凭啥不让人家删除」。
2. **中转地址是一张空输入框**：内置的那条（`wss://dsh.0t0.me/ws/connector`）要人背下来，
   换了自己的之后再也回不去。
3. **确认框会跑到看不见的地方**：遮罩 `position: absolute` 钉在面板 `.wrap` 上，清单很长时
   它定在**内容顶部** —— 用户滚下去点「停用」，框出现在上面被裁掉的位置。
   用户原话：「居然弹框在上面都被遮挡了？不是屏幕居中？？」

## Decision

1. **活跃行也给「删除」**，点下去是**先停用、再删除**两步（`removeActive`）：
   停用让那台手机立刻下线并拿到终态（`device-revoked`），随后抹掉记录。
   服务端的不变量（`device-admin.ts`：显式删除只作用在已停用的行上）**保持不变** ——
   省掉的是让用户自己先停用、再翻到「已停用」里去找。
2. **中转改成选择框**：内置 / 自定义；内置值只写在一个常量（`BUILTIN_RELAY_URL`）里，
   选中时地址以只读文字显示。**用分段按钮而不是原生 `<select>`** ——
   下拉弹层是浏览器画的、吃不到 DSH 的 token（深色下第二项几乎看不清），
   而且多一次点击。
3. **上报地址也能删**：自报地址的「删除」= `hide`（不再报给手机；网卡还在，所以可恢复），
   删掉的收进「已删除 N 条 · 展开」；手动追加的那类删掉 = `clear`（真从表态里清）。
4. **确认框 `createPortal` 挂到 `document.body` + `position: fixed`**（与主面板同一个做法），
   永远居中、不被任何滚动容器裁掉。
5. 顺手删掉三句复述性的小字（传输方式 / 上报地址 / 配对说明），并把卡片从"纯描边"
   换成 DSH 的图层底色 + 统一字号节奏（卡标题 13/600、分区标题 12 tertiary、
   表格头 11.5、行 12.5、按钮 12.5）。

准入门槛（可机械判定）：

1. 活跃行同时有「停用」与「删除」；点「删除」弹出的标题是
   `删除「{name}」？它现在还在用。`，后果句写明"先停用、再抹记录"。
2. 「中转」那一栏是**分段按钮**（内置 / 自定义），页面上没有 `<select>`；内置选中时
   不出现地址输入框，地址以文字形式显示 `wss://dsh.0t0.me/ws/connector`。
3. 确认框遮罩 `position: fixed`，且挂载点不在面板的滚动容器里（`createPortal` 到 body）。
4. 上报地址每行是「删除」（不是"禁用"）；点完那条从列表里消失，出现
   `已删除 N 条 · 展开`；手动追加的那类删掉走 `clear`。

6. **整体版式（方案 A，2026-11-01 落地）**：面板从"三个并列卡 + 一堆小字"改成
   **一条总览 + 四张卡**——总览条一行读完（中转状态 · 在线台数 · 直连端口）；
   「连接」卡头右挂保存键；「传输方式 + 上报地址」并成「通道与地址」一卡，
   批量启动/停止进卡头；设备卡头是 标题 + 台数 + 清空全部记录，**当前在服务那台标「本次」**；
   配对的出码键也进卡头。行级动作降噪：停用=中性描边、删除=红色描边、
   **实心红只留给确认框的确认键**。

## Alternatives considered

1. **保持"先停用 → 再在「已停用」里删除"**
   - 最强的理由：服务端不变量一条都不用动，手机一定能收到终态。
   - 为何被否：用户要的是"我的设备我能删"，两步还藏在折叠区里等于没有。现在由界面把两步
     合成一次点击，顺序仍然对。
2. **让服务端允许直接删活跃行（去掉 `refuseActive`）**
   - 最强的理由：最少的一次往返。
   - 为何被否：硬删会把撤销记录一起抹掉，那台手机只会拿到 `device-unknown` 并一直重试 ——
     用户看不到任何"我被移除了"。先停用这一步是**给手机的信号**，不是权限。
3. **确认框继续用 absolute、只把 `.wrap` 改成 `position: sticky`/滚到可见**
   - 最强的理由：不动定位语义，改一行。
   - 为何被否：只要面板里还有滚动容器，任何"相对内容"的定位都会在长清单里跑位。
     挂 body 是唯一与滚动无关的做法，而且主面板本来就这么干。

## Consequences

- 收益：任何一台设备都能一步删掉；中转不用记域名；确认框在哪儿点就在哪儿出现。
- 代价：删除活跃设备 = 停用 + 删除**两次写**（两次名册重发）；失败时两半的错都会落在
  面板顶部那一行提示里。
- 代价：删掉的那台手机下次只会看到 `device-unknown` 并重试到重新扫码 —— 与直接硬删同一个
  结局，无法避免（这是"名册里没有你"的固有语义）。
- 代价：`client.js` 又多了一处 `createPortal`；它不进 `pnpm build` 的类型检查，
  只能靠 `node --check` 与 `tests/client-panel.test.ts`。

## 判据

- connector **818 项**全绿；`tests/client-panel.test.ts` 改 4 条 + 新增 1 条（活跃行有删除、
  删除活跃行的对话框文案、已停用行按名字挑、两个遮罩都是 fixed、上报地址可删除并折叠）。
- `pnpm exec tsc --noEmit` 0、`pnpm build` 过、`node --check client.js` 过。
- 真机/真面板验证：在跑着的隔离 DSH（`127.0.0.1:3080`）刷新后，「中转」是选择框、
  设备行有「删除」、点「停用」的确认框在屏幕正中。
