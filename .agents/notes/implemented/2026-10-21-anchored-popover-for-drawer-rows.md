# Agent Note: 剩下两处「跟手」也改成锚定浮层 —— 以及为什么只有这三处

Status: implemented

## Problem

用户 2026-10-21 在真机上指出顶栏「切换子智能体」是"点在上面、弹在下面"，当天只改了一处，
另两处（顶栏连接状态点、抽屉会话行的长按菜单）在 `tools.md` 里登记为"同一类，未改"。
同一轮晚上用户又追问「这个 APP 还有多少这个种不跟手的操作习惯」，要求把剩下的清掉。

判据不变：**触发点矩形与面板矩形的距离**，不是"看起来还行"。

## Decision

**只改这两处，其余保持底部 sheet**：

| 触发点 | 位置 | 形态 | 为什么 |
|---|---|---|---|
| 子会话标题（切换子智能体） | 顶栏 y≈56dp | 锚定浮层 | 2026-10-21 已改，判据 `panel.top - crumb.bottom < 80` |
| **连接状态点** | 顶栏 y≈56dp | **锚定浮层**（本轮） | 与标题同一行、同一类视线；三个入口里只有它在上半屏 |
| **抽屉会话行「…」** | 抽屉列表里任意一行 | **锚定浮层**（本轮） | 长按的是**那一行**，菜单从底部升起来要跨半屏 |
| 空态「连电脑（配对）」 | 屏幕中部偏下 | 底部 sheet | 触发点本来就在下半屏，拇指够得着 |
| 抽屉连接行 | 抽屉上部 | 底部 sheet | 同上；而且它点开的是"连接操作"，与抽屉同层，弹底部 sheet 不会丢上下文 |
| 输入栏一侧（`＋`、模型、权限） | 屏幕底部 | 底部 sheet | 拇指区，锚定浮层会把手挡住的区域盖住 |

**锚点由触发控件自己量**：抽了 `dshAnchorOf(BuildContext)`（`ui/dsh_popover.dart`）——
`Builder` 拿自己的 `RenderBox`，坐标相对 overlay（全局坐标在有状态栏/键盘时会整体偏一段）。
顶栏那枚 38×38 的连接点用它，抽屉行也用它；两处共用一份实现，不再各写一遍 `localToGlobal`。

**菜单的触发从"长按"挪到行尾「…」**：长按要留给拖动排序（见
`2026-10-21-drawer-drag-and-counts.md`）。两个手势不能抢同一个动作 ——
Web 侧菜单是 hover 出的行内按钮，触屏上它必须常显。

## Alternatives considered

1. **给 `showConnectionActionsSheet` 加一个 `anchor` 参数，而不是新写一个浮层版**
   - 采纳的就是这个：内容只画一份，形态由 `anchor == null` 决定。
   - 代价：那个函数多了一个分支；收益是"重新配对"的入口不会分成两份文案。
2. **抽屉行菜单继续用长按，拖动改用行尾拖动手柄**
   - 最强的理由：长按菜单是 2026-10-21 刚做的，改触发方式会让已有肌肉记忆失效。
   - 为何被否：300dp 宽的抽屉里再放一条 24~44dp 的手柄，等于把标题宽度再切一刀；
     而 Web 的行本身就是可拖的。长按 = 拖动是触屏列表的通用约定，菜单退到「…」更省地方。
3. **保留长按菜单，拖动只在"菜单里的上移/下移"之外另开一个"排序模式"**
   - 为何被否：多一个模式就多一个"怎么退出"的问题，而用户要的是"像 Web 那样直接拖"。
4. **把空态出路也改成锚定**
   - 为何被否：它的触发点在屏幕中部，锚定浮层会盖住空态文案；底部 sheet 在那个位置更自然。

## Consequences

- 收益：三个"点上面、弹下面"的入口全部清掉。判据进测试：
  `subagent_enter_test.dart`（标题）、`connection_actions_sheet_test.dart`（连接点）、
  `session_drawer_test.dart`（行菜单），三处都是 `panel.top - anchor.bottom < 80` 且水平 < 80。
- 代价：`showConnectionActionsSheet` 的签名多一个可选 `Rect? anchor`；
  `ChatAppBar.onConnectionTap` 与 `DshConnectionDotButton.onAnchorPressed` 的类型
  从 `VoidCallback` 变成 `void Function(Rect)` —— 与 `onTitleTap` 同一条：
  **锚点必须由触发控件自己量**。
- 代价：浮层的动作菜单给了 `maxHeightFactor: 0.8`（默认 0.55 会把「重新配对」挤到滚动区外）。
- 仍未改（也不该改）：输入栏一侧的三个入口仍是底部 sheet —— 那里是拇指区。
- 验证：`dsh_popover_test.dart` 补了"下方放不下就翻到上方"的实测（面板底边 = 锚点上沿 − 6）；
  真机截图 `e01c-popover.png`（连接点）/ `e02-row-menu.png`（会话行）。
