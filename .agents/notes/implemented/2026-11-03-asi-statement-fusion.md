# 网页脚本的语句粘连要用扫描兜住，不能靠"看着对"

- 日期：2026-11-03
- 触发：线上事故 —— relay 网页部署后整页点不动（管理台登录、控制台菜单、生成令牌全部无反应）
- 状态：implemented

## 背景

`d385762` 把网页反馈收成一个组件（`relay/src/ui/kit.ts`），`UI_KIT_JS` 的 IIFE 结尾写成
`})()`（没分号），而两个页面在 `${UI_KIT_JS}` 后面紧跟一行 `(function () {`。JS 的 ASI
不会在 `(` 前插分号，两行被接成一次调用：

```
Kit.configure({ ... })(function () { … })   →  TypeError: Kit.configure(...) is not a function
```

脚本在第一段就抛错，后面的路由与事件全没绑上 —— 表现是"点什么都没反应"，看起来像后端挂了。

这类错**两道现有闸都看不见**：`tsc` 只查类型（页面是模板字符串，不进类型检查）；
`node --test` 跑的是 node 侧代码。只有真浏览器加载页面才会炸。

## 决定

修分号（`})();` + 三处单行 `Kit.*` 调用补分号），并加**两层**闸：

1. **窄**：`UI_KIT_JS` 必须以分号收尾、页面里单行写完的 `Kit.xxx(…)` 必须带分号；
2. **宽**：扫整段脚本的 ASI 危险形态 —— 上一行以 `)`/`]`/标识符/字面量收尾（完整语句）
   且下一行以 `(`/`[` 开头，命中即失败；
3. 另外用最小 `document` 替身把 `UI_KIT_JS` **真跑一遍**，断言它挂出七个方法
   （`new Function` 只查语法，语句粘连是运行期错误，必须执行到底才看得见）。

## 被否掉的

- **只补分号、不加闸**：下次在任何页面里写一行 `foo()` 接一个 IIFE 就又炸，而炸的
  现场是"整页无反应"，与根因（少个分号）离得很远。
- **只加宽规则**：宽规则抓的是"已经粘连"；窄规则还挡"粘连的前置条件"——单行调用不带
  分号本身没错，但它是下一次事故的必要条件。
- **把页面脚本抽成独立 `.js` 文件用 tsc/eslint 检查**：中转没有构建步骤（`node src/main.ts`
  直接跑 TS），引入构建链只为这条规则不划算；扫描写在测试里，成本是一个函数。
- **浏览器端到端测试**（headless Chrome 加载两页）：结论最真，但给中转的 CI 加一个
  Chromium 依赖不划算；本地排障时用 chrome-devtools MCP 加载渲染后的页面即可（本次就是这么查出来的）。

## 代价

- 宽规则有误报风险（上一行以 `(` 收尾的续行、以 `;` 开头的行都要排除）—— 已在规则里显式
  排除，并在两页各跑一遍确认 **0 命中**。
- 扫描只看 `<script>…</script>` 的第一段（中转的页面只有一个 script 块），多段时要跟着改。

## 验证

- 两页扫出 0 处危险形态；`relay` 的 `node --test` **165** 项全绿；
- 真浏览器（chrome-devtools MCP）加载渲染后的两页：`Kit.configure` 报错消失、管理台露出
  登录表单、控制台点「我的电脑」能切页、「添加电脑」能弹框。
