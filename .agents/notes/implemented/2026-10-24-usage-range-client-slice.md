# Agent Note: 用量页的时间范围 —— 纯前端切片，不改 `usage.summary`

Status: implemented

## Problem

用量页的热力图一直只有一种窗口：最近 52 周。想回答"这一周干了多少"时，
那 52 周的格子铺满一屏、还得自己数日子；而"最近 7 天"这个最常用的问法在界面上不存在。

先要证明的是**这件事到底要不要动契约**：`usage.summary.byDay` 已经带着全部保留日期的
`{date, turns, tokens}`（契约 §5.7 的规则⑤，逐天聚合在连接器里做）。也就是说
"看最近 N 天"是**取窗口**，不是"再问电脑要一份更窄的数据"。

## Decision

**纯前端切片**：`usage_page.dart` 的 `usageWindowOf(days, range, today)` 只做两件事 ——
按 `YYYY-MM-DD` 的字符串序（同格式下字典序 = 时间序）留下窗口内的日期，算出这一屏要画**几周**。
`usage.summary` 的出入参**一个字段都不动**。

- 四档：`7 天 / 30 天 / 90 天 / 全部`（`UsageRange` 枚举；"全部"= 一条都不切、恒画 52 周）。
- **窗口仍是连续日历**：格子按 周 × 星期 画，窗口首日落到它那一周的周一、一直到今天所在的周。
  所以"7 天"在周六看是 **2 列**、在周一正好 1 列 —— 不是"只画 7 格"的一根长条
  （那样就没有星期维度了，读起来是另一张图）。
- 切窗口时清掉选中格（`_selected = null`）：落在窗口外的日期没有读数可显示，
  留着它就是摆一个旧数字。
- 标题跟着窗口走（`最近 7 天` / `最近 52 周`），读数行不变。

## Alternatives considered

1. **给 `usage.summary` 加 `days` / `from` 参数，让连接器先切** —— 最强理由：手机上少传数据，
   将来 byDay 变长时也不会把整包塞进一帧。
   被否：`byDay` 的覆盖范围是各会话 `trajectory` 保留的最近 200 轮（`connector/src/dsh/trajectory.ts:98`），
   本来就不长；为一次纯展示的切片改动一个已定案的跨端契约，代价是"每一处引用 `usage.summary`
   的地方都要重新核对"，收益是零（数据早就在手上）。真要减帧，该先量。
2. **在手机侧做"最近 N 天"的聚合（再算一份总量）** —— 被否：那是第二个真值源。
   切片只决定"画哪些格子"，总量卡与分项仍然来自电脑侧的同一份聚合。
3. **改成日历月份选择器（这月 / 上月 / 自定义）** —— 被否：用户问的是"最近一周 / 一月"，
   不是"哪个月"；月份选择器在 390dp 上还要多一层 sheet。
4. **窗口内只画有数据的那几格** —— 被否：那就成了"点阵"不是日历，星期与月份标签都失去意义。

## Consequences

- **收益**：最常用的"最近 7 天"一键可达；契约、连接器一行都没动。
- **代价**：窗口内的"总量"仍是全量汇总（总量卡、四格卡片不随窗口变）——
  这是**有意的**：它们答的是"这台电脑一共用了多少"，窗口只作用于热力图那一块。
  若将来要"窗口内的合计"，那是另一个功能（要新字段），不在本次范围。
- **代价**：`全部` 恒画 52 周，若保留日期早于 52 周前，那些天不显示（与改动前一致）。

## 判据

- flutter **1189 → 1192**（`test/usage_page_test.dart` +3）：窗口切片（7/30 天 + 周数是连续日历）、
  「全部」不切 + 对照组、切到 7 天后点格子读数仍正确。
- **变异校验**：把窗口边界放宽一格（`compareTo(startKey) >= -1`）⇒ 恰好那两条窗口用例红
  （第一条与"全部"里的对照组），读数那条正确地仍绿 —— 证明"切窗口"与"怎么读"是两件事。做完即还原。
- `dart analyze --fatal-infos` 0、`dart format` 0（scope 见 `tools.md`）。
