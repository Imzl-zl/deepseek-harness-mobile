# Agent Note: 连接方式选择器落地为「当前连接块 + 端点全量列表 + 真实拨号记录」

Status: implemented

## Problem

模型层早就把端点备齐了（`AppModel.endpoints` / `preferEndpoint`、
`EndpointTransport.connect()` 按序拨号），但**界面上一条都看不见**：用户不知道
当前走的是直连还是中转、地址是什么、换 WiFi 后直连失效时发生了什么 ——
传输层刻意安静重试（不降权、不弹错），于是"自动回落中转"这件事
在手机上没有任何痕迹，用户看着"已连接"以为一切如常。
更藏不住的一处：抽屉连接行写死了一句「中转已连接 · 空闲」，而 2026-10-16
无线验证后日常走的就是直连 —— 那句话每一条连接都是错的。

## Decision

连接方式选择器 = 三处 UI，共用同一套说法（`model/chat_item.dart` 的
`connectionSummary` / `endpointKindLabel`）：

1. **连接 sheet 顶部「当前连接」块**（`ui/connection_summary_block.dart`，
   sheet 与设置页共用同一个 widget）：连上时显示 `当前连接：<kind> · <地址>`；
   当前走的不是端点表第一位、且第一位的**真实拨号记录**是失败时，第二行给出
   `直连 <地址> 拨不通（原因）` —— 这是"换 WiFi / 电脑换 IP"的唯一提示。
2. **设置页「连接方式」组**（`ui/settings_page.dart`）：端点**全量**列表，
   行 = `[图标 + 直连/中转 + 地址(+连接器自报名) + 状态] [首选(恒占位)]`；
   点一行 = `preferEndpoint` 置顶（只改序、不删条目、不踹连接），下次重连生效。
3. **状态全部来自真实拨号记录**：`EndpointTransport.onAttempt` 每试一个端点
   报一次结局（`core/endpoint_transport.dart`），`AppModel.attemptOf` 记账；
   四档：`当前连接`（仅服务态）/ `拨不通：原因` / `拨通过` / `还没试过`。

准入门槛（可机械判定）：

1. **不主动探测**：设置页不许为了显示"通不通"自己去拨号。判据是
   `app/lib/ui/settings_page.dart` 里只有 `app.attemptOf` 一个数据来源，
   没有 `connect` / `PairingClient` 调用。
2. **没有记录就没有结论**：没拨过的端点显示"还没试过"，不许显示"通"。
3. **relay 与 direct 都显示**（用户 2026-10-16 拍板："两个配置两种方式"）：
   端点列表行数 = `app.endpoints.length`，没有折叠、没有"高级"分组。
4. **回落提示必须有据**：`connectionSummary` 只在"首选拨过且失败"时给
   note；首选没拨过或上次是通的，note 为 null（不编原因）。
5. **同一个事实一套说法**：`当前连接` 只在 `ConnectionStateView.serving`
   时标注（拨通记录跨连接保留，重连中标"当前"会与顶栏/连接 sheet 的
   "重连中…"打架）。

## Alternatives considered

1. 只显示 direct，relay 折叠进「高级」
   - 最强的理由：列表只剩日常用的那条，视觉最干净；relay 确实是"平时不出现"的保底。
   - 为何被否：① 自动回落中转时"当前正走的那条不在列表里"，用户管不着自己
     正在用的端点；② 端点表出现"可见子集"这第二套真相（列表显示规则 vs
     实际拨号表），是迟早漂移的地方。用户看到这个问题时的原话是
     "明明就是两个配置两种方式"—— 折叠等于把一种正当配置藏起来。
2. 设置页打开时对每个端点主动探测
   - 最强的理由："通不通"是即时结论，不依赖上一次真实拨号的时机。
   - 为何被否：多出第二条拨号路径，"通不通"取决于探测时机而不是真实拨号；
     direct 探测失败还会在电脑侧监听面留下一次未完成握手。真实拨号记录
     本来就会在每次重连时刷新，足够新。
3. 置顶后立刻触发重连（让新顺序马上生效）
   - 最强的理由：用户点了就见效，不用等下一次自然重连。
   - 为何被否：会踹掉正在用的连接（当前会话的帧流会断）；`preferEndpoint`
     的所有权纪律是"只改序"，立即重连要把连接层的 start/退避也拖进这个动作。
     toast 明说"下次重连生效"。
4. 传输层自己维护每个端点的健康状态（失败计数 / 熔断）
   - 最强的理由：拨号方最清楚成败，状态放它手里最自然。
   - 为何被否：`endpoint_transport.dart` 的文件头定了"不降权、不重排"——
     失败过的端点下一轮必须仍在原位置（直连是会恢复的）。健康状态一旦进传输层，
     离"智能跳过"只差一步，而那正是被否掉的降权。传输层只报事实（onAttempt），
     记账在 `AppModel`。
5. 按第一版 5 组把设置页摆全（账号 / 通用 / 模型 / 插件 / 关于）
   - 最强的理由：设置页像个"完整的设置"，用户不用猜还有什么。
   - 为何被否：其余组还没搬（`docs/settings-porting-notes.md`），占位行点下去
     只弹"还没做"—— 比没有这一行更糟（用户以为功能坏了）。本期只有连接方式，
     空端点时给空态文案。

## Consequences

- 收益：① "走的哪条、为什么"在三处入口（连接 sheet / 设置页 / 抽屉连接行）
  同一套说法；② 换 WiFi 后从"安静重试"变成"块里第二行说明直连拨不通"；
  ③ 抽屉连接行不再写死"中转"，直连落地后那句错话消失；
  ④ 端点状态零新依赖：全部复用已有拨号路径的事实。
- 代价：① 每试一个端点多一次回调（可忽略）；② `AppModel` 多一张
  `endpointAttempts` 表要随端点表维护（端点从不删除，表只增）；
  ③ 设置页本期只有一组，短寿地看起来"不像设置页"—— 等其余组搬迁时再长全；
  ④ 连接 sheet 多一块不可点的信息区，遮罩点击区域少了一行高度。
- 原型同步（`mock/proto`，交互基线不允许单边漂移）：连接 sheet 加「当前连接」
  行、关于与连接详情页加「连接方式」两组行（直连=当前/首选、中转=保底/可置顶，
  走 toast 演示动作）、抽屉连接行改「直连已连接」；`verify-settings.mjs`
  27 → 28 项，`verify-proto.mjs` dump 加 `connSheetShowsCurrent`。
  取舍：端点是活数据，原型用当前真实部署的地址（192.168.2.43:8790 / :8787）
  当静态演示值，与原型既有的静态内容同一性质。
