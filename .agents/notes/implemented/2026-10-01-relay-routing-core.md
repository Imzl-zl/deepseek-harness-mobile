# Agent Note: `relay/` 的第一块不是网络层，而是路由核心（外加一个必须补的洞）

Status: implemented（`relay/src/routing.ts` + `protocol-view.ts`，7 条用例；网络层与配对中继见"仍未做"）

## Problem

`relay/` 是全新的一侧。第一步该写什么？先看契约把它约束成什么：

- **§2 的拓扑**：`[手机] ⇄(WSS) ⇄ [中转] ⇄(WSS) ⇄ [桥接] ⇄ [DSH]`；
- **I10**：中转**只读路由元数据**（`sid` / `seq` / `fc` / 帧类型），方法名、事件类型、载荷一律不可见；
- **§5.5**：它按 `sid` 保留一段重放窗口，裁剪要等设备 `persisted` 覆盖过；
- **§12.1 第 3 步**：**身份判定在电脑侧**，中转只转发与记账。

这四条合起来说明：中转的"大脑"就是**路由与记账**，而它对载荷的无知应该是**类型层面**的
（拿不到载荷），不是纪律层面的（约定不看）。所以第一块就写它，而且可以完全脱离网络测。

## Decision

`relay/src/routing.ts`：

- **只认识 `RoutingView = { t, sid, seq }`**，原始行原样搬运（`raw`，中转不解它）。
  `protocol-view.ts` 的 `routingViewOf(raw)` 是中转与载荷之间**唯一**的接口，它没有回传载荷的口子。
- **`sid` 归属只能从电脑侧发来的帧里学**（谁发过某个 sid，那个 sid 就归谁）—— 设备侧说了不算。
  设备发来指向未知归属的帧：**转发不了，但登记"它在听"**（见下），并丢弃这一帧；
  **不自己造错误帧** —— 契约 §9 只授权中继合成 `presence`，自己造业务错误会让
  "电脑侧离线"与"这个会话不存在"在设备侧变成同一件事。
- **窗口按 `(设备, sid)` 分**：每台设备缺的段落不一样；裁剪用**这台设备自己的** `persisted`。
  有洞或已被裁过头 → 返回 `undefined`（= 要求快照），不给残缺增量。
- 窗口封顶（默认 1000 条/窗口），超限丢最旧的 —— 那会让设备看出缺口，正是要它走快照的信号。

## 一处从测试里逼出来的设计决定

第一版 `fromDevice` 在"还没学到归属"时**直接返回**，于是设备也就没被登记为听众。
测试立刻暴露出后果：**重连上来先说话的那台设备，会漏掉随后电脑侧推给它的帧**
（电脑侧还没推过任何东西时，归属就是空的 —— 而"设备先说话"在重连场景里很常见）。

改成：**先登记"它在听"，再看能不能转发**。这安全的前提写在代码注释里：
帧是按每台设备的密钥端到端加密的，中转只搬密文；登记错 sid 的设备拿到也解不开。

## Alternatives considered

1. 先写网络层（WS 收发、ticket、限流），路由逻辑内联在 handler 里
   - 最强的理由：能更早跑起来一个"真的能连"的中转。
   - 为何被否：那会把"路由与记账"写死在 socket 回调里，而它恰恰是最需要**单独被测**的部分
     （窗口裁剪、归属学习、覆盖判据是三条都会静默出错的规则）。网络层随后套上去就行。
2. 让中转也能读载荷（反正密文它搬得动，解不解是它自己的事）
   - 最强的理由：未来某个功能（比如按会话限流、按方法统计）会想要方法名。
   - 为何被否：I10 是**不变量**，而"读一下没关系"的来源正是这种未来需求。
     真要按会话限流，用 `sid` 就够了；真要按方法统计，那应该被显式设计成一次契约变更。
3. 设备指向未知 `sid` 时，中转合成一个错误帧回给设备
   - 最强的理由：设备能立刻知道"这个会话的电脑侧不在"，不必等超时。
   - 为何被否：见 Decision 第三条 —— 契约只授权合成 `presence`；而且"造一个错误"
     会把两种不同的处境（电脑侧离线 / 这个会话不存在）压成同一个表现。

## 仍未做（下一轮，按顺序）

1. **配对请求的中继路径（一个必须补的洞）**：配对帧**没有 `sid`**（它要先于任何会话存在），
   所以本层的 `sid → connector` 归属表**帮不上它**。要支持"手机经中转配对"，中转必须知道
   "这台设备该转给哪个连接器" —— 最自然的做法是**出码登记**：电脑侧出码时把
   `codeHash → 自己` 注册给中转（**只登记哈希**，与 §12 的中转表 `code_hash` 列一致，也与
   第 18 轮把请求改成带哈希的决定一致），设备带同一个 `codeHash` 来 `POST /ws-ticket` 时，
   中转据此把它绑定到那台连接器。**这需要写进契约**（中转的记账表与 ticket 的输入）。
2. **网络层**：`ws` 服务端（连接器侧与设备侧两个入口）、`POST /ws-ticket`（一次性 ticket，
   令牌不进 URL）、连接器令牌校验、限流与审计。
3. **`ws` 依赖**：中转是独立一侧，`ws` 在它那里是**运行时依赖**（与连接器不同：连接器只拨号，
   客户端用 Node 自带的 `WebSocket`）。
4. **`relay/` 的工程骨架**（package.json / tsconfig / 测试脚本）：本轮先让核心能被连接器的工具链
   直接跑起来（`cd connector && pnpm exec tsx --test ../relay/tests/routing.test.ts`，7 条全绿），
   骨架与依赖随网络层一起立。
