# Agent Note: 中转自带的管理面板（中转可观测/限额/面板 第 4 批）

Status: implemented

## Problem

前三批把"能不能记账、能不能拦住"做出来了，但运营者要看的那些数字与动作**没有出口**：
在线连接器与活跃通道只在进程内存里，额度只有 429 与日志，吊销只有一条 CLI。
服务器上要回答"现在谁连着、谁用了多少、这台是不是卡住了"，只能读日志拼。

## Decision

1. **同一 `host:port` 的 `/admin`，不新开端口**。Caddy 已经把整站反代过去
   （`Caddyfile.example`），公网 IP 那条路本来就在 8787 —— 多一个端口等于多一个
   安全组口子、多一处要配的反代。绑回环则意味着操作者必须 SSH 隧道，问题从"鉴权"
   变成"访问方式"。
2. **凭据是独立的管理摘要**（第 1 批）：`Authorization: Bearer`，**不设 cookie**。
   浏览器不会自动带 `Authorization`，所以整套面**没有 CSRF 可打**；写操作与读操作
   用同一个头，没有"表单提交"那条路。
3. **实时性用轮询（2 s），不用 WS/SSE**：浏览器的 `WebSocket` / `EventSource`
   **不能自定义请求头**，要用长连接就只能把令牌塞进 URL（访问日志、浏览器历史、
   Referer 全都会带上）。轮询把凭据留在头里，而"人看面板"不需要亚秒延迟。
4. **页面是单文件内联**（`admin/page.ts`）：中转没有构建步骤（`Dockerfile`），
   引打包链会打破"`node src/main.ts` 直接跑"；单文件也让 CSP 简单
   （没有外链可加载）。数据用 `textContent` 渲染，不拼 HTML。
5. **四个写动作**：改额度（按人写回配置）、重置用量、断开（整台连接器或单条通道）、
   吊销/恢复令牌（吊销即下线）。每个都留一条 `admin.action` 审计（actor/action/主体），
   **令牌本体不进日志**。
6. **写动作经 `AdminOps` 注入**：HTTP 层不认识配置文件路径，落盘与"整份重写"的
   写法留在 `main.ts`（与 CLI 共用 `issue-token.ts` 的那套函数）。
7. **列表封顶 500 行**、超出只报总数：名册行数没有上限（契约"设备上限 不设上限"），
   面板不能因为一台灌了几千行的连接器把事件循环按住。

## 补充：视觉按"独立产品"做（同日修正）

第一版照搬了 DSH 的主题 token，理由是"和手机端同一套语言"。这条理由不成立：
**中转是独立服务**（`node src/main.ts` 自己跑，不加载任何 DSH 运行时），它不是宿主
的插件页，也就没有"必须长得像宿主"的约束。改成自成一体的控制台：

- 左侧分区导航（概览 / 连接器 / 通道 / 用量 / 令牌）+ 右侧内容区，hash 路由
  （刷新保持分区），不是一长条滚动页。
- 自己的配色（深色海军底 + 青绿强调；跟随系统亮暗，两套变量），内联 SVG 标记。
- 概览多一条**真实的**近 60 分钟转发曲线：`metering.traffic()` 按分钟累计 60 个整数
  （滚动窗口，`rollTraffic` 补零），不是抽样也不是编的；KPI 与曲线共用一个读面。
- 登录屏先于看板；401 退回登录；「退出」清 `sessionStorage`。

## Alternatives considered

1. **独立 admin 端口（默认只绑 127.0.0.1）**
   - 最强的理由：网络位置就是一层保护，漏配令牌也不至于全裸；面板与设备流量互不打扰。
   - 为何被否：部署在公网服务器、操作者从自己的电脑访问，绑回环等于强制 SSH 隧道；
     而"漏配令牌"这个风险已经由"没配 `admin` 就不存在这张面"从结构上关掉。
2. **反代 Basic/SSO 做鉴权，relay 不碰凭据**
   - 最强的理由：relay 里零凭据代码，SSO 还能带审计与多用户。
   - 为何被否：那要求每位操作者都有反代账号，且 relay 自己仍然需要一个"谁能调
     写接口"的判据 —— 两套凭据要么重复、要么其中一套形同虚设。
3. **复用连接器令牌做管理凭据**
   - 最强的理由：少一个概念、少一套签发路径。
   - 为何被否：连接器令牌的权力是"替一台电脑报名册、拨数据面"，不该放进浏览器；
     而且 `digest-auth` 的表**硬拒非 connector 条目**，复用要在那边开口子。
4. **WS/SSE 推送**
   - 最强的理由：状态变化立刻可见，不必等 2 s。
   - 为何被否：见 Decision 3（凭据只能进 URL）。若将来真需要，正确做法是给面板
     单独发一次性短票 + cookie，而不是把长期令牌放 URL —— 那是另一个决定。
5. **前端工程（Vite/React）**
   - 最强的理由：状态多起来后手写 DOM 会啰嗦。
   - 为何被否：打破"无构建步骤"；现在一页 5 块表格 + 4 个按钮，手写足够。
6. **面板直接读写配置文件**
   - 最强的理由：实现最短，不用注入 `AdminOps`。
   - 为何被否：HTTP 层会认识配置路径与令牌表，职责错位；测试也要造真文件。

## Consequences

- 收益：服务器上的四类问题（谁在线、哪条通道、谁用了多少、谁被挡住）第一次有出口，
  且与日志、额度共用同一份内存事实，不会两处漂。
- 收益：吊销从"改配置 + 重启"变成"点一下、立刻下线"（与第 1 批的可变表配套）。
- 代价：页面只有中文、没有分页与排序（封顶 500 行 + 总数）；够用，但不是成品后台。
- 代价：按连接器主体的额度覆盖**只在本进程有效**（配置里没有这一格），重启回到
  `defaultBytes`；按人（`quota.owners`）才写回配置。
- 代价：面板与 CLI 都会整份重写 `relay.config.json`，**不能并发**（写进 cookbook 的
  "两个不要"）。没有跨进程锁 —— 检测冲突比假装安全便宜。
- 代价：写操作目前没有"二次确认"的服务端保护（页面有 `confirm`），一次误点就是真实
  断线；审计行是唯一的追溯线索。
- 未验：面板在多操作者并发点击下的表现（单实例、单人运维场景）。

## 本批的机械门槛（实测）

- `cd relay; pnpm typecheck` → 0；
- `node --test` → **125 / 125**（批前 123；`admin-face.test.ts` 从 4 条扩到 6 条，
  覆盖页面/快照/四类写操作/审计/401 路径）。
- 变异校验（一次）：吊销令牌后**不**收掉在线控制面 → **恰 1 红**
  （"面板能管：…吊销即下线"）。同时把该用例的关闭等待改成带超时 ——
  否则变异时它会挂住整个套件，看起来像环境问题。
- 真实浏览器（独立 headless Chrome + CDP，`mock/proto/tools/cdp.ps1`）：打开 `/admin` →
  贴令牌 → 状态变「已连接」；`按人额度` 表渲染出 `user:alice 0 B / 200.0 MB` + 两个按钮，
  `名册` 显示 `共 0 行`；页面上没有任何外链脚本/样式。
  **这一步抓到一个真 bug**：页面原本也要求 Bearer，浏览器打开 URL 不会带 `Authorization`，
  用户根本到不了输入框 —— 已改成"页面免令牌、`/admin/api/*` 与写操作要令牌"，用例同步。
