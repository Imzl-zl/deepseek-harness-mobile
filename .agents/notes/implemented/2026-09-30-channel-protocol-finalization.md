# Agent Note: 通道协议定稿 —— 两层序号分离、每连接握手、live 独立成帧、接管默认前台档

Status: implemented

## Problem

协议此前只有骨架:信封里 `ev` 必带 `seq`,恢复只有"增量或快照"两种结果,其余三处留给实现者自己发明——AEAD 算法与 nonce 来源、审批接管的仲裁、鸿蒙设备私钥的落点。

不写下来会各自长成什么样,是可以预期的:

1. **nonce 用随机数**。"每帧独立随机 nonce"读起来最省心,于是每帧一次 `Random.secure()`(系统调用),而 XChaCha20 又不在平台加速清单里 ⇒ 逐帧封箱变成"系统调用 + 纯 Dart AEAD";重放防护还得另写一套。
2. **live 帧塞进 `seq`**。实时 token 流没有自己的位置,最省事的做法是给它也编一个会话序号 ⇒ 破坏"修订号 = DSH 会话 seq"这个唯一真值基础,恢复语义随之失真。
3. **快照当原子整体**。`snapshotRequired` 只带一个原因,实现者会把基线当成一次性给出;而 DSH 的开场快照本来就是分页的(`maxMessages` 默认 50 + `hasMore`)⇒ 快照与增量拼接处丢一段。
4. **接管判定各写一套**。"手机在线就接管"看着合理,但 claim 会挡住桌面 UI(claim-or-delegate 顺序 waterfall),而"在线"与"用户在看"是两件事 ⇒ 用户在电脑前等一个永远不出现的审批框。

## Decision

协议按"连接层 / 会话层"两层定稿,并把三处待定全部定值。

准入门槛(可机械判定):

1. **nonce 必须由连接层计数器 `fc` 派生**(12 字节大端),代码里不得出现随机 nonce;接收方拒绝 `fc ≤ maxFc`。
2. **每连接一次握手**:长期种子经 HKDF 派生 Ed25519(签名)与 X25519(静态 DH)两把;共享密钥含 `eph×eph`,因此长期种子泄露不能解已结束连接。
3. **live 帧不进 items、不推进 `seq`、不参与 ack、恢复不回带**(fixture `10` 断言)。
4. **快照必须带 `asOfSeq` 与 `hasMore`**,分页期间到达的 `ev` 只缓存,分页结束后按 `seq` 合并(fixture `11`/`12` 断言)。
5. **待审批与待回答是持久事实的投影**,悬空即"有 ask、无 outcome",桥接重启后从日志重建(fixture `13` 断言;`TransientFacts` 只允许在线态与能力位)。
6. **接管判定必须与 fixture `16` 的判定表逐条一致**:默认 `foreground`(前台且订阅该会话才 claim),并列时按"最近交互 → 最早配对 → id 升序"确定性排序。
7. 参数改动必须同时改契约 §10 的参数表并同步 fixtures。

## Alternatives considered

1. 保留"每帧随机 24 字节 nonce + XChaCha20-Poly1305"
   - 最强的理由:无状态,不需要计数器,不必担心计数器回退或持久化;24 字节随机空间的碰撞概率可忽略。
   - 为何被否:计数器方案一次解决三件事(nonce 唯一性、重放防护、流控信用),而随机方案要额外写重放防护;`cryptography` 的默认随机源是 `Random.secure()`,逐帧封箱等于逐帧系统调用;XChaCha20 不在 `cryptography_flutter` 的加速清单里,8 MiB 帧纯 Dart 要 0.3–1.6 s。改成 `(sid, seq)` 或 `fc` 派生后,可选 ChaCha20-Poly1305 或 AES-GCM(都有平台加速)。
2. 用 TLS 客户端证书代替自建握手
   - 最强的理由:成熟、有库、社区审计过,免去自研密码学的风险;mTLS 的双向认证是标准做法。
   - 为何被否:手机端要在 Flutter 三端(尤其鸿蒙)拿到"可用的客户端证书"没有可靠路径,DSH 侧还要引入证书签发与吊销;自建握手只用到 X25519 / Ed25519 / HKDF / AEAD 四个现成原语(全部有纯 Dart 实现),并由 `protocol/vectors/` 提供跨端互操作向量兜住实现漂移。
3. 审批仲裁取"手机独占"(最简单的一档)
   - 最强的理由:判定最少、最容易测,没有"两处同时可答"的歧义。
   - 为何被否:它改变桌面既有行为——只要手机在线,电脑上就看不到审批;而手机常在后台、连接也不可靠。默认取 `foreground` 保留了桌面路径,同时把"是否接管"显式交给用户开关(`always` / `foreground` / `never`),并给 claim 配 10 min 看护超时与 fail-closed。
4. 基线快照改为"重开 `follow()` 取开场快照"
   - 最强的理由:与增量同源,不必另拼一套快照逻辑。
   - 为何被否:`follow()` 的首帧只给一次,重开等于新建订阅并触发 promote 路径;而 `page()` 本身就是按消息对齐、有页预算、冷安全的分页接口,`cursor = "b:<beforeSeq>"` 直接对应它的 `beforeSeq`。
5. 让中转也分配序号(便于它独立完成补课)
   - 最强的理由:中转能自行裁剪与补课,电脑侧压力更小。
   - 为何被否:一旦中转分配序号,它就从投影变成第二真值源,"清空中转仍收敛"这条不变量不再成立;现在的窗口只是缓存,给不出连续区间就明确说给不了。

## Consequences

- 收益:nonce、重放防护与流控归一为同一个计数器;前向保密由每连接握手直接给出,不再依赖"以后补密钥轮换";live 帧与持久事件各就各位(体验与恢复语义不再互相打架);待审批可从日志重建,消掉了"桥接重启即丢审批"这条产品缺口;接管判定变成可执行判定表;参数集中成一张有依据的表。
- 代价:实现面变大——握手 3 条消息 + 双向验签、连接层 `fc` 与信用窗口、快照分页拼接、日志重建待处理集合,四块都要两侧各写一遍;每连接一次握手带来 3 次 DH 与 2 次签名校验的开销;`peerDependencies` 用精确版本 ⇒ DSH 升级必须同步改,否则插件被静默跳过;契约文档显著变长,其中约二十处 DSH 行号引用进入"DSH 升级时重核"的维护负担。
- 未消除的代价:鸿蒙侧仍要自写 HUKS platform channel;真机 AEAD 小帧基准尚未做(算法切换路径已留,nonce 与 AAD 规则不变);中转的容量压测与 ICP/PIPL 合规仍是上线前置。
