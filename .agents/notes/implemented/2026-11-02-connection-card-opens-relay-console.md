# Agent Note: 连接卡的令牌行直接给一个"去注册 / 登录"外链

Status: implemented

## Problem

「手机 → 连接」卡的令牌格只有"已设置/未设置 + 输入框 + 清除"，没有"令牌从哪来"。
公开中转开了账号模式之后，用户必须自己记得中转域名、在浏览器里打开、注册/登录、进控制台
「添加电脑」、再把令牌贴回来 —— 这一步在面板里没有任何入口，用户很容易卡在"未设置"。

## Decision

令牌行渲染一个真正的 `<a target="_blank" rel="noopener noreferrer">`，地址由**当前中转
拨号地址**推导：`ws(s)://host/任意路径` → `http(s)://host/login`（只换协议、丢掉路径）。
`/login` 在已登录时会 302 到 `/console`，所以同一个链接同时服务"新用户注册"与"老用户看控制台"。
解析失败或地址为空时不渲染链接。内置与自定义中转走同一条判据。

准入门槛（可机械判定）：

1. 链接只在 `new URL(relayUrl)` 成功且协议是 `ws:` / `wss:` 时出现；其余情况 DOM 里没有这个 `<a>`。
2. `href` 必须等于 `http(s)://url.host/login`；不携带令牌、不携带查询串。
3. `target="_blank"` 且 `rel="noopener noreferrer"`。
4. 中文与英文文案各一条，且都有真实调用点（connector 的 i18n 单测会拦孤儿键）。

## Alternatives considered

1. **只给内置中转显示链接**
   - 最强的理由：内置那条一定是我们自己的中转，账号页一定存在，链接永远不会 404。
   - 为何被否：自建中转同样开了账号模式，用户也在这里贴令牌；按 host 推导对两者是同一段代码，
     只给内置加等于把自建用户留在原来的死路上。
2. **弹一个说明框，列出"打开浏览器 → 注册 → 添加电脑"步骤**
   - 最强的理由：不依赖中转 UI 是否存在，旧中转也能给操作指引。
   - 为何被否：注册与会话本来就发生在浏览器里，说明框只是把多步流程抄一遍；用户还是要自己
     找地址。外链加一行提示已经把"去哪"解决了。
3. **直接链到 `/console`，让未登录的人被 302 到登录页**
   - 最强的理由：少一次跳转，已登录用户直达。
   - 为何被否：新用户看到的是"控制台"这个词，落点却是登录页；`/login` 的名字与
     「注册 / 登录」文案一致，登录页本身带注册入口。
4. **加设备码（device code）领取令牌，由电脑侧轮询写回**
   - 最强的理由：完全不用复制粘贴，绑定也天然可信。
   - 为何被否：要新增中转端点、连接器轮询与面板状态机；首连绑定已经把令牌与 `pcId` 绑在一起，
     这次要的只是"去哪拿令牌"的入口。设备码留作后续 UX 升级。

## Consequences

- 收益：令牌从"凭空出现"变成"点一下去拿"；内置与自建中转都覆盖；没有新增接口、没有新增存储。
- 代价：旧版中转没有账号页时，点开是 404（面板无法预先知道对方是否开了账号模式）；
  中转部署在子路径时，推导只到 origin，链接会落在根上；客户端改动需要随
  `dsh-mobile-connector` 0.1.10 重新打包/安装才在 DSH 面板里生效。
