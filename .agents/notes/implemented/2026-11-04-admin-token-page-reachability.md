# Agent Note: 管理台签出的令牌「可达 + 说清归属」

Status: implemented

## Problem

2026-11-03 已经给管理台加了「添加我的电脑」（`POST /admin/api/tokens/issue`，令牌页那行），
但三处仍让人以为"管理员加不了电脑"：

1. **文档与代码相反**：`docs/subsystems/relay-accounts.md` §8 写着「管理台不签发自己的令牌」，
   而代码里早就签了。
2. **顶栏是死路**：Bearer 模式下顶栏「我的电脑」仍写着「登录后添加电脑」并指向 `/login`；
   break-glass 管理员没有账号会话，点过去只会看到一个登录页。
3. **归属说不清**：那张令牌 `userId` 为空、不占任何账号的电脑数，但令牌页没有一句话说明，
   用户会以为"添加我的电脑"要算到某个人的额度上。

先判定线上版本（这一步可能直接结案）：`GET https://dsh.0t0.me/admin` 的正文
**sha256 = 82352034…efbcbf**，与本地 `ADMIN_PAGE` 逐字节相同（长度 71262）。
线上跑的就是带「添加我的电脑」的那版，**不需要升级镜像**，这不是版本问题，是可用性问题。

## Decision

1. **只改可达性与说明，不新开接口**：`/admin/api/tokens/issue` 就是"不归属任何账号的令牌"
   的接口（id 预填 `local`、同 id 活跃回 409、明文只回一次、只落摘要）。
2. **文档改成现状**（`relay-accounts.md` §5/§8/§9）：管理台令牌页可以签一张 break-glass 令牌；
   它不归属任何账号、不占账号配额，在「用量」的「未归属账号的主体」表里。
3. **令牌页那行下面加一句说明**：不归属账号 / 不占账号电脑数 / 出现在未归属表。
   同时令牌表的「账号」列把无主令牌显示成「未归属」，而不是一个破折号。
4. **顶栏按登录方式换落点**：账号会话仍进 `/console`（完整的账号电脑管理）；
   Bearer 模式落到 `#/tokens` 并聚焦「添加我的电脑」那行 —— 同一页，不再跳登录页。
5. **表里 `owner` 的判定不变**（`userId` 优先、其次旧 `owner`），只改显示文案。

## Alternatives considered

1. **当作"线上是旧镜像"，升级镜像了事**
   - 最强的理由：零代码改动，而且"功能不在线上"是这类问题最常见的原因。
   - 为何被否：线上页面与本地 HEAD 的 `ADMIN_PAGE` 哈希逐字节相同，功能就在线上。
     按升级处理会让人以为已经修了，实际问题（顶栏死路 + 说明缺失）原封不动。
2. **新开一个「无主令牌」接口（或一个独立页面）**
   - 最强的理由：语义最直白，能把"不归属账号"写进 URL 与请求形状里。
   - 为何被否：那个接口已经是 `/admin/api/tokens/issue` —— 它签的就是无主令牌
     （不带 `userId`）、明文只回一次、409 防覆盖。再开一个等于同一个动作两处真值、
     两条审计路径，还得决定"两个接口谁先腐化"。这次要补的是**说明与入口**，不是产能。
3. **把管理员做成独立身份（第三种角色）**
   - 最强的理由：从根上回答"这张令牌算谁的"。
   - 为何被否：break-glass 的设计前提就是**可以完全没有账号**（服务器还没建号时也要能进门）。
     给它造一个身份，等于把"账号体系坏了也能救"这条退路又绑回账号体系。
4. **顶栏继续指向 `/login`，只把原因写清楚**
   - 最强的理由：改动最小，且"管理员应该有个账号"是合理的产品立场。
   - 为何被否：那仍然是一条走不通的路 —— 登录成谁？没有账号的管理员在这一步就没有下一步。
     而令牌页本来就能完成同一件事。

## Consequences

- 收益：文档与代码一致；Bearer 管理员从顶栏一步到"能签令牌的那一行"；不会再误以为要占某人额度。
- 代价：顶栏按钮的行为**按登录方式分叉**（账号进控制台、令牌进令牌页）。这是有意的不一致，
  已在文档 §8 写明；两套落点各自都是那条身份唯一能走通的路。
- 代价：令牌页多一行说明文字。它属于"会一直显示"的静态说明，不是一次性提示。
- 不变：`/console` 仍然要求账号会话；管理员仍不是一种独立身份；没有第二个签发接口。
