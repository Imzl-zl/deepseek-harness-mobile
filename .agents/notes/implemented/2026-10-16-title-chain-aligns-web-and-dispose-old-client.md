# Agent Note: 标题链对齐 DSH 侧栏规则 + 换 AppModel 必须 dispose 旧客户端

Status: implemented

## Problem

2026-10-16 深夜真机连出三个问题，都指向"手机与 Web 分叉"：

1. **会话标题**：列表与顶栏都显示 `` <goal_round> Objective: "在新文件…" `` 这类
   原始串；没有标题的会话显示**目录名**甚至 **sid**，而 Web 同一批会话显示
   「未命名」。用户原话："现在的名字是对的，但一点击会话进去，名字就变了"。
2. **两条直连 socket**：电脑侧同时看到手机拨了两条 `8790` ESTABLISHED。
3. **退出重进连不上 / 连接不稳定**：与 2 同源。

## Decision

**标题：链改成 `投影提示标题 → 「未命名」`，删掉目录名与 sid 两级兜底；
`currentTitle` 删掉最后的本地推导兜底。** 判据（可机械判定）：

1. DSH 的 Web 侧栏对无标题会话显示本地化「未命名 / Untitled」，
   **不使用目录名兜底**——`ui-workspace/README.zh.md:32` 原话；判据在
   `ui-workspace/src/client/tree.ts:296` 的 `sessionTitle`（只取存储标题，
   空串交给渲染层本地化）。手机对齐这一条。
2. `session.list` 的行**只有投影提示**（host 侧 `SessionSummary` 见
   `dsh-api-session-controller/lib/types/types.d.ts`：字段是 `sessionId /
   updatedAt / running / blank / origin / cwd / projections`，**没有**独立的
   持久标题字段）。所以远程客户端拿不到 Web 那个"持久标题"，提示标题是
   列表行唯一的标题来源——契约如此，不是将就。
3. **顶栏与列表逐字同一条链**：`currentTitle` 不再回退到本地从条目推导的
   标题（`_storeOf(sid).title`）。那是 2026-10-15 那个"点进去名字变了"的
   病根（两个真值源），当时只搬走了第一层，兜底层一直留着——而
   `displayTitle` 永不为空（最差也是「未命名」），兜底只在"会话不在列表里"
   时生效，给出的恰是列表里看不见的名字。

**连接：换 `AppModel` 必须 dispose 旧的。** `_onPaired` / `_reassembleUnpaired`
替换 `_app` 前加 `_app?.dispose()`。旧客户端持着传输层（socket），不 dispose
就换掉，旧连接一直挂在电脑侧——真机实测的两条直连 socket 与"连接不稳定"
同源。判据：这两个方法体内各出现一次 `_app?.dispose()`，且替换发生在
dispose 之后（顺序反了会 dispose 到新客户端）。

## Alternatives considered

1. 标题继续保留目录名兜底
   - 最强的理由：无标题会话至少显示个有信息量的名字（项目目录），比"未命名"强。
   - 为何被否：DSH 的 Web 明确不用目录名兜底（README 原话），手机上出现一串
     目录名当会话名就是与 Web 的分叉；而用户拿来对照的正是 Web。
2. 标题对 `<goal_round>` 这类"内部串"做手机侧清洗（识别 `<xxx>` 前缀就丢弃）
   - 最强的理由：用户看着最干净。
   - 为何被否：那是 DSH 标题域从会话首条消息推导的结果（首条消息本身就是
     用户贴进去的 goal_round 块），手机清洗等于第二套标题规则，早晚和 DSH 漂；
     且"内部串"没有封闭名单，正则式清洗是猜。**本轮不做**，若用户要求，
     正确的问法是"DSH 的标题推导该不该跳过结构化消息"。
3. 顶栏保留本地推导兜底（"至少有个名字"）
   - 最强的理由：会话不在列表里时顶栏不至于光秃秃。
   - 为何被否：那正是 2026-10-15 真机 bug 的病根（列表与顶栏两个名字）；
     会话不在列表里只发生在"刚建还没刷新"，此时顶栏显示 null、界面退到
     'DSH'，比显示一个列表里看不见的名字诚实。
4. 旧 AppModel 不 dispose，靠连接层自己超时清理
   - 最强的理由：少改一行，旧连接最终会被半开检测清掉。
   - 为何被否：半开检测要等沉默超时（分钟级），期间电脑侧挂着一条没人用的
     连接，而用户的感受是"连接不稳定 / 换了电脑还连着旧的"。

## Consequences

- 收益：① 无标题会话与 Web 同显示「未命名」，目录名/sid 兜底消失；
  ② 顶栏与列表永远同一个字符串（"点进去名字变了"这一类分叉结构性消除）；
  ③ 重配对 / 断开凭据不再泄漏旧连接。
- 代价：① 顶栏在"会话刚建、列表还没刷到"时显示 'DSH' 而不是推导名
  （一帧的事，下一次刷新即恢复）；② 目录名兜底删掉后，`SessionSummary.cwd`
  的注释里"标题链第二级"的说法作废（它仍为"挑靶子"而发）；
  ③ `<goal_round>` 这类标题仍在（DSH 的投影就这么给），要治得治 DSH 侧。
