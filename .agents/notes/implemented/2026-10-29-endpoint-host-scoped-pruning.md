# Agent Note: 端点按"哪台电脑报的"剪枝，而不是只按 URL 记身份

Status: implemented

## Problem

端点表的所有行为都以 **url** 为身份（`core/endpoint.dart` 的 `Endpoint.id = url`）。
真实用法是**远程**：一口气换网络、换电脑、换中转地址之后，表里会留下再也拨不通的条目，
而只要它"曾经成功过一次"，`mergeDiscoveredEndpoints` 的剪枝就永远留着它
（`data/endpoint_book.dart` 的 `_succeededEndpointIds`），每一轮拨号都为它多等一个超时
（直连 3s / 中转 10s，见 `platform/transport_factory.dart`）。

2026-10-29 真机现场就是这张表的形状：一条当前电脑的地址、两条 VMware 虚拟网卡、
一条昨天那台电脑的地址，其中旧条目全部"成功过"，永远不会被剪。

## Decision

给 `Endpoint` 加 **`hostId`**（那台电脑的 Ed25519 公钥 `pcSignPubHex`，客户端字段，
与 `manual` 同一条先例：只出现在手机自己的落盘里，连接器的 `endpoint.describe` 不报）。
合并时用当前凭据的公钥盖上，剪枝规则多一条：**别的电脑报过的自动条目直接删**（手填的不动）。

> **为什么不用配对载荷里的 `pcId`**：它是连接器 id，默认值就是 `"local"` ——
> 两台电脑各自跑默认配置时 `pcId` 相同，"换了一台电脑"根本判不出来。
> 公钥是配对时钉死的（契约 §12.1），天生唯一且不可伪造。这条是落地前发现并改掉的。

准入门槛（可机械判定）：

1. 合并时 `hostId` 由 `AppModel.hostIdOf`（装配层接 `credentials.pcSignPubHex`）提供；
   连接器不报它 —— 所以 `mergeEndpoints` 原位更新时"fresh 空着就沿用已存的"，
   否则一处漏盖会判不出"换了一台电脑"。
2. 剪枝：`!manual && hostId 非空 && hostId != 当前公钥` ⇒ 删；**即便它成功过**。
3. 被剪掉的那条若正是"记住的那条"，`rememberedEndpointUrl` 一并清空并落盘 ——
   否则下一次拨号第一优先仍指向一个不存在的条目。
4. `_succeededEndpointIds` 在每次合并后**只留表里还在的 id**：换电脑裁掉的条目
   不该在"曾经成功"里留名（同名地址再出现时会逃过剪枝）。

## Alternatives considered

1. 继续只按 URL 记身份，把"成功过"改成"最近 N 次成功过"
   - 最强的理由：不动数据形状，改动最小，也不用把 pcId 传进来。
   - 为何被否：它只是把"永远留着"变成"留久一点"。换电脑之后那些地址**一次也不可能通**，
     时间衰减解决不了"明知不可拨还在拨"。
2. 在 `Endpoint` 上加一个连接器也会回填的 `hostId`（即改 `endpoint.describe` 的线上形状）
   - 最强的理由：身份完全由电脑侧说，手机不用维护第二份知识。
   - 为何被否：那要动协议与会话面（`wire/rpc/endpoint.dart` + 连接器 + 金样），
     而"这台手机连过谁"是**手机自己的记忆**，电脑侧本来就不该知道。
3. 换凭据（重新配对）时清空整张端点表
   - 最强的理由：一行代码，绝不会留下旧电脑的地址。
   - 为何被否：手填地址与"同一台电脑在另一个网络的地址"会一起没掉；
     用户在家的那条地址不该因为一次重配就被清掉。

## Consequences

- 收益：换电脑后旧地址不再参与拨号（省掉每轮 3s/10s 的超时）；"记住的那条"不会
  指着一个已删条目；成功集不再无限膨胀。
- 代价：端点 JSON 多一个客户端字段 `hostId`（连接器忽略它，手机侧的落盘与回读要一致）；
  合并路径多一次 stamp，`_sameEndpointTable` 也要比 hostId，否则"只变了归属"不落盘。
- 未覆盖：**同一台电脑**换地址后，旧地址仍按老规则（成功过就留）。理由是没有
  "哪个地址属于同一台电脑的哪一个网络"的可判定依据 —— 留着只是顺序靠后，
  不是每轮必试的第一条。

## 同日补：失败冷却 + 按电脑排序（`dialOrder`）

**问题（真机可量化）**：手边这台机器的端点表是 4 条，其中两条是 PC 的 VMware
host-only 网卡（`192.168.40.1` / `192.168.235.1`），手机永远拨不通，而连接器每次照报。
只要"记住的那条"拨不通（换网 / 冷启动），就要依次付 `3s × 2`，最坏 9s 才落到中转。
远程用（公网）时更糟：所有直连都不可能通。而 `EndpointAttempt` 原先**没有时间戳**，
连"这个失败是刚才还是昨天"都答不出来，任何冷却都写不出来。

**改动**：

- `EndpointAttempt` 加 `atMs`（可空；空 = 不知道，**不参与冷却**）；
- `dialOrder` 增加两个桶：**别的电脑报的**排在当前电脑之后、**冷却中的**排最后
  （`isCooling`：最近一次失败距今 < `kEndpointCooldown` = 60s）；
- **连"记住的那条"也不例外** —— 它刚失败就一样排队尾，否则每轮都为它白等一个超时；
- 窗口一过自动回原位，成功即清 ⇒ 仍然是"不永久降权"，只是不再"每轮重试同一个死地址"；
- 手填端点也在添加时盖上 hostId，于是"别的电脑的手填地址"同样排后（**不删**，用户意图仍在）；
- 判重只看结论（`ok` + `reason`）不看 `atMs`，否则每次拨号都会触发一次界面重建。

**取舍**：60s 是"够几轮退避重试、又短到网络回来一分钟内能用上"；若将来连接层的退避上限
变化，这个值要跟着复核（验收判据：换网后一分钟内直连能重新被选中）。
