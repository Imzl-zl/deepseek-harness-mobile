# Agent Note: 宿主版本线用「双轨发布」，不用「一个包适配多版本」

Status: implemented

## Problem

DSH 发 `0.2.2` 线之后，用户分成两拨：升级的、不升级的。插件只有一条版本线时，任何一次抬线都会
让另一拨人拿不到更新；而把 `engines.dsh` 放宽到覆盖两条线，又等于 claim 一个没测过的版本
（`2026-10-31-plugin-engines-dsh.md` 已否过一次）。

同一次抬线里还发现两件具体事实：

1. `0.2.2` 的 `subagentCatalog` v3 是**持久化单向门**（`docs/persistence-changes/2026-11-02-subagent-catalog-names.zh.md`）：
   新宿主写下的目录，旧宿主**拒绝打开**。跨版本回退本身不安全，所以"多留几条线"买不到稳定。
2. 已发布的 `0.1.20` 上界是旧写法 `<0.2.2`，`includePrerelease` 下放行整条 0.2.2 预发布线 ——
   升级用户会拿到一个"装上并跑起来"的旧插件，比装不上更难查。

## Decision

**一个包名、多条版本线并行发布，靠宿主逐版本判定挑。**

- `0.1.21` → `engines.dsh: ">=0.2.2-rc.1 <0.2.3-0"`，服务 0.2.2 线，功能跟进。
- `0.1.20` 不动（npm 版本不可变），继续服务 0.2.1 线，冻结：只修致命问题。
- 支持窗口 **N-1**：只保留当前线 + 上一条线；宿主进下一个 minor 时淘汰最老那条。

机制分三层，各管一段，互不替代：

| 层 | 机制 | 谁负责 | 依据 |
|---|---|---|---|
| 声明 | `engines.dsh` 一条范围 | 包清单 | `packages/boot/app-boot/src/plugin-compatibility.ts:57-61` |
| 分发 | npm 版本不可变 + 逐版本兼容判定 | 发布流程 | `plugin-manager/README.md:56`（`listVersions` 标 `incompatible`）、`plugin-market/README.md:96`（`defaultVersion` 取最高兼容版） |
| 运行 | 能力协商 | 连接器 | `connector/src/dsh/caps.ts:115`（按宿主服务逐面开关）、`connector/src/dsh/host-version.ts:78`（报**运行时**版本，不是构建期常量） |

抬线步骤写成可执行清单：`docs/cookbook/release.md` §3。

## Alternatives considered

1. **一个宽范围吃两条线**（如 `>=0.2.1-rc.5 <0.3.0`）
   - 最强的理由：一次声明管很久，用户升不升都能装上。
   - 为何被否：判定在**加载前**，插件内的运行时分支救不了"装不上"，只能救"装上了崩"；
     而且我们的类型只对着**一个** `@deepseek-ai/dsh-*` 精确版本编译，多版本分支等于把 `tsc`
     的保护拆掉。这次 `tsc` 零错、847 条测试全绿，正是因为只有一个版本。
2. **在包里做运行时特性探测 / 适配层**
   - 最强的理由：主流生态里确实常见（没有硬门槛时只能这么活）。
   - 为何被否：DSH 有硬门槛（`engines.dsh`），探测是第二套判据 —— 两套判据就会打架，
     而且"装上了才发现不兼容"正是 DSH 已经替你避免的那种失败。
3. **跟着宿主每发一个 rc 就发一个插件补丁**
   - 为何被否：2026-10-31 已否过，理由不变 —— 把"宿主发版"变成"我们必须发版"，
     而用户装到的仍是旧版、DSH 只是静默跳过。

## Consequences

- 收益：升级用户与不升级用户**各有能装的版本**，不需要谁迁就谁；抬线动作收敛到每宿主 minor 一次。
- 收益：`0.1.21` 的上界改成 `<0.2.3-0`，0.2.2 用户不再被旧的 `0.1.20` 静默放行。
- 代价：**旧线没有新功能**。0.2.1 用户要么升级宿主，要么停在上一条线。
- 代价：同时维护两条线，窗口上限 2；要开第三条线说明该砍而不是该加。
- 代价：抬线必须真机 e2e 一轮。这次单测 847 条全绿也**没有**覆盖到真实宿主的形状
  （替身绕开了 `subagentCatalog` 的 v3 载荷）。
- 文档：`docs/cookbook/release.md` §3 提供版本矩阵与 playbook；`tools.md` 的兼容性坑点改成指向它，
  避免两处说法漂。
