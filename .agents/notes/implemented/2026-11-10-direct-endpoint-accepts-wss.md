# Agent Note: 直连端点收 `wss://` —— TLS 由外部终结是合法形态

Status: implemented

## Problem

通道里三处判据各自推出了"直连只能明文 `ws://`"，而它们都没有协议依据：

- 手机「添加端点」把直连硬拦在 `ws://`（"直连是明文 ws://"）；
- 电脑侧 `advertise` 的 `extra` 只收 `ws://` + 非公网（"公网请走中转"）；
- 文档跟着写成"直连一般填 `ws://`，写成 `wss://` 反而拨不通"。

而监听面的文件头写的是另一句话：**"不终结 TLS，TLS 由外部终结（`tailscale serve`
或反向代理）"**，且"手机侧始终拨 `wss://`"。于是有域名、有反代、有 frp 的人 ——
正好是最该走 TLS 的那批 —— 被挡在门外，只能退回公网明文；而 `extra` 原本的用途
（把不在网卡枚举里的地址报给手机）也正好被这条限制堵死。

真因是把**部署细节**（TLS 在哪终结）当成了**产品边界**（直连只能局域网）。
`protocol/` 里没有任何一条说直连不能是 `wss://`：直连与中转的区别只是"要不要换票"。

## Decision

直连地址分两档：`ws://` 限非公网；`wss://` 不限主机（公网也收）。

准入门槛（可机械判定）：

1. **手机手填直连**：`wss://` 一律可添加，`allowPlaintextPublic` 为 `false`；
   `ws://` 公网必须先勾"公网明文"确认，勾了才落表。
2. **电脑侧 `extra`**：`wss://` 任意主机通过；`ws://` 必须过 `isNonPublicHost`；
   其它协议、带凭据 / query / fragment 一律拒。
3. **监听面不变**：仍然只监听明文 WS、不持有证书、不做 TLS 分支。
4. **两侧判据同源**：公网 / 私网的判定复用 `isNonPublicHost`
   （电脑侧）与 `isPrivateOrLoopback`（手机侧），新增用例把同一批地址钉在两边。

## Alternatives considered

1. 只改文档、不改代码，主线教用户填公网明文 `ws://`
   - 最强的理由：零代码改动，`ws://` 公网 + 确认档本来就能用，当天就能交付。
   - 为何被否：有域名的人恰恰是最该走 TLS 的；主线变成"教你关掉 TLS"，
     而明文只保护元数据不保护内容这件事，用户只会记成"这软件要明文"。
2. 把公网 `wss` 入口当成一条 relay 端点复用
   - 最强的理由：relay 端点已经支持 `wss://` 与自定义地址，手机侧一行不用改。
   - 为何被否：relay 端点要先换票（`/ws-ticket` → `/ws/device?ticket=`），
     而连接器的直连面不提供票源。等于凭空造出第二条中转协议，两端都要重写。
3. 让监听面自己终结 TLS（插件内置证书）
   - 最强的理由：用户只填域名和端口，配置最少，不用另装 Caddy。
   - 为何被否：插件要持有私钥、处理续期与 ACME 端口，攻击面从"一个 WS 端口"
     扩到"一张证书的生命周期"；而且没有域名时这条仍无解。
4. frp 用 `https`（vhost）类型，让 frps 透传 TLS、后端电脑终结
   - 最强的理由：VPS 上不用装 Caddy，frps 一个进程全包。
   - 为何被否：TLS 仍然要在电脑上终结，等于把方案 3 的证书负担搬到用户机器；
     家宽拿证书还要 80/443 或 DNS-01，比在 VPS 上自动签难一档。
5. 保持现状，公网一律走中转
   - 最强的理由：暴露面最小，用户不会把 8790 明文直接挂出去。
   - 为何被否：这条边界从来不是协议的要求，只是三处代码的互相引用；
     它让"只想穿透、不想跑中转"这一整类部署无解，而 `relay/` 并不是所有人都愿意跑。

## Consequences

- 收益：反向代理、`tailscale serve`，以及任何在监听面**前面**终结 TLS 的隧道都能直接填；
  电脑侧可以把穿透域名作为 `extra` 自动上报，换地址不用再让每台手机手填。
  删掉的是"公网只能走中转"这条自设边界，不是协议约束。
- 代价：多了一条"公网入口"的配置面 —— 用户可能把 8790 明文直接挂公网，
  那时只有元数据保护而不是 TLS；直连的建连预算仍是 3 秒，公网握手偏紧，
  超时只能回落中转（有意不改：改它需要真机数据，见 `tools.md` 的查证顺序）。
  两侧判据仍分居两个仓，靠同一批地址的用例钉住，谁先改谁那边先红。
