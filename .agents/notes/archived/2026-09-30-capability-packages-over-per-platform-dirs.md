# Agent Note: 多端按能力切包,不按端切目录

Status: archived

Superseded by: `.agents/notes/proposed/2026-09-30-experience-first-three-layer-split.md`
取代范围：本篇用「工程量 / 收益比」论证多端结构，新篇改用**体验判据**并把覆盖范围从两层扩到三层（新增「每端专属表达」层）。本篇「核心零分支 + 按能力切包」的结论仍然有效，新篇原样保留。

## Problem

"支持三端"最常见的两种写法都会烂,而项目里没有任何东西拦得住它们:

- **单文件里 `if (Platform.isAndroid)`**:平台判断会顺着"顺手加一个分支"扩散进业务代码。后果不是难看,而是纯 Dart 单测立刻不可写——每个分支都要跑在真机上才知道走没走到;"某端没走到这条分支"这类 bug 只有真机才能发现。
- **一个端一个目录**:三份 UI 必然各自漂移,用户看到的是三个产品;同一个修复要改三处,漏一处就是"某端没修";而"支持第四个平台"变成复制整个 app。

本项目已经查清平台差异其实只有两件事:**私钥存哪个密钥库、通知走哪条通道**。为这两件事付出"三份 UI"的代价,收益是负的。

## Decision

平台差异只允许存在于**按能力切分**的包里:`app/packages/<能力>/` 是纯 Dart 接口 + 兜底实现,`app/packages/<能力>_<端>/` 是各端实现,`lib/platform/` 是唯一装配点。协议、恢复引擎、本地库、领域模型、UI 一套代码零平台分支。

准入门槛(可机械判定):

1. `lib/core` / `lib/data` / `lib/model` 出现 `dart:io`、`package:flutter/services.dart`、`widgets.dart`、`material.dart`、`Platform.`、`defaultTargetPlatform`、`MethodChannel`、`EventChannel` 任一即失败(允许 `package:flutter/foundation.dart`)。
2. `lib/ui` import 带端后缀的实现包(`*_ios` / `*_android` / `*_ohos`)或 `dart:io` 即失败。
3. 新增一个平台时,`lib/core` / `lib/data` / `lib/model` / `lib/ui` 的 diff 必须为空。
4. 每个能力包必须有纯 Dart 兜底实现;兜底实现在 release 构建里被选中即启动 fail-fast,不得静默降级。
5. 能用上游 fork 或纯 Dart 包解决的(本地库、加解密),不得自己再包一层抽象。

## Alternatives considered

1. 一个端一个目录(每端一套 `lib/`)
   - 最强的理由:边界最直白,任何平台的特殊处理都能就近写,不必先设计抽象;新人接手某一端只看一个目录就行。
   - 为何被否:三份 UI 必然漂移,而平台差异实际只有密钥存储与通知通道两件事;修复要改三处、漏一处就是"某端没修",新增平台等于复制整个 app。为一个只有两处差异的问题复制整个 UI,代价与收益完全不成比例。
2. 单文件里就地 `if (Platform.isIOS)` 分支
   - 最强的理由:最省事,不用建包、不用装配点,一处写完就完事。
   - 为何被否:平台判断会扩散进业务代码,纯 Dart 单测立刻不可写;而且"某端没走到这条分支"只有真机能发现——与"验证脚本是规格"的既有做法直接冲突。
3. 连本地库与加解密也自己包一层统一抽象
   - 最强的理由:接口完全统一,任何端都能换实现,理论上最可控,将来换实现只改装配点。
   - 为何被否:`sqflite` 与 `cryptography` 本来就有三端同一 API 的方案,再包一层只在"上游换实现"时才回本,而每个能力都要自己维护接口与兜底。**抽象只加在真正有平台差异的地方**——这是我们否掉它、而不是否掉抽象本身的理由。

## Consequences

- 收益:平台差异被压缩到三个能力包,核心逻辑与 UI 一套代码、纯 Dart 可测;新增平台不触碰 `core` / `data` / `model` / `ui`;修复与优化三端同时生效;边界由 `verify-platform-boundary.mjs` 拦,不靠自觉。
- 代价:多一层接口包与装配点——即使简单能力也要写"接口 + 兜底 + 装配";能力包边界靠脚本守,而抽象层自身将来可能演进(例如推送能力从"注册 + 接收"扩到"分类报备与模板"),届时 `push` 的接口要有一次整体升级。
