# 回答审批无反应:跨模块裸调导致回调中断

- 日期:2026-09-30
- 影响面:审批卡的「拒绝 / 允许一次」、计划卡的「要求修改 / 同意执行」全部失效
- 严重度:高(表面像"权限直接生效了",实际是回答没送达)

## 现象

点「拒绝」或「允许一次」后:队列不推进、面板不消失、不产生回执节点。因为下一次审批不会顶上来,看起来像"系统已经接受并继续了",实际回答根本没被处理。

## 排查时间线

1. 先用**授权矩阵验证脚本**(`mock/proto/tools/verify-authz.mjs`,18 项)把行为固化成断言,一次跑出 3 项失败:
   - 拒绝后队列清空 → 失败(`pending=1`)
   - 拒绝产生回执节点 → 失败
   - "允许一次"后下一次仍重新要授权 → 失败(`pending=3`)
2. 失败模式很集中:队列不推进 + 无回执 + 按钮置灰不动 → 指向**回调在中途抛异常**。
3. 静态比对两个模块的符号作用域,发现 `interactions.js` 在 `settleApproval` / `settlePlan` 里**裸调 `haptic()`**,而 `haptic` 只定义在 `app.js` 的 IIFE 内。
4. 结论:该调用抛 `ReferenceError`,中断了整个回答流程。

## 根因

`haptic` 是 app.js 的**私有符号**,interactions.js 没有同作用域访问权。由于两文件都在页面里加载,写起来"看起来"能调到,实际是运行时错误,而且发生在**异步回调和 `setTimeout` 里**,不冒泡到页面级错误处理,静默失败。

## 止血

在 `interactions.js` 内自带一份 `haptic`(不依赖 app.js),并把跨模块调用一律改为**通过注入的 `api` 对象**。

## 沉淀

- 规则:`interactions.js` 通过注入的 `api` 调用 `app.js`,**不得裸调对方私有符号**(已写入根 `AGENTS.md` §3 与 §6)。
- 规则:权限相关路径以 `verify-authz.mjs` 的 18 项为准,须 0 失败(已写入根 `AGENTS.md` 常驻军规)。
- 方法:异步回调里的静默失败,靠"把行为固化成断言"才能暴露;人工点一遍很可能被误判成"已生效"。

## 相关

- 同一时期另有一个返回栈竞态:切换 sheet 时"先 `closeSheet()` 再 `openSheet()`",异步 popstate 会把**刚打开的风险确认门**按层数自愈逻辑弹掉,导致风险门打不开、权限静默生效。修法是 `openSheet` 内部复用同一 sheet 层。
- 两个问题都属于"授权路径静默失效",因此一并纳入授权矩阵验证的覆盖范围。
